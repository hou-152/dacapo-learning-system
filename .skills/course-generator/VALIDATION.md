## 一、核心流程完整性检查

### ✅ 通过项

1. **输入方式明确**
   - 方式 1：基于文章生成（`/course-generator /path/to/article.md`）
   - 方式 2：基于概念生成（`/course-generator --concept "概念名"`）
   - 可选参数：`--name "自定义课程名"`

2. **四阶段流程清晰**
   - 阶段 1：提取与规划（5 分钟）
   - 阶段 2：章节拆分（10 分钟）
   - 阶段 3：生成 .concepts.json（3 分钟）
   - 阶段 4：写入与验证（2 分钟）

3. **输出结构规范**
   - 主页.md（课程导航）
   - 00-学习计划.md（学习路径）
   - 章节文件（01.md, 02.md, ...）
   - .concepts.json（概念关联元数据）
   - assets/（图片资源目录）

4. **依赖关系明确**
   - 调用 `/concept-learning` 进行概念提取（基于文章时）
   - 查询 `concepts/` 目录或 `dacapo-wiki`（基于概念时）
   - 参考 `references/concepts-json-schema.md`（数据结构）

5. **质量自检清单完备**
   - 完整性、一致性、可读性、关联性、递进性、无冗余六项检查

### ❌ 未通过检查项

#### 1. **缺失 .concepts.json**
- **预期**：根目录应有 `.concepts.json` 文件，标注每章的 mainConcepts 和 relatedConcepts
- **实际**：文件不存在
- **影响**：
  - 无法自动生成主页的"相关概念"列表
  - 无法进行知识图谱可视化
  - 无法基于概念推荐后续学习路径

#### 2. **主页缺失核心问题**
- **预期**：主页应列出 3-5 个核心问题
- **实际**：简介中提到"一个大问题"（一个人的一生，有多少是自己选的），但未拆解成 3-5 个具体问题
- **建议修复**：
  ```markdown
  ## 核心问题
  
  1. 中国人的"私"是怎么回事？为什么同一个人可以为小家牺牲大家？
  2. 关系、人情、面子如何在差序格局中运转？
  3. 圈内规则和圈外规则如何判别？
  4. 社会分层如何测量？流动性在哪里？
  5. 尊严和承认如何驱动身份政治？
  ```

#### 3. **章节数量未严格遵循字数规则**
- **SKILL.md 规定**：
  - 短文（3,000-8,000 字）：3-5 章
  - 中篇（8,000-15,000 字）：6-8 章
  - 长文（> 15,000 字）：8-12 章
- **实际案例**：02.md 约 2,800 字（短文），但整个课程有 9 章
- **分析**：该课程是"七本书共读"，每章对应不同书籍的不同主题，不是单篇文章拆分，因此不适用该规则
- **结论**：规则本身适用于单篇文章生成课程，多书整合型课程需要另行处理

#### 1. 生成 .concepts.json
```json
{
  "01.md": {
    "mainConcepts": ["社会学想象力", "个人困扰与公共议题"],
    "relatedConcepts": {

    "relatedConcepts": {

      "社会分层": { "relevance": 0.6, "context": "波纹半径与社会地位的关系" },
```

- 从每章的小标题和首段提取 mainConcepts

- relevance 按"同层 0.8 / 相邻层 0.7 / 跨层 0.5-0.6"估算

### 优先级 2（改进建议）

#### 1. 阶段 3 的生成规则需要更具体的实施步骤
**当前问题**：SKILL.md 说"从架构图识别概念层级关系"，但未说明：
- 如何从 concept-learning 的产出中提取架构图？
- 架构图是 Mermaid 格式还是文本描述？
- 如何自动解析层级关系？

**建议补充**：
```markdown
### 阶段 3：生成 .concepts.json（实施步骤）

1. 读取 concept-learning 的产出文件（如 `concept-network.json` 或 `架构图.md`）
2. 解析 Mermaid 图或 JSON 结构，提取概念间的关系
3. 为每个章节文件：
   a. 从章节标题或首段提取 mainConcepts（1-2 个）
   b. 查询与 mainConcepts 相关的概念（从架构图或概念库）
   c. 计算 relevance：
      - 同层概念（并列关系）：0.8
      - 相邻层概念（依赖或派生）：0.7
      - 跨层概念（间接关联）：0.5-0.6
   d. 生成 context：
      - 从架构图的连线标签提取（如"理论基础""实践应用"）
      - 或用模板生成（如"都出自费孝通""下一章引入"）
4. 写入 `.concepts.json`，格式遵循 `references/concepts-json-schema.md`
```

#### 2. 章节拆分原则需要补充边界情况
**当前问题**：
- 多书整合型课程（如本案例）如何处理？
- 如果原文本身已有章节结构，是否保留？

**建议补充**：
```markdown
### 章节拆分原则（补充）

**边界情况 1：原文已有章节结构**
- 如果原文是书籍摘录且已有章节，保留原结构，不强制重拆
- 如果原章节过长（> 3,000 字），按"一章一核心概念"进一步拆分

**边界情况 2：多篇文章整合**
- 每篇文章独立生成章节，不合并
- 最终课程的章节数 = 各文章章节数之和
- 主页需说明多篇来源（如"七本书共读"）

**边界情况 3：概念密度极高的理论文章**
- 单章可聚焦 1 个核心概念即可（不强制 1-2 个）
- 字数可压缩到 1,000-1,500 字（保证论证链完整）
```
