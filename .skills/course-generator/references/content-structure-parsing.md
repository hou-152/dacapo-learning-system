# 内容结构解析指南

## 核心原则

**不是按字数平均切分**

文章的章节划分必须基于**语义完整性**和**逻辑连贯性**，而非机械地按字数或段落数均分。一个有效的章节是一个**自洽的思想单元**。

---

## 典型文章结构识别

### 1. 问题陈述（Problem Statement）

**特征**：
- 通常在文章开头
- 提出疑问、矛盾或待解决的问题
- 设定讨论的边界和语境

**识别标志**：
- "为什么..."、"如何..."、"...的困境"
- 现状描述 + 问题暴露
- 引入背景、定义关键概念

**章节边界**：当问题完整陈述完毕，开始进入解释或论证时结束

---

### 2. 论证（Argumentation）

**特征**：
- 提出观点、假设或解决方案
- 展开推理链条
- 建立因果关系或逻辑框架

**识别标志**：
- "因为..."、"所以..."、"这意味着..."
- 理论引用、模型构建
- 多个论点的递进或并列

**章节边界**：
- 单一论证完成时（一个完整的推理链）
- 转向不同维度的论证时
- 从抽象论证转向具体案例时

---

### 3. 案例（Case Study / Example）

**特征**：
- 具体的故事、数据或实例
- 用于支撑或说明前述论证
- 提供可感知的现实锚点

**识别标志**：
- 人名、公司名、具体事件
- 数据、图表、实验结果
- "比如..."、"以...为例"

**章节边界**：
- 案例分析完成，回归理论总结时
- 切换到下一个独立案例时

---

### 4. 小结（Summary / Reflection）

**特征**：
- 对前文的提炼或升华
- 引出下一阶段讨论
- 提供行动建议或思考方向

**识别标志**：
- "总之..."、"综上..."、"这说明..."
- 重申核心观点
- 提出新问题或延伸思考

**章节边界**：自然段落结束，或开始新的问题陈述

---

## 章节划分策略

### 原则 1：每章聚焦 1-2 个核心主题

**正确示例**：
- 章节 1：问题陈述 + 问题的三个维度分析
- 章节 2：解决方案框架 + 第一个关键要素详解
- 章节 3：第二个关键要素 + 支撑案例

**错误示例**：
- 章节 1：问题陈述 + 部分论证 + 一个案例的前半段（主题分散）
- 章节 2：案例后半段 + 小结 + 新问题开头（割裂语义）

---

### 原则 2：章节之间有明确的前置关系

**依赖类型**：

1. **顺序依赖**：必须先理解 A 才能理解 B
   - 示例：先定义"注意力经济"（章节 1），再讨论"注意力的货币化"（章节 2）

2. **累积依赖**：B 在 A 的基础上扩展
   - 示例：先讲"基础原理"（章节 1），再讲"高级应用"（章节 2）

3. **并列关系**：A 和 B 是同一层级的不同维度
   - 示例：章节 2、3、4 分别讨论"技术"、"商业"、"伦理"三个独立维度

**检查方法**：
- 如果打乱章节顺序，读者是否会困惑？
- 前一章的结论是否是后一章的前提？

---

## 实战操作流程

### Step 1：通读全文，标注结构标志

- 用不同颜色标注：问题、论证、案例、小结
- 识别文章的**主线逻辑**（线性、树状、螺旋上升？）

### Step 2：找到自然断点

**自然断点的信号**：
- 话题转换（从"为什么"到"怎么做"）
- 抽象层级变化（从理论到案例，或反之）
- 明确的过渡句（"接下来讨论..."）

**非自然断点的陷阱**：
- 段落结束（段落可能只是呼吸节奏，不代表思想完结）
- 字数达标（机械切分破坏语义）

### Step 3：验证章节完整性

每个章节必须能回答：
1. **这一章讲什么？**（一句话概括核心主题）
2. **为什么放在这里？**（与前后章节的关系）
3. **读完能带走什么？**（独立的知识单元或思考启发）

### Step 4：调整边界

如果某章包含多个不相关主题 → **拆分**  
如果某章过短且无法独立成章 → **合并到相邻章节**

## 错误示例与修正

### 错误 1：机械切分

**错误做法**：
```
章节 1（前 500 字）：问题陈述 + 论证开头
章节 2（中 500 字）：论证中段 + 案例开头
章节 3（后 500 字）：案例结尾 + 小结
```

**问题**：论证和案例被强行割裂，读者需要跨章节才能理解完整逻辑。

**正确做法**：
```
章节 1：完整的问题陈述（200 字）
章节 2：完整的论证 + 支撑案例（800 字）
章节 3：小结 + 延伸思考（300 字）
```

---

### 错误 2：主题分散

**错误做法**：
```
章节 2：
- 讨论 AI 的计算成本问题
- 穿插一个关于数据隐私的案例
- 回到成本优化策略
```

**问题**：一章内跳跃多个不相关主题，读者难以形成清晰记忆。

**正确做法**：
```
章节 2：AI 的计算成本问题 + 优化策略
章节 3：AI 的数据隐私挑战 + 案例分析
```

---

### 错误 3：忽略前置关系

**错误做法**：
```
章节 1：高级应用案例
章节 2：基础原理解释
```

**问题**：读者在不理解原理的情况下先看案例，产生认知负担。

**正确做法**：
```
章节 1：基础原理解释
章节 2：高级应用案例（基于章节 1 的理解）
```

## 输出格式要求

每个章节应明确标注：

```yaml
chapter_id: 2
title: "论证：注意力的稀缺性原理"
content_types:
  - argumentation
  - definition
core_topics:
  - 注意力作为有限资源
  - 稀缺性的经济学含义
depends_on:
  - chapter_1  # 必须先理解"注意力经济"的定义
leads_to:
  - chapter_3  # 为"注意力的货币化"提供理论基础
```

---

## 总结

**好的内容结构解析 = 尊重作者的思维逻辑 + 优化读者的认知路径**

- 以**语义完整性**为第一优先级
- 识别**结构标志**而非依赖字数
- 确保**前置关系**清晰
- 每章是一个**独立且有用的知识单元**
