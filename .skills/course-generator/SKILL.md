# 课程生成器

## 一、任务定位

从深度文章或概念名生成结构化课程。输入可以是文章路径（提取核心概念）或概念名（从概念库构建）；输出是完整课程目录，包含主页、章节文件、学习计划和概念关联元数据。

## 二、输入格式

### 方式 1：基于文章生成
```bash
/course-generator /path/to/article.md
```

文章要求：
- 清洗稿或完整转写稿（≥ 3,000 字）
- 有明确的知识结构或论述链条
- 非纯新闻报道或琐碎记录

### 方式 2：基于概念生成
```bash
/course-generator --concept "概念名"
```

概念要求：
- 概念已存在于概念库（`/Users/housibo/Documents/dacapo-学习仓库/concepts/`）
- 有足够的关联概念可展开（≥ 5 个相关概念）

## 三、输出结构

生成目录位于：`/Users/housibo/Documents/dacapo-学习仓库/courses/<课程名>/`

```
<课程名>/
├── 主页.md                  # 课程入口与导航
├── 00-学习计划.md            # 预期收获、前置知识、学习路径
├── 01.md                    # 第 1 章
├── 02.md                    # 第 2 章
├── ...
├── .concepts.json           # 章节概念关联元数据
└── assets/                  # 图片资源（如需要）
```

### 文件说明

**主页.md**
- 课程定位（一句话）
- 核心问题（3-5 个）
- 章节列表（带链接）
- 相关概念（从 `.concepts.json` 生成）

**00-学习计划.md**
- 这一课要解决什么（4-6 个具体问题）
- 前置知识（如有）
- 学习路径建议（顺序 / 可选 / 深挖）

**章节文件（01.md, 02.md, ...）**
- 标题：`## 这一篇要解决的问题`
- 正文：核心内容（保留原文结构与论证链条）
- 小结：3-5 条要点
- 下一篇预告（可选）
- 学习反馈区（引导思考问题）

**.concepts.json**
- 每个章节的主概念（1-2 个）
- 相关概念（relevance > 0.5）
- 概念关系说明
- 详细格式见 `references/concepts-json-schema.md`

## 四、核心流程

### 阶段 1：提取与规划（5 分钟）

**基于文章时**：
1. 调用 `/concept-learning` 提取核心概念（保持原有 6 字段结构）
2. 从架构图识别概念层级关系
3. 按「基础层 → 机制层 → 应用层」规划章节顺序

**基于概念时**：
1. 从概念库读取目标概念
2. 查询关联概念（通过 `dacapo-wiki` 或直接读 `concepts/` 目录）
3. 按概念依赖关系规划章节

### 阶段 2：章节拆分（10 分钟）

**拆分原则**：
- 每章聚焦 1-2 个核心概念
- 单章字数 1,500-3,000 字
- 保留完整论证链条（不能只摘定义）
- 章节间有明确递进关系

**章节数量**：
- 短文（3,000-8,000 字）：3-5 章
- 中篇（8,000-15,000 字）：6-8 章
- 长文（> 15,000 字）：8-12 章

**检查清单**：
- [ ] 每章能独立回答一个具体问题
- [ ] 删掉某一章会让学习路径断裂
- [ ] 没有「杂项」「其他」「补充」这类章节

### 阶段 3：生成 .concepts.json（3 分钟）

为每个章节文件标注概念关联。

**输出格式**（必须按章节分组）：
```json
{
  "01.md": {
    "mainConcepts": ["对齐", "风格分布压窄"],
    "relatedConcepts": {
      "perplexity": { "relevance": 0.7, "context": "下一章引入的检测指标" },
      "RLHF": { "relevance": 0.6, "context": "对齐的具体技术" }
    }
  },
  "02.md": {
    "mainConcepts": ["RLHF"],
    "relatedConcepts": {
      "对齐": { "relevance": 0.7, "context": "上一章讲解的理论基础" }
    }
  }
}
```

**关键要求**：
- ✅ 顶层 key 必须是章节文件名（"01.md", "02.md"）
- ✅ relatedConcepts 必须是对象（key 是概念名）
- ✅ 每个相关概念必须有 relevance 和 context
- ❌ 不要生成单层结构（没有章节分组）
- ❌ 不要把 relatedConcepts 写成数组

**生成步骤**（详细实现见 `references/generate-concepts-json.md`）：

1. **提取 mainConcepts**：
   - 从章节标题（## 这一篇要解决的问题）中匹配概念
   - 或从首段统计概念出现频率，取前 1-2 个

2. **查询 relatedConcepts**：
   - 基于文章时：从 concept-learning 的架构图解析关系
   - 基于概念时：从概念库读取 relatedConcepts 字段
   - 查询 `.learning-progress/concept-relevance.json`（如存在）

3. **计算 relevance**：
   - 优先使用 concept-relevance.json 的真实相关度
   - 否则按层级估算：同层 0.8 / 相邻层 0.7 / 跨层 0.5-0.6

4. **生成 context**：
   - 判断概念是否在相邻章节（"下一章引入""上一章讲解"）
   - 或根据关系类型（"具体技术""理论基础""实践应用"）

**验证**：
- [ ] 每个章节都有对应条目
- [ ] mainConcepts 至少 1 个
- [ ] relatedConcepts 的 name 都能在概念库找到
- [ ] relevance 在 0.5-1.0 之间
- [ ] 格式符合 dbs-learning 的期望（按章节分组）

### 阶段 4：写入与验证（2 分钟）

**写入顺序**：
1. 创建目录：`courses/<课程名>/`
2. 生成主页与学习计划
3. 生成各章节文件
4. 生成 `.concepts.json`
5. 更新 `courses/INDEX.md`（追加本课程）

**验证清单**：
- [ ] 所有章节文件已写入
- [ ] `.concepts.json` 的章节文件名与实际文件一致
- [ ] 主页的章节链接可点击
- [ ] 学习计划里的问题与各章标题呼应

## 五、调用 concept-learning 的规范

**何时调用**：
- 输入是文章路径时，必须调用
- 输入是概念名时，跳过（直接从概念库读取）

**调用方式**：
```bash
/concept-learning /path/to/article.md
```

**使用产出**：
- 核心概念 → 章节主题
- 支撑概念 → relatedConcepts 候选
- 架构图 → 章节顺序与层级关系
- 费曼解析 → 章节正文的通俗化表达

**不做的事**：
- 不复制 concept-learning 的完整产出到课程文件
- 不把六字段结构直接转成章节（概念 ≠ 章节）
- 不为了凑章节数拆散一个完整概念

## 六、课程命名规范

**格式**：`<核心主题>`

**示例**：
- ✅ `AI 检测原理与课堂判读`
- ✅ `Agentic Engineering 工作流`
- ✅ `如实所现`
- ❌ `文章学习课程` （太泛）
- ❌ `概念 A 与概念 B 与概念 C` （冗长）

**命名来源**：
1. 优先用文章标题（如已有明确主题）
2. 或用最核心的 1-2 个概念组合
3. 避免日期、版本号、临时性词汇

## 七、任务边界

**做的事**：
- 生成课程框架与章节文件
- 标注概念关联元数据
- 提供学习路径建议

**不做的事**：
- 不生成练习题或测验（学习反馈区只引导思考）
- 不对原文内容做价值判断或批评
- 不补充文章未提及的外部知识
- 不修改已生成课程的章节内容（除非明确要求迭代）

## 八、质量自检

交付前逐条检查：

1. **完整性**：主页、学习计划、所有章节、.concepts.json 都已生成
2. **一致性**：主页章节列表 = 实际文件 = .concepts.json 的键名
3. **可读性**：每章首段回答「本章要解决什么」
4. **关联性**：.concepts.json 的 relatedConcepts 都能在概念库或文章中找到
5. **递进性**：删除任一章会让学习路径断裂
6. **无冗余**：没有内容重复 > 50% 的章节
