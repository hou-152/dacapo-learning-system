## 解决的问题

DaCapo 交互式学习系统有 3 个 skills（course-generator, dbs-learning, concept-bridge），用户面临以下困难：

1. **不知道该用哪个**：每个 skill 处理不同阶段，用户需要理解差异
2. **不知道怎么调用**：每个 skill 有不同参数（文章路径、课程目录、章节列表等）
3. **场景判断困难**：同样是"想学某某"，可能需要不同 skill

learning-navigator 通过识别 5 种学习场景，自动推荐合适的 skill 和参数，让用户从粗糙需求直达可执行调用。

## 核心能力

1. **场景识别**
   - 从对话恢复用户意图（学习目标、材料、阶段）
   - 判断 5 种场景：生成课程 / 交互学习 / 学完推荐 / 概念查找 / 基于掌握度
   - 识别非学习场景并明确拒绝

2. **候选筛选**
   - 固定清单：3 个 skills（course-generator, dbs-learning, concept-bridge）
   - 根据输入材料类型（文章 / 课程 / 概念 / 无）匹配 skill
   - 根据学习阶段（准备 / 进行中 / 完成）匹配 skill

3. **参数引导**
   - 识别缺失的必要信息（文章路径、课程目录、章节列表）
   - 只问 1 个问题，提供示例格式
   - 说明为什么需要这个信息

4. **提示词生成**
   - 生成可直接执行的 skill 调用
   - 包含推荐理由（一句话说明）
   - 保留用户的原始材料和目标
   - 补充必要的参数说明

5. **边界清晰**
   - 只负责推荐，不执行下游 skill
   - 不代替其他 skill 的业务逻辑
   - 明确说明验证范围和未验证风险

## 使用方式

### 快速开始

在学习仓库目录下调用：
```bash
/learning-navigator
```

然后描述你的学习需求（可以很粗糙）。

### 典型用法

**场景 1**：想学一篇文章
```
我想学《乡土中国》这篇文章
/learning-navigator
```

**场景 2**：开始学习课程
```
我想开始学 AI 检测原理
/learning-navigator
```

**场景 3**：学完后推荐
```
学完前 3 章了，下一步学什么？
/learning-navigator
```

**场景 4**：查找概念相关内容
```
我想学"对齐"相关的内容
/learning-navigator
```

**场景 5**：不知道学什么
```
根据我的掌握度推荐吧
/learning-navigator
```

## 仍未验证的风险

1. **多目标场景**：用户说"我想学 A 和 B"，导航器应该让用户选择优先级
2. **路径变体**：课程路径可能是相对路径、波浪号路径、绝对路径
3. **概念库依赖**：场景 4 和 5 依赖概念库，空库时应有友好提示
4. **前置条件**：场景 2 需要先有课程，场景 5 需要先有学习历史

**建议**：在实际使用中遇到这些情况时，根据用户反馈优化 SKILL.md 的判断逻辑。

## 制作流程总结

### 使用的工具

- **skill-adapter**：从 `/dbs` 适配而来

### 适配步骤

1. **阶段 1：澄清对标与目标**
   - 对标对象：`/dbs`（商业工具箱入口）
   - 目标领域：DaCapo 学习系统（3 个 skills，5 种场景）
   - 新名称：`learning-navigator`

2. **阶段 2：生成适配后的 Skill**
   - 保留：场景识别、候选筛选、提示词生成
   - 移除：版本检查、编号执行、隐藏款目录
   - 简化：固定候选清单（3 个 skills）
   - 适配：5 种学习场景 + 参数引导

3. **阶段 3：分级验证**
   - 等级 1：结构校验通过
   - 等级 2：行为冒烟通过（6/6）

4. **阶段 4：生成交付报告**
   - VERIFICATION.md：验证报告
   - DELIVERY-REPORT.md：本文件

### 核心适配差异

| 维度 | /dbs | learning-navigator |
| --- | --- | --- |
| 候选发现 | 动态扫描 Marketplace | 固定 3 个 skills |
