**诊断时间**: 2026-09-30

## 已有资产

### 1. 数据资产
- **概念库**: 112 个概念文件（64 个已建立关联）
  - 位置: `concepts/core/` + `concepts/courses/`
  - 格式: 定义 + 首次出现 + 相关概念
  - 关联关系: 189 条引用（CONCEPT-GRAPH.md）
  
- **课程库**: 46 个课程，282 个章节
  - 位置: `courses/[课程名]/`
  - 格式: 01.md, 02.md... + learner-log.md + assets/
  - 特点: **已经采用 dbs-learning 结构**（问题→知识地图→费曼任务→检查站→用户反馈）

- **用户原话**: 875KB JSONL (user-feedback/user-utterances.jsonl)
  - 包含: 观点、判断、案例、解决方案
  - 已分类: content_roles, evidence_type, course, lesson
  - **核心价值**: 记录了你的真实学习轨迹和洞察

### 2. 脚本工具
- `backend.py` (61KB): 学习工作台核心逻辑
- `extract_course_concepts.py`: 从课程提取概念
- `generate_concept_graph.py`: 生成概念关系图谱
- `rebuild_course_index.py`: 重建课程索引
- `build_evidence_atoms.py` (51KB): 构建证据原子

### 3. 核心洞察（从用户原话提取）

#### 洞察 1: 按需加载能力（工具箱比喻）
> 系统拥有很多能力，不等于每一轮都要把这些能力输出到上下文。
> 就像你有一个工具箱，里面有很多扳手，但你没必要全天都提着它。

**设计启示**: 概念不需要全部常驻上下文，按需加载相关概念和依赖

#### 洞察 2: 常驻信息源
> dbs-learning 要有很多高质量的信息源，能够提升学习速度和斜率。
> 必须常驻 RSS 信息源和 AI 内参。

**设计启示**: 学习系统需要持续的高质量信息输入，用于前沿问题的增强搜索

#### 洞察 3: 任务锚点 = 收敛
> 一直探索却不收敛其实也是目的，是逃避，因此得落地，得具体。

**设计启示**: 学习必须有明确的任务锚点，每个概念学完要有可验证的应用

## 当前问题

### 1. 上下文压缩导致的信息丢失
- **症状**: 之前用 300K 上下文窗口反复压缩，丢失了交流细节
- **根因**: 没有结构化存储学习进度、概念掌握度、反馈调整记录
- **影响**: 无法追溯学习轨迹，无法基于历史反馈自适应调整

### 2. 缺少即时反馈机制
- **现状**: 学完一个概念后，没有立即看到：
  - 这个概念与已学概念的关联
  - 掌握这个概念解锁了哪些新概念
  - 当前概念网络的生长状态
- **期望**: 学完立即看到关联网络，产生"成就感"和"复利感"

### 3. 缺少进度可视化
- **现状**: `.learning-progress/` 目录存在但为空
- **缺失内容**:
  - 概念掌握度曲线
  - 学习时间线
  - 概念网络生长动画
  - 课程完成度统计
- **期望**: 能看到学习曲线、知识网络生长，产生"上瘾"感

### 4. 自适应调整未自动化
- **现状**: 课程已有反馈区，但调整依赖手动判断
- **缺失能力**:
  - 自动分析反馈信号（没看懂/看懂了/想应用）
  - 自动调整下一课难度/角度/节奏
  - 自动推荐下一个最适合学的概念
- **期望**: 系统根据反馈自动调整，像 dbs-learning 一样

## 核心需求（用户明确要求）

### 1. 即时反馈
学完一个概念，立刻看到它与已学概念的关联网络

### 2. 进度可见
能看到学习曲线、概念掌握度、知识网络生长

### 3. 自适应调整
借鉴 dbs-learning 的反馈驱动机制，根据反馈调整下一课难度/角度/节奏

### 4. 节省上下文
后台任务用 subagents，学习交互保持单 agent
