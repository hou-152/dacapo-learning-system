## 这一课要解决什么

学完这门课，你手上应该多出四个可检查的动作：

1. 拿一次自己和 agent 的真实规划经历（选型、排期、写方案），指着具体那一步，说清它落在 Appleton 诊断的哪一层（计划当脚本／规划者与旅行者分离／文字墙超载）。
2. 在自己的系统里点名至少三件「边界物」，并对每一件回答：它现在主要为谁优化，证据是它上一次让你改主意是什么时候。
3. 对着一个真实决策点，写出一个「更厚的界面」最小改造动作，并说明它把哪部分工作从工作记忆搬到了世界里。
4. 用 Appleton 的两个自问检查一件你正在做的东西，给出一个能落地或明确否掉的答案。
