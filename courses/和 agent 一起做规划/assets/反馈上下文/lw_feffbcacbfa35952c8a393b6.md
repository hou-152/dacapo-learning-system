## 与课程的直接联系

1. 否掉 log 指标。原话逐字：「哎，你那个log的那个东西老早就没用了呀」「因为他自动化很多东西，他是没法去铺开的」。课程侧：04 篇的痕迹表把 `learner-log.md` 带 `DBS_USER_RESPONSE` 标记的 3 门课列成一行指标[[01-交互式学习/02-课程真源/和 agent 一起做规划/04.md]]；05 篇第一节接受撤回，并给出管道铺不开的机制（这条通道依赖入口系统发 request id，只覆盖 3 门带 hash 后缀的课）[[01-交互式学习/02-课程真源/和 agent 一起做规划/05.md]]。

2. 回填与默认设置。原话逐字：「那我已经没有写在这里了，没有写在这些学习反馈里。那你会不会帮我回填到学习反馈里面去？对吧？我不知道」「它为什么还是没有去走默认设置？反而有时候还会占据我很多的 token？」。课程侧：05 篇第二节回答——dbs-learning 的流程原文是「找到序号最大的那一篇，阅读该文章末尾的『学习反馈』」，它假设反馈已经在文件里；现存唯一自动通道只覆盖 3 门课；此前回填一直是人肉摘要，那是转述不是原料；本轮才把 01—04 的原话逐字回填[[01-交互式学习/02-课程真源/和 agent 一起做规划/05.md]]。04 篇的说法是「闭环在我这一侧是通的」，断点在「你的原料有没有被存成下一篇能直接读的东西」[[01-交互式学习/02-课程真源/和 agent 一起做规划/04.md]]。

3. ELI5。原话逐字：出处指向 claude-plugins-community；提示词为「请把我当成对这个话题一无所知的人，用一个包含大图且文字较少的 HTML 组件来向我解释。」；并说「其实你要是不经常用都没必要去安装这个 Skill，这个 Skill 里面也就是一句提示词而已。」。课程侧：04 篇第三节此前查过 agents／claude／codex／zcode／dsh 技能目录与 `Documents`，没有命中叫 ELI5 的 skill，并说它在别的工具里的话说一声去核[[01-交互式学习/02-课程真源/和 agent 一起做规划/04.md]]；这一轮用户给的就是出处。所取来源[[https://github.com/anthropics/claude-plugins-community/blob/main/eli5/skills/eli5/SKILL.md]]只到页面外壳，元信息显示 10 lines (7 loc) · 321 Bytes，正文与提示词未取到，来源状态自记「已读取，仍需核对主张」。

4. 约束前提。原话逐字：「假设我们之前的约束没有问题（那个约束是建立在我赶 DDL 的情况下，我不知道它能否被证伪，这是第一点；假设它已经被证实了，那我们就按这个去设计）。」。课程侧：03 篇写下的硬约束是「降低读的成本，同时不降低输出的量」，并称它是「这门课里唯一一条不需要引用的判据」[[01-交互式学习/02-课程真源/和 agent 一起做规划/03.md]]；05 篇第四节把它用作三段设计的成立条件[[01-交互式学习/02-课程真源/和 agent 一起做规划/05.md]]；学习计划的占位 W-0921-4 记着同一件事的待验[[01-交互式学习/02-课程真源/和 agent 一起做规划/00-学习计划.md]]。

5. 三段设计。原话逐字：「1. 输入与清洗：在某一个对话区（比如 DeepSeek 的对话框）、文档或文件夹里，我说出或写下反馈。系统找到它后帮我补充上下文，接着做各种溯源、对照，处理矛盾点并完成清洗。」「2. 自动化产出闭环：结合 DBS 的 content-system 和内容工厂，转化为一个产出过程。这就是一个很纯粹的费曼闭环产出，把纯粹的交互式学习推进到后期的自动化闭环。」「3. 辅助材料定位：其中词汇表可以承担溯源、补充上下文、矛盾清洗那一块的作用；手写笔记存下来则可以当作链路图。」。课程侧：05 篇第四节用一张表逐条给成立条件——输入与清洗要「你不配合它也能工作」（四轮都没写已是一次实测）；自动化产出闭环的出口必须是用户的一手判断（按能量账，整理稿是复述、负收益）；词汇表要过第三条判据（改一个词，下游引用跟着改），做不到就仍旧是命名而不是中间物[[01-交互式学习/02-课程真源/和 agent 一起做规划/05.md]]。三条判据与「词汇表只是入场券」出自 02 篇[[01-交互式学习/02-课程真源/和 agent 一起做规划/02.md]]。

6. 60%—80% 与疑问。原话逐字：「我自己交互式学习的课，大概有 60% 甚至 70%、80% 后面都没再去翻过。打不打开，取决于我后续有没有产生新疑问。资料是有的，但疑问往往找不到。」。课程侧：05 篇第三节把「回访率低」从资料问题改判成疑问问题，并把 60%—80% 与开环报警、135 项目那条硬边界（标〔来自记忆摘要，未回源核〕）并置[[01-交互式学习/02-课程真源/和 agent 一起做规划/05.md]]；学习计划把它记成一条变量[[01-交互式学习/02-课程真源/和 agent 一起做规划/00-学习计划.md]]。

7. Token。原话逐字（同上第 2 条的后半句）：「反而有时候还会占据我很多的 token？」。课程侧：05 篇给的是估算——每轮要读课程文件、skill 文本与项目规则，本课四篇加选材索引约 8 万字符；并把无回填时的开销写成双付：先为读付费，再为丢失付费[[01-交互式学习/02-课程真源/和 agent 一起做规划/05.md]]。

## 口径与误读防线

- 60%—80% 是用户自述估计，05 篇也只称它是「开环率的一个估计值」[[01-交互式学习/02-课程真源/和 agent 一起做规划/05.md]]；不要把未回访当失败，也不要把它当课程内容质量的证据。
- 学习计划的痕迹快照是 2026-09-21 回填前的状态；plan 自注「『没写进文件』不等于『没发生』，本课四轮反馈都走对话，即为反例」[[01-交互式学习/02-课程真源/和 agent 一起做规划/00-学习计划.md]]。
- 04／05 篇正文里的第一人称是课程文本的叙述（05 篇标【我】的是写课方的判断），不是用户履历；用户打勾与手写笔记的证据在 03 篇的转录里，03 篇自己声明转录可能有误读[[01-交互式学习/02-课程真源/和 agent 一起做规划/03.md]]。
- 本条反馈提供的是用户自述与设计意图；本页不把「log 没用了」「对话没写进反馈」升级成对用户行为的结论。
