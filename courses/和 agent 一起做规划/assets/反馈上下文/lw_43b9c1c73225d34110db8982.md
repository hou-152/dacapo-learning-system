## 反馈与课程的直接联系

1. 产物定稿。反馈原话「其实这节课我觉得最终的产物，可以把我们前面说过的无限画布加上类似 Obsidian 的 AI 插件，做成一个由大模型加持的 Agent loop。有些开源项目完成度可能比我们更高，该用就用。」[[01-交互式学习/04-用户原话与费曼/工作台视图/lw_43b9c1c73225d34110db8982.md]]。08.md 开头写成「产物你已经定稿了：无限画布 + Obsidian 类 AI 插件 + 大模型加持的 Agent loop，开源项目完成度更高就直接用。」并加上一条守线：loop 的中间物必须是用户能读写的文件（Markdown 这一层），不能是某个 app 的私有数据库 [[01-交互式学习/02-课程真源/和 agent 一起做规划/08.md]]。

2. 多模型与多 Agent。反馈原话「我现在真正的问题是：我们这个 Agent loop 的形态到底该怎么使用？

1. 多模型之间究竟该如何调用与调动？
2. 多 Agent 之间该如何协调？这确实是我之前一直以来的难题。」[[01-交互式学习/04-用户原话与费曼/工作台视图/lw_43b9c1c73225d34110db8982.md]]。08.md 第二节给出多模型按判断类型分工，不按强弱，并写三条编排规则；第三节给出多 Agent 靠工件不靠对话，引用一条标〔记忆〕的工件化路由规则与《多 Agent 编排 2W2H》五项 [[01-交互式学习/02-课程真源/和 agent 一起做规划/08.md]]。06.md 已先把 jev 定位在回路第①/②步，说明它能接打标、接不了叙述，这为「多模型」中的小模型角色提供了前置判断 [[01-交互式学习/02-课程真源/和 agent 一起做规划/06.md]]。

3. 外包边界。反馈原话「确实有些东西可以很早就解决，很多东西也都可以外包。但真正类似 idea 的核心内容，还是得我们自己慢慢去推敲和推进，这才是比较有意思的地方。」以及「比如去写、去编代码这类东西可以外包出去，但如果自己坚持做，就一定要跟 AI 聊清楚，交互式学习的反馈必须要有。而我认为不应该外包的，其实是阅读，真正的阅读。」[[01-交互式学习/04-用户原话与费曼/工作台视图/lw_43b9c1c73225d34110db8982.md]]。07.md 的四条检验（标准是否稳定、代价是否可兜回、是否需要你的目的、一天能否训出）是后续判阅读不能外包的工具 [[01-交互式学习/02-课程真源/和 agent 一起做规划/07.md]]；08.md 用它把阅读四条全不中、把「找资料、筛摘要、判相关性、做对照」划为可外包 [[01-交互式学习/02-课程真源/和 agent 一起做规划/08.md]]。反馈里「交互式学习的反馈必须要有」对应 04 起改用的回填口径，也对应 08.md 第一版三件事里的「一个写入动作：把打标结果落回对应文章末尾的反馈区」[[01-交互式学习/02-课程真源/和 agent 一起做规划/08.md]] [[01-交互式学习/02-课程真源/和 agent 一起做规划/00-学习计划.md]]。

4. 实践过程。反馈原话「对于我们这个个人工作台来说，本身就是一个实践的过程。我其实并不在意它能给我做出什么样的代码，有就改呗，反正交互学习我都有记录。」[[01-交互式学习/04-用户原话与费曼/工作台视图/lw_43b9c1c73225d34110db8982.md]]。08.md 把它接回 01 的诊断：这个工作台没法先在纸上做完，属于「只能边做边改」的那类决定 [[01-交互式学习/02-课程真源/和 agent 一起做规划/08.md]]。
