# 03｜知识库没用，那你要的东西长什么样

## 这一篇要解决的问题

你把课程的工具反过来对准了自己想做的事：一个真正降低学习成本的工具，「击穿边界物、击穿中间层」的那种，以及你说不清的「纯粹的交互式学习」。

这一篇不替你设计产品。它只做一件事：把你的想要压成能被检查的形状，好让下一步不是再建一个 Wiki。

## 正文

### 一、先对一下你的笔记

你画出来的结构，我读到的是这样：

- 计划最好被看作临时行动的一种弱资源 → 规划者 ≠ 执行者 → 两个世界不可互读；
- How：边界物 → 词汇表 → 一物多名、一名多物 → 自证预言 / 反身性；
- 三条判据你各打了一个勾：两边都能指着它说话（共享身份）、两边各自用它做不同的事（可塑性）、改动它两边的工作都跟着变（可操作）；
- 成本层 → 视觉、交互、可操作；结构层 → 撞现实、看结果；
- 旁边还留了「agent loop / graph ?」和一句关于软件的猜测。

如果哪一条我读错了，直接说。

### 二、Wiki 为什么没用：第三条判据

【你】「我其实曾经建过很多次各种各样的 Wiki，但其实都没什么用。后来我想，我需要的可能不是知识库，而仅仅是知识管理。」

用你自己打的那三个勾来判：一个 Wiki 满足第一条（你任何时间点都能指着它说话），第二条也勉强（存和取是两种用法），卡在第三条。往里放一条笔记，你的工作不会跟着变——明天要做的事和今天一样多，只是多了一页可搜的文字。

【我】所以「知识管理」和「知识库」的差别可以压成一个可检查的问法：**这个工具被改动的哪一处，会让你的哪件工作变得不一样。** 答不出这一句，它就是第三个 Wiki。

你那条「击穿边界物、击穿中间层」的直觉，按这个判据读，指的是同一件事：中间物要能被穿过去动手，而不只是被看着。

### 三、你的账簿已经给这个工具设了一条硬约束

【你】能量账唯一规则：输出自己的东西 = 充电，复述别人的东西 = 掉血。

这条规则对工具形态有直接后果。一个「帮你读、帮你总结、帮你存」的工具，降低的是读的成本，同时把你往复述那一侧推。按你自己的账，那是负收益。

于是设计约束可以写成一句：**降低读的成本，同时不降低输出的量。** 这一句会把形态从「更好的阅读器」推向「逼你交东西的东西」——比如它不收你的摘要，只收你的判断；不保存你的划线，只保存你用它做出的决定。

这条约束是你账本给的，不是外部建议。它也是这门课里唯一一条不需要引用的判据。

### 四、「击穿中间层」在工程上的一块料

12 号 json-render 解决的是另一头的问题：让模型生成界面，同时保证生成的界面不会跑出你定义的形状。

【原文】「When users prompt for UI, you need guarantees.」做法是给模型一套受约束的词表：模型不写代码，只产出一棵符合 schema 的 JSON 树，渲染由你事先定义的 React 组件负责。收益三条：只能用你目录里的组件（Guardrailed）、每次输出都匹配 schema（Predictable）、流式渐进渲染（Fast）。

【我】这套做法能直接搬到你那个工具上。如果你要 agent 现场为你生成可操作的中间物（一张能改的图、一个能点的面板、一份能选的对照表），你必须先有那份组件目录，否则它每次生成的东西都是新的文字墙，你读它的成本和读聊天记录一样高。

代价要说清楚：写那份组件目录是人的活，也是这个方案里唯一不能外包给模型的部分。这跟她的价值排序是一致的——agent 做廉价劳动，人做定语汇表的那部分。

### 五、「纯粹」怎么算

【你】「纯粹的交互式学习：非常纯净的交互式学习，具体我也还描述不太清楚。」

说不清的地方，先用候选逼近。三种都可以选，也可以都不选：

| 候选 | 内容 | 要付的代价 |
|---|---|---|
| A | 不预先写文章：推进全在对话里发生，课程文章不再出现 | 没有可回看的外部记录，下一轮会话接不上 |
| B | 学习者先出：你每次先给原始判断，我只补最大缺口，永不先讲 | 速度变慢，且要求你每次都有原始判断可给 |
| C | 你说的第三种 | — |

【我】A 和 B 会和 02 的结论打架：你想要的越纯，可回看的中间物越少。所以真要做工具，它得负责把对话过程自动固化成能回看的物件——这件事现在由我手写文章来做，也正是你想省掉的那部分人工。

顺着这条往下，pure 的判据可以写成：**一节课结束时，除了一段对话，还多出一件能指着说话的东西。**

### 六、本篇最小动作

一句话，别写方案：

> 如果 ________ 这个东西做出来，我会在 ________ 这件事上，比现在多做 ________。

再补一行：如果这句话是假的，我会看到的证据是 ________。

（第二节那个问法和第三节那条约束，可以直接拿来当这句话的检查器。）

## 小结

1. 你的笔记已经把 02 的结构转成了自己的动作表，三条判据你都用上了。
2. Wiki 失效的位置是第三条：改它，工作不变。知识管理可以压成一个问法——改动哪一处，哪件工作会不一样。
3. 你的能量账给工具加了一条硬约束：降低读的成本，同时不降低输出的量。
4. json-render 给的是「击穿中间层」的工程底料：先写组件目录，模型只填受约束的 JSON。
5. 「纯粹」目前有三个候选定义，代价都是同一个——少了可回看的中间物。工具该负责把这段补回来。
