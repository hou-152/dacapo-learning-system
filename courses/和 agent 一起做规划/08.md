# 08｜这个 Agent loop 该怎么用

> 材料：选材六篇（`assets/260921-选材/`）＋你自己的既有规则（多 Agent 分工、工件化交接，「来自记忆摘要，未回源核」，标〔记忆〕）＋本课程前七篇。
> 标【你】的是你本轮原话；标【我】的是我的判断。

## 这一篇要解决的问题

产物你已经定稿了：无限画布 + Obsidian 类 AI 插件 + 大模型加持的 Agent loop，开源项目完成度更高就直接用。你要的不是架构图，是「该怎么用」。这一篇回答你那两个问题——多模型怎么调动、多 Agent 怎么协调——最后把「阅读不外外包」这条放回形态里。

## 正文

### 一、产物定稿，但守一条

【你】「有些开源项目完成度可能比我们更高，该用就用。」

【我】这条本身就是 06 那个判据在替你做事：外壳不是边界物，画布与文件格式才是。要守的只有一件——**loop 里的中间物必须是你能读写的文件**（Markdown 这一层），不能是某个 app 的私有数据库。开源项目随时可以换，格式一旦丢了，你的历史就锁在别人的壳里。

【你】「对于我们这个个人工作台来说，本身就是一个实践的过程。我其实并不在意它能给我做出什么样的代码，有就改呗。」

这句话是把 01 那条诊断用在自己身上：这个工作台没法先在纸上做完。它属于你切出来的第二类决定——只能边做边改的那种。「有就改呗」也正好对上她的价值排序：外壳是廉价劳动，判断留在你手里。

### 二、多模型怎么调动：按判断类型分工

不要按强弱分，按 07 那四条检验分。分完是这样的：

| 判断类型 | 谁做 | 典型活 | 判错在哪看见 |
|---|---|---|---|
| 高频、可兜回、标准稳定的分类 | jev 这类小模型 | 给反馈原料打标、判相关性、筛重复 | 抽样复查：随机抽 20 条人工过一遍 |
| 要写句子的生成与对照 | 大语言模型 | 占位问题、补上下文、做对照报告 | 你在答录时发现不对劲 |
| why／what、代价不对称的裁决 | 你自己 | 要不要做、为谁做、什么时候停 | 没有下游能兜，只能自己背 |

【我】三条规则可以写死在编排层，模型只做单轮调用（这条和你 135 项目里那条一致〔记忆〕）：

1. **每次调用先指出它属于哪一类判断。** 指不出的，先别接。
2. **同一类判断只派一个模型。** 两个模型判同一件事，你得到的是两个结论，不是一次判断。
3. **每个输出字段都要能接一个「错了在哪看见」。** 接不上的字段，不进 loop。

关于第 2 条有个例外：如果第二个模型给的是**对照**（它怎么归类、把握多大），那它就不是重复判断，是多了一个控制点。这跟 06 那张表是同一条线。

### 三、多 Agent 怎么协调：靠工件，不靠对话

【你】「多 Agent 之间该如何协调？这确实是我之前一直以来的难题。」

你手上已经有一条自己拍过板的候选规则〔记忆〕，它正好对着这条难题：

> 跨会话、跨 Agent、改变状态或权限、覆盖旧决定、需验收追责 → 必须工件化（绑定 run id + 任务 hash + 结果 hash）；探索与一次性反馈留对话；同一原则第二次口头解释，即触发工件化。

【我】这条规则说白了就是用课程的第三条判据在管人机通道：**把一段对话变成一件可改动的物**。协调出问题的时候，绝大多数不是 Agent 不够聪明，是这次交接没有物件——对方只能靠记忆和猜测继续。

再叠上你自己在《多 Agent 编排 2W2H》里拆过的那五项：触发、交付物、通道、验收、例外。协调失败十个里有九个是这五项缺了一项。落到你的 loop 上，最小可用的协调协议是三句话：

1. 每个 Agent 只做一类判断（照第二节那张表分派角色）。
2. 每次交接留一件物，不留一段话。
3. 每周看一次开环清单：做完没下文、下轮没引用的，都算开环。

第三句是你账本里那条开环报警〔记忆〕。它也正好治你 60%—80% 那个数字：没被回访的课，就是一笔挂着的开环。

### 四、阅读为什么不能外包

【你】「我认为不应该外包的，其实是阅读，真正的阅读。」

拿 07 那四条检验量一遍，它一条都不中：

| 检验 | 阅读 |
|---|---|
| 标准是否稳定 | 不稳定。同一段文字对不同的人给出不同的东西 |
| 代价是否可兜回 | 不可。读漏的东西，你不会知道自己漏了 |
| 是否需要你的目的 | 需要。读什么取决于你拿它去做什么 |
| 一天能否训出来 | 不能 |

【我】再补一条本课程给的理由：她的三层诊断里，阅读是薄界面最大的受害者。把阅读交出去，交出去的不是时间，是判断的原料。

分界线可以画得再细一点：

- 找资料、筛摘要、判相关性、做对照 → 可以外包（这是 jev 那类活的射程）
- **读** → 自己读

【你】还加了一句条件：自己坚持做的部分，必须跟 AI 聊清楚，交互式学习的反馈必须有。这跟你的账本一致——读进来的是原料，说出来并留下回执的才算充电。

### 五、第一次真实运行

第一版只做三件事，别的都先不做：

1. **一份画布**：你的课程文件、选材、占位表已经在里面（本课题就是现成的一小块）。
2. **一个分类器**：用 jev 或同类小模型给「反馈原料」打标，字段固定成：属于哪篇、哪一类判断、置信度、要不要你裁决。
3. **一个写入动作**：把打标结果落回对应文章末尾的反馈区——也就是本课从 05 起一直在人肉做的那件事。

验收判据（可证伪）：

- 三周内，占位表里被触发取用并结清的条目 ≥ 3。
- 回填过的反馈中，被下一篇引用的比例高于现在。

反面证据：画布打开次数上去了，占位触发是 0。那说明它还是一块更好看的白板——按第三条判据，它没有改变任何工作。

## 小结

1. 产物定稿，守一条：中间物必须是你读写的文件，壳可以随时换。
2. 多模型按判断类型分工，不按强弱；每次调用先说出它属于哪一类，并配一句「错了在哪看见」。
3. 多 Agent 协调靠工件不靠对话；你那条工件化路由规则〔记忆〕正是这条判据的落地版。
4. 阅读四条检验全不中，不能外包；可以外包的是找、筛、判相关性。
5. 第一版只做三件事：画布、分类器、写入动作；验收看占位被结清的条数，不看打开次数。

## 结课说明

这门课的选材六篇已经走完，主线（边界物与更厚的界面）与你自己的形态决定（画布 + 插件 + loop）已经接上。往下有两条路，你选：

- **结课**：把 08 的最小实验拿去跑三周，回来回填结果，再决定要不要接着开课。
- **立项**：把「个人工作台」当成一件事立起来（目标、验收、权限边界、断点续跑）。这一步不属于教室，属于 `dbs-goal` 或 `define-goal` 那扇门，说一句我就换工具。
