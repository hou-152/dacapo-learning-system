# 和 agent 一起做规划｜学习计划

## 学习目标

学完这门课，你手上应该多出四个可检查的动作：

1. 拿一次自己和 agent 的真实规划经历（选型、排期、写方案），指着具体那一步，说清它落在 Appleton 诊断的哪一层（计划当脚本／规划者与旅行者分离／文字墙超载）。
2. 在自己的系统里点名至少三件「边界物」，并对每一件回答：它现在主要为谁优化，证据是它上一次让你改主意是什么时候。
3. 对着一个真实决策点，写出一个「更厚的界面」最小改造动作，并说明它把哪部分工作从工作记忆搬到了世界里。
4. 用 Appleton 的两个自问检查一件你正在做的东西，给出一个能落地或明确否掉的答案。

## 学习路径

1. **看清诊断，认下边界物**（01—02）：把「计划是弱资源」「规划者与旅行者分离」「两个互不可读的世界」装成三个能用的判断词，落到你自己的规划经历上；再把边界物和你已经拆过的跨角色交接接口对齐。
2. **中间物怎么造厚**（03）：看 12 json-render 用受约束词表换「保证」这条工程路径，再把它用在你「知识管理工具」的设想上。
3. **反馈、回填与回访**（04—05）：用痕迹查「新课题没什么用」这条自述；定位断点在原料沉淀；把回填从人肉动作变成课程默认动作的替代品；用 60%—80% 这个数字把变量换成疑问。
4. **形态与第二个判断者**（06）：把新模型 jev 放进回路，只让它接「打标」那两步；用 danluu／控制点论／18 三条量它与你的分工。
5. **收束到形态决定**（07）：01 主张写作过程本身不可外包；把六篇压到「无限画布 + Obsidian + 插件」这一个决定上，产出最小实验判据清单。

> 路径会按每篇末尾的真实反馈调整；文章数量与顺序可以变。
