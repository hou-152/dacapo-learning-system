# 01｜Agent = 模型 + harness：把「养小龙虾」翻译成工程语言

## 这一篇要解决的问题

四份材料都说「自进化」，但它们说的不是同一件事。这一篇先立一个共同的底座：把你的小龙虾拆成「模型」和「模型外面那套系统」，看清每一层负责什么。读完你会知道，所谓「养虾」「自迭代」，发生的位置在三层不同的部件上，而且你手上正好有一套能对照的旧知识。

## 正文

### 一句话先把四份材料收拢

欣烨的课程给了你一句口诀：普通聊天看现在，定时任务看时间，心跳看变化。这句话管的是「小龙虾什么时候开始干活、什么时候停、怎么回报」。三个动作的差别，全在「谁在等」。

但在这句口诀下面还垫着一层东西：小龙虾凭什么「能」定时？凭什么记得你上周说过什么？凭什么按约定只读不写？这一层，就是今天要拆的 harness。

### 内参给的公式

LangChain 那篇把整件事压成一行：

**Agent = Model + Harness**

模型只做一件事：吃进文本，吐出文本。它不知道现在几点，跨不了会话，碰不到你的文件。凡是包在模型外面、让它能按时干活、能记住事、能碰工具的代码、配置和执行逻辑，全部算 harness。作者给的定义干脆得有点粗暴：「If you're not the model, you're the harness.（只要你不是模型，你就是 harness。）」

你手里的小龙虾就是一份「模型 + harness」的打包：

- 模型：deepseek、glm、kimi k3 这些，负责理解和生成，可随时换。恒在直播里演示过多模型轮换，哪层任务配哪档模型本来就是 harness 的设计项。
- harness：OpenClaw 这套运行时。system prompt 六文件、记忆组件、定时任务、心跳、skill、回执通道，全在这一层。

### 把 harness 摊开，用你熟悉的四层看

你在知识库课题里已经学过 Agent 记忆的分层。这里不用新框架，把你熟悉的四层套上去，OpenClaw 的部件会各就各位。

**第一层：系统提示层。** 六个 markdown 文件：agents、so、user、identity、tool、memory。米罗管它们叫「小龙虾的入职培训手册」，他的已经写到 1.7 万字。每次你发消息，模型拿到的是一份组装好的系统提示 + 你的话，然后才轮到生成。这一层决定小龙虾是谁、守什么规矩、汇报什么格式。

**第二层：记忆层。** OpenClaw 官方的四个组件：dreaming（每天凌晨三点「做梦」整理记忆）、active memory（对话时主动插入记忆）、memory index（把纯文本记忆向量化）、memory wiki。重点是米罗那条提醒：这四个组件**默认全部关闭**。装好不等于开启。这一层对应你学过的「记忆分层」的落地形态，也对应米罗说的「养虾」——他 140 天的 11GB 上下文，大部分都沉淀在这一层。

**第三层：行动层。** 定时任务（cron）、心跳（heartbeat）、skill、工具调用。欣烨的口诀发生在这里：普通聊天是模型在回答，定时任务是系统到点拉起模型，心跳是系统隔段时间叫醒模型看变化。这一层管「什么时候开始、什么算完成」。

**第四层：验证层。** 回执、运行记录、欣烨的四步验收（听懂 → 存进系统 → 执行 → 送达）。你在 CONTEXT.md 里管这叫回填环。这一层最不起眼，却是全部「自迭代」能不能转起来的引擎。

### 三个「自迭代」，落在三层上

现在可以回答那个问题了：四份材料说「自进化」，为什么听着像三件事？因为它们迭代的对象本来就在三层上。

1. **数据层迭代 = 记忆层在变。** 米罗的模式：你纠正它一次，它把规则沉淀进记忆文件，下次直接用。迭代的对象是记忆和数据，规则文件本身不常改。慢，但稳。
2. **行动层迭代 = 行动层的「谁在等」换了。** 欣烨的模式：任务从「你发消息它干活」变成「到点它自己干、干完送回执」。迭代的对象是工作方式。
3. **程序层迭代 = 系统提示层和 skill 在改自己。** 恒给的四步模板：执行完回顾 → 提取 1-2 条经验 → 追加进 experience-log.md → 下次先读。迭代的对象是行为策略本身。最快，也最容易翻车。

你项目里那套 ITERATION-HARNESS（Captain / First Mate / 证据类型 / 回滚）和 skill-darwin 案例，就是第三种迭代的加强版：给「改自己」加上了证据、判定和回滚。

### 本课题的工作定义

到这里可以给「自迭代」下一个我们这门课自己的定义：

**自迭代 = 系统带着「证据 + 判定 + 回写」跑圈，人站在验证层当验收员。**

缺回执的自动运行叫后台噪音；有回执但没有判定的循环叫原地打转。欣烨那个「任务连跑 7 次、每次 10 分钟超时、成功 0 次」的案例就是后者——系统看着在跑，其实一次都没成，最后发现是任务被放进了读不到上下文的会话里。内参那篇 RSI 文章从另一个方向补了同一句话：没有可判分的验证环，迭代就转不起来。这个结论到第三阶段会正式展开。

### 今日最小动作：给你的小龙虾做一次 harness 体检

你已经部署好了。今天不动配置，只做三件事，做完记下来：

1. **记忆层**：问它「你现在默认开启的记忆组件有哪些？dreaming、active memory、memory index、memory wiki 里哪些还没开？」看它答什么。
2. **系统提示层**：让它「用一句话分别说明你 agents / so / user / identity / tool / memory 六个文件现在各自管什么」。如果它答不上来或答错，说明这些文件可能没配或没喂进上下文。
3. **行动层**：说「我准备创建一个未来 24 小时内只执行一次的只读任务。请先告诉我，你需要我提供哪些信息才能创建」。看它会不会主动要「具体时间、时区、执行次数、回执发到哪里」。

三条结果记在下一篇的学习反馈里。特别是第 3 问它漏掉的信息，下一篇讲六件套时会用得上。

## 小结

1. Agent = Model + Harness。模型只吃文本吐文本，按时干活、记忆、工具、回执全是 harness 的活。
2. 你的小龙虾 = 模型 + OpenClaw 运行时；harness 可以按系统提示层、记忆层、行动层、验证层四层来看。
3. 三个「自迭代」对应三层：数据层（记忆沉淀）、行动层（定时/心跳 + 回执）、程序层（skill 改自己）；验证层是引擎。
4. 本课题定义：自迭代 = 证据 + 判定 + 回写跑圈，人当验收员。
5. 今日动作：harness 体检三问（记忆组件、六文件、定时任务所需信息），结果记进学习反馈。
