# 03｜创建 + 四步验收：任务从「说清楚」到「真跑起来」

## 这一篇要解决的问题

上两篇的反馈里有两处要优先接住：两套「分层」记混了，cron 和 harness 的上下文关系要精确化。接住之后，本篇把任务从草稿推到真实运行：创建它，并走完四步验收（听懂 → 存进系统 → 执行 → 送达）。到点之前的动作今天就能做完，等回执的事交给系统。

## 正文

### 先接住你上两篇的反馈

**1. 「知识库的分层我有点忘了」+「系统分这个分层有吗」——两套切法，你没错。**

01 里那四层（系统提示层 / 记忆层 / 行动层 / 验证层）是本课题自己起的名字，用来切 harness。你知识库课里记的四个存储件（元数据、内存、向量库、滑动窗口）是另一套切法，切的是「知识怎么存、怎么取」。两套切的是同一个东西的不同侧面，记混很正常。对照表：

| 知识库课的四个存储件 | 本课题的四层 | 在 OpenClaw 里的对应 |
|---|---|---|
| 元数据 + 滑动窗口组装 | 系统提示层 | AGENTS / SOUL / USER / IDENTITY / TOOLS / MEMORY 六文件 |
| 内存 + 向量库 | 记忆层 | memory index（你已开，715 个文档）、active memory |
| 那门课没讲，它讲的是存取，不讲话动 | 行动层 | cron、心跳、skill |
| 那门课在检索评估和面试答法里带过 | 验证层 | 回执、运行记录、四步验收 |

所以「有这个吗」的答案是：前两层的一半你学过，行动层和验证层是这次新起的名字。

**2. 「Cron 不受上下文影响，harness 受上下文影响」——直觉对，措辞再精确一步。**

调度不受上下文影响：到点必跑，你不在线它也跑。执行受上下文影响：它跑的时候手里那份上下文从哪里来，决定了干不干得成。harness 是整套外壳的总称，不单指「受影响的部件」。这条区分正是本篇四步验收的第三、第四步要抓的东西，下面欣烨的 7 次超时案例会把它打透。

**3. Task Packet 你没印象，那就从「已确认基础」里拿掉。** 本篇起不默认你会它，改拿你自己刚拿到手的真证据当锚点（见下一节）。

**4. First Matter 是 front-matter 的误记**，指 skill 文件开头那段 YAML 头。04 拆 skill 时正式讲。

**5. 体检结果接住了。** memory index 已开启、active memory 按需检索、dreaming 和 memory wiki 未确认开启——这就是米罗说的「官方默认全关」状态。你已经有一只开始攒记忆的虾了（715 个文档）。补一个动作：这套结论来自对话自述，找时间到设置界面或 WEB UI 对一眼痕迹，看看哪些组件真的有开关。

### 你的小龙虾已经先学会了六件套

你 02 的反馈里贴了一段很有价值的真证据：你问它创建任务需要什么，它回了 8 项（任务目标、检查范围、执行时间、成功标准、失败处理、允许动作、反馈入口、反馈格式），还给了一个填空模板，并承诺「先复述任务类型、时间、时区、次数、权限、反馈入口，确认无误后再创建」。

把这 8 项和六件套对齐：

| 虾的模板 | 六件套 | 备注 |
|---|---|---|
| 任务目标 | 看什么 | |
| 检查范围 | —— | 六件套把范围压进「看什么」，虾拆出来更细 |
| 执行时间 | 什么时候做 | 记得写时区和「只执行一次」 |
| 成功标准 | 什么算有用 | |
| 失败处理 | 没找到怎么办 | |
| 允许动作 / 禁止动作 | 能做什么 | |
| 反馈入口 + 反馈格式 | 带回什么 | 入口和格式分开要 |
| 任务名称 | —— | 六件套没有，加上：以后在任务列表里一眼认出 |

结论：虾侧的模板已经覆盖六件套，还多要了三样有用的东西。人侧的任务卡（02 那张）和虾侧模板对齐后，创建就能过第一关。它承诺「先复述再创建」，这步是四步验收的第一步，但它复述了不等于你验收通过——「不要相信一句已经好了」仍然成立。

### 四步验收：一项一项确认，不跳步

课程里给的四步：

**第一步，听懂。** 它能复述任务正文。检查动作：创建后只追问一句——「请复述刚刚创建的任务：具体日期、钟点、时区、执行次数、反馈入口。不要重新创建任务。」复述对得上，第一步过。

**第二步，存进系统。** 你能看到这条任务存在于任务列表，时间、类型、启用状态都正确。这一眼看的是设置界面或任务列表，顺手截图（遮掉私密信息）。

**第三步，执行。** 到点后看运行记录。成功、超时、报错都属于真实运行结果；重点是它真的动手了。

**第四步，送达。** 回执真的到了你选的入口（当前对话或飞书群）。运行记录里「已执行」不等于「你收到了」。

四步必须分开确认，因为一项任务看着一直在跑，也可能一次都没成。欣烨的案例：一条 Meyo 检查任务每 4 小时跑一次，设置界面显示一直在工作，实际连跑 7 次、每次 600 秒超时、成功 0 次、收到的有效结果 0 条。原因：任务被单独放进了一个读不到原对话上下文的会话——它连 Meyo 是什么都不知道，自然缺材料。修复动作：停掉错误任务 → 放回主会话（带上原对话内容）→ 手动跑一次，确认能完成、回执到面前。要记住的就一句：**任务在重复运行，也可能一次都没成功。**

这条案例同时把你的直觉钉死了：调度照常到点（不受上下文影响），执行却因为缺上下文 7 连超时（受上下文影响）。

### 动手清单（今天）

1. 把 02 任务卡的【时间】填成未来 24 小时内你方便回看的时刻。
2. 把任务卡发给小龙虾创建。它若又给 8 项模板，就按任务卡的内容逐项填进去，填完对照一眼它有没有漏项。
3. 创建后只追问那一句复述，不要重新创建。
4. 今天能确认到第二步（听懂 + 存进系统，含截图）。到点后收第三步（运行记录）和第四步（回执到入口）。
5. 回执回来后按三件套检查：成功带回「学到的内容 + 来源 + 最小下一步」；失败带回「查过什么 + 卡在哪 + 原话」。截图留存（遮私密）——这是作业 05 的一半。
6. 你补一个「建议」：从它带回的经验里挑一个你愿意尝试的最小下一步，写一句话——这是作业 05 的另一半。作业 05 交付物 = 六要素任务说明全文 + 真实执行回执截图。

## 小结

1. 01 的四层是本课题切 harness 的新名字；你知识库课的「元数据 / 内存 / 向量库 / 滑动窗口」是切存取的另一套——对照表把两套接上了。
2. 精确版：cron 的调度不受上下文影响，执行受上下文影响；harness 是整套外壳的总称。
3. 你的虾自己给出的 8 项模板已经覆盖六件套，还多出任务名称、检查范围、反馈格式三样有用的。
4. 四步验收一步一确认：听懂 → 存进系统 → 执行 → 送达。欣烨 7 连超时的案例 = 调度正常、执行缺上下文。
5. 今天的活：填时间 → 创建 → 追问复述 → 确认到第二步并截图；到点收执行和送达；回执回来补「建议」。
