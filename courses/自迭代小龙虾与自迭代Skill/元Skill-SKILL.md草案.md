# 元Skill：skill 生命周期的守门与路由层

本 Skill 只做 4 件事：**识别阶段、定合同、出证据、路由执行**。所有重活由被路由的资产完成，本 Skill 不发明新流程。

## 阶段判定

- 「帮我设计 / 做一个 skill」「把这个主题做成 skill」→ **设计**
- 「审计 / 体检 / 评审这个 skill」「这个 skill 为什么触发错 / 跑不好」→ **审计**
- 「改 / 进化 / 优化 / 迭代这个 skill」「把这次翻车变成修复方案」→ **迭代**

## 三阶段流程

| 阶段 | 干什么 | 复用资产 | 产物 |
|---|---|---|---|
| 设计 | 定 skill 合同：目标、触发边界、流程、验证钩子、回写口子 | `03-Harness-设计合同.md`、`06-未来薄Skill候选规格.md` 三个风险当检查单 | 合同草稿 |
| 审计 | 对已有 skill 出证据：合同核对、四部件体检、交付物 vs 合同 diff、已知问题回放、触发实测 | `ITERATION-HARNESS.md` 证据类型 | 审计报告 |
| 迭代 | 一条窄假设 → 候选 v2 → 盲测 → 用户批准替换或回滚 | `skill-darwin-lite`、`loop-engine` | 候选 + 回滚点 |

## 硬性规则

1. **不自动改 SKILL.md**：任何修改走「候选 + 盲测 + 回滚」，最终覆盖由用户批准。
2. **不新造机制**：本 Skill 只路由，不发明新流程。
3. **审计报告每条结论必须带证据类型**：SOURCE_PRINCIPLE / OBSERVED_FAILURE / ENGINEERING_INFERENCE / DECISION。
4. **交付物 vs 合同逐条 diff**：专查合同漂移（要番茄炒蛋交付东坡肉），执行在合同之外添加的机制必须显式标记并交用户裁决。
5. **每次运行后写 experience-log**：观察层自动写；策略层规则由用户验证后标注「已验证 + 日期 + 验证人」。

## 不做什么

- 通用问答、人格塑造、自动记忆写入、对一切任务强制加载。
- 不重复 skill-darwin-lite / loop-engine / nuwa-skill / engineering-meta 的具体执行，只路由到它们。

## 验收用例

- 审计后报告每条结论带证据类型，每条问题配最小修复动作。
- 迭代后留下：一条窄假设 + 候选 + 盲测记录 + 回滚点 + 用户批准记录。
- 合同漂移案例（用户真实反馈）：要求「番茄炒蛋」交付「东坡肉」，整改后交付「无东坡肉版番茄炒蛋 + 加料」——审计必须能识别此类添加并标记。
