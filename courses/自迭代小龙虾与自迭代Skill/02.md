## 这一篇要解决的问题

上一篇把小龙虾拆成了四层，这一篇落在行动层：任务要说到什么程度，系统才不会靠猜。你会拿到六件套的完整拆解，并发现它和你 ITERATION-HARNESS 里的 Task Packet 是同一张合同的两个厚度。读完交出本篇唯一产物：你的任务卡初稿。

## 正文

### 一句人话，系统替你补了多少空白

很多人第一次给小龙虾安排未来任务，说的是这类话：

> 明天晚上帮我去觅游，看看有没有小龙虾管理记忆好的帖子。

人一听就懂。但这句话交给系统执行，里面至少有六处空白：

1. 明天晚上是几点？不写具体时间，任务可能根本存不进系统。
2. 「记忆管理」具体指什么？是 OpenClaw 记忆组件的用法，还是 Agent 长期记忆的方案？
3. 什么内容算一条值得学习的经验？标准太松，一句空泛感想也会被当成结果交回来。
4. 找不到的时候，要不要告诉你？
5. 阅读的时候能不能顺手点个赞、留个言？
6. 回来只说一句「完成」，还是把来源一起带回来？

关键在最后一点：任务真正执行的时候，你通常不在旁边，没办法中途补一句。所以这些空白必须在开始前写清楚。写清楚的本质，就是少让小龙虾替你猜。

### 六件套逐个拆

欣烨把上面这些空白收成六个问题，前三个管目标、时间和标准，后三个管意外、边界和回执。

**第一问：看什么。** 要写对象和目的。对象是「Meyo 社区的公开内容」，目的是「找一条关于怎么让小龙虾更好地管理记忆的真实经验」。写目的比写对象更重要，因为「为什么看」决定了它怎么筛。

**第二问：什么时候做。** 写具体日期和钟点、时区、执行次数。写「北京时间」是因为系统没有默认时区这种保证。写「只执行一次」是因为这次练习要看到完整过程。时间选未来 24 小时内你自己方便回来看消息的时段，别选你睡觉的点。

**第三问：什么才算有用。** 把标准写具体：内容要包含具体做法、真实案例或者踩坑过程。你自己读完，至少要能说清作者遇到了什么问题、后来做了什么。这条标准可以直接塞进任务里，让小龙虾照它筛。

**第四问：没找到怎么办。** 这次只执行一次，没找到合格内容也要回来说明它查过什么；如果真是零条结果，就直说没找到；访问失败就把页面提示或报错原话带回来。这样你分得清「没找到」和「没去查」。失败不可怕，没消息、或者编一条内容来交差，才让你无法处理。

**第五问：能做什么。** 第一次只读：允许搜索、阅读、筛选、整理。禁止点赞、评论、关注、私信，禁止下载、安装、改配置。判断线只有一条：把信息带回来的可以先做，会改变外部状态的先停下来问你。它要是遇到一条很想回复的帖子，只把建议带回来，由你决定发不发。

**第六问：带回什么。** 成功时带回：学到的一件事 + 来源（作者、标题、链接都可以，标准是以后还能重新找到原内容）+ 一个你愿意尝试的最小下一步。失败时带回：查过什么 + 卡在哪 + 真实原话。

### 六件套和你已有的 Task Packet 是同一张合同




| 六件套 | Task Packet 字段 | 防的空白 |
|---|---|---|
| 看什么 | goal + allowed_inputs | 对象和目的不清，范围太宽 |
| 什么时候做 | 调度时间 + max_attempts | 时间歧义，任务存不进系统 |
| 什么算有用 | success_gate | 标准太松，空泛感想当结果 |
| 没找到怎么办 | stop_conditions | 静默失败，分不清没跑还是没找到 |
| 能做什么 | forbidden_inputs + allowed_writes | 越权改变外部状态 |
| 带回什么 | output_schema | 回执没内容，无法验收 |

对照完你会发现一个差别：你的 Task Packet 里还多了 escalation（出问题找谁）和 run_id（这次运行的编号），六件套里没有。这不说明谁更对。欣烨的六件套是给「一次只读任务」的最小合同，你的 Task Packet 是给多 Agent 工程任务的加厚版。同一张合同，按任务风险选厚度——这正是你 Harness 设计合同里「四种厚度」说的那件事。

### 任务卡初稿

把六问填完，得到一张可以直接交给小龙虾的任务卡。下面这版你只需要改一个地方：【时间】。

> 请创建一条一次性定时任务：
>
> - 时间：【未来 24 小时内某日某时】，北京时间，只执行一次，执行完任务自动结束。
> - 对象：Meyo 社区的公开内容。
> - 目的：找一条关于「怎么让小龙虾更好地管理记忆」的真实经验，内容包含具体做法、真实案例或踩坑过程；读完要能说清作者遇到了什么问题、后来做了什么。
> - 动作边界：只允许搜索、阅读、筛选、整理。禁止点赞、评论、关注、私信，禁止下载、安装、改配置。遇到想回复的帖子，只把建议带回，由我决定。
> - 回执：成功时，带回「学到的内容 + 来源（作者/标题/链接）+ 一个最小下一步」；失败时，带回「查过什么 + 卡在哪 + 报错或页面提示原话」。回执发回本对话。

三个细节值得单独说一下：

1. 「只执行一次」和「执行完自动结束」都写上，是怕它把一次性任务理解成每天重复。
2. 回执发回本对话，你要选一个自己容易看见的入口。这条任务会写进第 03 篇的四步验收里。
3. 这张卡现在是草稿。**今天不创建**。课程的原话是：现在立刻在聊天里查一次，不算完成练习。我们要体验的是人在聊天框外，小龙虾到点自己动手。

### 今日最小动作

1. 把任务卡里的【时间】填成未来 24 小时内你方便回看的时刻。
2. 决定回执入口（建议就是当前对话，或者你天天看的飞书群）。
3. 把 01 篇的体检三问结果和这张填好的任务卡，一起写进本篇末尾的学习反馈。

## 小结

1. 一句人话里藏着六处空白，系统执行时没人能中途补，所以要在开始前写清。
2. 六件套：看什么、什么时候做、什么算有用、没找到怎么办、能做什么、带回什么。
3. 六件套就是你 Task Packet 的自然语言版，差两个字段：escalation 和 run_id；按任务风险选合同厚度。
4. 只读任务的判断线：带信息回来可以先做，改变外部状态先停下问你。
5. 本篇产物：任务卡初稿，今天只填时间、不创建。
