# 04｜三个循环如何跑起来

## 本篇基于的反馈

03 在 Notion 里没有新的学习评论。本篇基于当前可见上下文生成，并按 `00-学习计划.md` 继续推进：把第 3 篇的八层责任图，改成能运转的三个循环。

## 这一篇要解决的问题

第 3 篇解决了“出了问题该看哪一层”。这一篇解决“这些层怎么一起动起来”。先记住三个循环：执行循环、学习循环、价值循环。能把这三个循环讲清楚，八层系统就开始从结构图变成工作流。

## 正文

八层系统最容易被误用成一张目录表：L1 到 L8，每层记一个名词，然后停在那里。

原始材料里更有用的部分，是它把八层压成三个循环。循环的意思是：每次任务跑完，都要留下状态、结果和反馈；下一次任务可以接着这些证据继续跑。

三个循环分别处理三类问题：

1. 执行循环：任务怎样被模型和设备完成。
2. 学习循环：新信息怎样改变系统。
3. 价值循环：内部能力怎样变成外部结果，再带回反馈。

### 1. 执行循环：让任务从入口走到验收

执行循环连接 L3、L1、L2，再回到 L3。

它的基本路径是：

任务进入 L3 任务层，任务卡写清目标、输入、约束、阶段、计划、结果路径、bad case 和验收标准。然后 L1 流量层选择合适模型，L2 设备层选择可用执行节点。执行完成后，结果写回任务卡，由审查者按照验收标准判断。

这条循环解决一个很具体的问题：任务不能靠某个聊天窗口保存进度。

一个可运行的执行循环，至少要有 6 个字段：

| 字段 | 作用 |
|---|---|
| 目标 | 这次任务要交付什么 |
| 输入 | 材料、链接、文件、评论在哪里 |
| 约束 | 哪些格式、边界、禁用规则必须遵守 |
| 执行者 | 哪个模型、哪个 Agent、哪台设备负责 |
| 结果 | 产物写到哪个文件、页面或数据库 |
| 验收 | 用什么证据判断完成 |

你前面给过一个很清楚的真实 loop：Claude Code 负责设计 loop，Codex 负责执行，Claude Code 再做一次 Agent-facing review，人再做一次 human-facing review。这个 loop 属于执行循环的成熟版本。

它的关键点有两个。

第一，任务状态要在任务卡里，而非只在模型对话里。Codex 执行到哪里，写了什么文件，Notion 有没有同步，验收失败在哪里，都要能被下一位执行者看到。

第二，验收要分两层。Agent-facing review 看机器是否按约束执行，例如文件是否存在、状态是否同步、relation 是否连上。human-facing review 看人是否真的能用，例如页面是否好看、03 是否在 Notion 里可见、课程路线是否清楚。

所以执行循环的健康信号很简单：换一个模型、换一个窗口、换一天继续，任务仍然能接上。

执行循环出问题时，常见表现是：

- 执行者说已经完成，但页面里看不到。
- 本地文件有了，Notion 状态没同步。
- Notion 里有页面，首页路线没有入口。
- 评论已经写了，下一篇没有读评论。
- 结果存在，但验收标准说不清。

遇到这些情况，优先修 L3 任务层。任务层修好以后，再看模型、设备和工具。

### 2. 学习循环：让材料改变系统

学习循环连接 L4、L5、L6、L7。

它的基本路径是：

材料从 L4 数据入口进入，先记录来源、时间、质量和边界。然后进入 L5 学习层，判断这份材料改变系统的哪一处。改变成立后，L6 维护层登记版本、路径和状态。反复有效的步骤，再进入 L7 工具沉淀层。

这条循环解决另一个具体问题：资料被保存了，系统行为却没有变化。

学习循环要问 4 个问题：

1. 这份材料来自哪里，可靠吗？
2. 它改变了哪条判断、规则、流程或工具？
3. 这个改变有没有在真实任务里试过？
4. 试过以后，应该进入长期库、观察区，还是丢弃？

拿这门课本身举例。

原始 docx 属于 L4 数据入口。我们先把它拆成“窗口失效、八层责任图、三个循环、最小闭环”几个学习单元，再写成课程正文。这个拆解属于 L5 学习层。

每一篇文章写入 `/Users/housibo/Documents/dbskill-learning/把 AI 从窗口变成系统/`，学习计划和 INDEX 同步更新，这属于 L6 维护层。

如果后面我们把“交互式学习写作 + Notion 同步 + 评论读取 + 状态验证”沉淀成稳定脚本或 SOP，它才进入 L7 工具层。

学习循环的健康信号是：新材料进入以后，系统的下一次动作发生了变化。

例如第 2 篇的评论里，你说要接入 `gate / input / 约束 / phase & plan / 结果 / bad case / 验收标准`。这条评论进入系统后，第 2 篇被重写成任务卡，第 3 篇开始把任务卡放回八层责任图。这就是学习循环在工作。

学习循环出问题时，常见表现是：

- 摘要越来越多，流程没有改变。
- 评论读了，但下一篇没吸收。
- 失败案例出现多次，却没有进入 bad case。
- 工具越来越多，使用入口越来越乱。
- 旧规则已经失效，学习计划仍然显示旧状态。

遇到这些情况，优先修 L5 学习层和 L6 维护层。先问“这条反馈改变了什么”，再决定要不要写工具。

### 3. 价值循环：让内部能力接受现实检验

价值循环连接 L7、L8，再回到 L4、L5 和 L3。

它的基本路径是：

工具、规则、判断和流程在 L7 被组合起来，形成 L8 的外部产物：报告、课程、网页、数据库、服务、交付物、决策建议。用户使用之后产生反馈。反馈重新进入 L4 数据入口，经 L5 判断后，修改任务、规则、工具和下一轮交付。

这条循环解决第三个具体问题：内部系统很复杂，外部用户仍然感知不到价值。

L8 要问的问题很朴素：

1. 这个产物给谁用？
2. 它帮对方完成什么判断或行动？
3. 对方怎么判断它有用？
4. 哪些反馈会改变下一轮系统？

在你的 Notion 课程工作台里，L8 的表现很直接：你打开页面后，能不能立刻看到当前学到哪里、下一篇是什么、评论有没有被处理、不同单元怎么分开、03 是否能直接进入。

所以你说“03 没有在 Notion 看到，Notion 的状态没有同步”，这条反馈指向价值循环：内部已经写了文件，但外部工作台没有让使用者感知到完成。

这条反馈回流以后，系统应该修改两个地方：

第一，执行循环要增加 Notion 可见性验收。写完本地文件后，必须确认数据库中能搜到、首页有入口、单元页当前进度正确。

第二，维护层要记录“页面显示”和“数据存在”是两个检查项。数据库里有 03，只证明数据存在；首页和单元页有稳定链接，才证明你能看到。

价值循环的健康信号是：用户反馈能改变下一次执行标准。

价值循环出问题时，常见表现是：

- 交付物存在，但使用者找不到。
- 页面结构完整，但阅读路径不清楚。
- 自动化流程很长，但最终产物没人用。
- 数据库 relation 很复杂，首页没有给人一个明确入口。
- 用户反馈只停留在评论区，没有进入下一轮任务卡。

遇到这些情况，优先看 L8。先把外部结果和反馈讲清楚，再决定 L1 到 L7 要怎么调整。

### 4. 三个循环怎么接在一张任务卡上

一张成熟任务卡，可以同时承载三个循环。

| 任务卡字段 | 对应循环 | 要回答的问题 |
|---|---|---|
| 目标 / 输入 / 约束 | 执行循环 | 这次要做什么，材料在哪里，边界是什么 |
| phase & plan | 执行循环 | 分几步做，当前做到哪一步 |
| 结果路径 | 执行循环 | 产物写在哪里，谁能接手 |
| bad case | 学习循环 | 这次失败暴露了什么系统问题 |
| 规则改动 | 学习循环 | 下次要改哪条判断或流程 |
| 工具沉淀 | 学习循环 | 哪个动作值得复用 |
| 用户反馈 | 价值循环 | 外部是否认可，哪里要改 |
| 下一轮动作 | 三个循环共同作用 | 任务继续跑、规则更新，还是重新定义价值 |

这样看，你前面提的字段并非文档装饰。它们对应三个循环的状态接口。

`gate` 决定任务能否进入执行循环。`input` 决定数据入口是否清楚。`约束` 决定执行者能否稳定行动。`phase & plan` 决定任务能否被接手。`结果` 决定输出是否可验收。`bad case` 决定学习循环有没有材料。`验收标准` 决定价值循环有没有边界。

### 5. 一个最小运行方式

先从一个真实任务跑，不要从完整系统开始。

比如“生成下一篇交互式学习文章”，最小运行方式是：

1. L8：明确产物给谁用。这里是给你继续学习和评论。
2. L4：读取来源。包括原始 docx、上一页 Notion 评论、本地学习计划。
3. L5：判断反馈改变什么。没有评论时，小步推进计划中的下一篇。
4. L3：形成任务卡。目标是写 04，约束是使用 `dbs-learning` 结构并同步 Notion。
5. L1 / L2：选择当前 Codex 环境执行，使用本地文件和 Notion 连接器。
6. L6：写入 `04.md`，更新学习计划和 INDEX。
7. L8：同步 Notion，确认首页、单元页和课次页都能看到 04。
8. 下一轮：等待你在 04 里评论，再决定 05。

这就是三个循环同时运转：执行循环把文章写出来，学习循环把反馈变成规则，价值循环用你的可见性和评论判断系统是否有效。

## 小结

- 执行循环负责让任务从任务卡进入模型和设备，再把结果写回状态。
- 学习循环负责让新材料和反馈改变规则、流程、维护记录或工具。
- 价值循环负责让内部能力进入外部产物，并让用户反馈回到系统。
- 一张成熟任务卡要同时承载目标、输入、约束、结果、bad case、验收和下一轮动作。
- 判断一个 AI 系统是否在运行，可以看任务是否能接手、反馈是否改变系统、结果是否被真实使用。
