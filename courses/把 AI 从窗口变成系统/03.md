# 03｜八层系统的责任图

## 这一篇要解决的问题

本篇基于 Notion 评论生成。你在第 2 篇评论里说：“OK，那回到我一开始给你的那个材料里去。”所以这一篇回到《V6 认知蒸馏 Demo》的主材料，讲清八层系统的稳定版本：每一层负责什么，任务失败时怎样定位责任。

## 正文

第 2 篇把你的 Claude Code、Codex、人工验收 loop 写成了一张任务卡。那张卡解决的是 L3 任务层的问题：任务要能脱离聊天窗口，被不同执行者接手。

现在回到原材料。作者讲的八层系统，核心价值在于提供一张责任图，帮助人定位任务失败的位置。

当一个 AI 任务失败时，先问失败落在哪一层。定位清楚以后，再决定修模型、修设备、修任务、修数据、修学习、修维护、修工具，还是修业务结果。

### 1. L1 流量层：模型能力从哪里来

流量层负责模型供应。

这里的“流量”指可调用的模型能力：官方订阅、API、中转服务、本地模型、低成本模型、高能力模型。

这一层要回答 5 个问题：

1. 这个任务该用哪个模型。
2. 模型是否稳定。
3. 成本是否合适。
4. 额度是否够用。
5. 调用失败后切到哪里。

原材料里最稳定的判断是：模型要当资源调度。不同模型像不同工具，有的适合低成本清洗，有的适合关键判断，有的适合快速草稿，有的适合代码审查。

流量层出问题时，常见表现是：

- 低能力模型承担了高风险判断。
- 强模型被用来做低价值机械任务，成本过高。
- API 额度耗尽后任务停摆。
- 模型切换后质量忽高忽低。
- 每次靠人临时决定用哪个模型。

这一层的稳定产物是模型能力卡、任务路由表、成本记录、额度监控、降级策略和失败切换记录。

### 2. L2 设备层：执行节点是否可用

设备层负责机器、环境和执行节点。

作者讲多台 Mini、多屏幕和多设备矩阵，最可迁移的重点是系统能否知道每台设备的状态。

这一层要回答 5 个问题：

1. 哪些设备在线。
2. 每台设备能跑什么。
3. 环境依赖是否完整。
4. 当前负载是否适合接任务。
5. 掉线后怎样恢复。

设备层出问题时，常见表现是：

- 脚本只能在某一台机器上跑。
- 换电脑后路径、依赖、权限全部失效。
- 电脑重启后后台任务无人接手。
- 多台机器存在，但任务仍集中在一个窗口里。
- 设备离线后，没有健康检查和恢复动作。

这一层的稳定产物是设备清单、环境说明、健康检查、启动脚本、最后心跳和恢复策略。

### 3. L3 任务层：任务能否脱离窗口生存

任务层负责目标、输入、限制、状态、责任、结果和验收。

你上一篇提到的 gate、input、约束、phase & plan、结果、bad case、验收标准，基本都属于任务层。

这一层要回答 7 个问题：

1. 任务目标是什么。
2. 输入材料在哪里。
3. 哪些约束必须遵守。
4. 当前做到哪一步。
5. 谁负责执行。
6. 结果写到哪里。
7. 什么证据说明完成。

任务层出问题时，常见表现是：

- 任务只能靠某个聊天窗口继续。
- 新模型接手后要重新解释背景。
- 多个 Agent 同时做事，互相覆盖结果。
- 执行者说完成了，但没有证据。
- 人工复查时不知道当时的目标和限制。

这一层的稳定产物是任务 ID、任务卡、状态机、输入指纹、责任 Agent、结果路径、错误日志、重试次数和验收记录。

### 4. L4 数据入口层：材料进入前是否经过审查

数据入口层负责外部材料进入系统的第一道门。

原材料里提到公众号、社群、GitHub、YouTube、小红书、B 站、X、本地微信等入口。不同平台的数据分布不同，噪声不同，风险也不同。

这一层要回答 6 个问题：

1. 材料来自哪里。
2. 是否有原始来源。
3. 是否重复。
4. 是否有转写错误。
5. 哪些是事实，哪些是推论。
6. 是否存在版权、隐私、平台规则风险。

数据入口层出问题时，常见表现是：

- 把口语转写里的错误模型名当成事实。
- 把作者临场表达当成稳定规则。
- 只追求采集数量，缺少筛选。
- 不记录来源和时间。
- 外部材料直接进入长期知识库。

这一层的稳定产物是来源记录、材料指纹、去重结果、暂存区、质量标签、待核验列表和使用边界说明。

### 5. L5 学习层：新信息是否改变系统

学习层负责把材料转成系统变化。

原材料里有一个重要判断：保存摘要不等于学会。学习完成的标准是系统行为发生变化。

这一层要回答 5 个问题：

1. 这份材料改变了哪条规则。
2. 是否修正了某个边界。
3. 是否产生了新工具。
4. 是否暴露了旧流程的失败模式。
5. 是否进入真实任务验证。

学习层出问题时，常见表现是：

- 每天读很多资料，系统流程没有变化。
- 文件夹里有大量摘要，后续任务从不调用。
- 新概念没有边界、反例和验证状态。
- 复盘只停留在感受，没有升级成规则。
- 同一个错误反复发生。

这一层的稳定产物是规则变更、概念定义、边界修正、反例、验证结果和真实任务反馈。

### 6. L6 维护层：增长是否保持可控

维护层负责系统长期健康。

当模型、设备、任务、数据和学习都在增长，系统会产生大量文件、缓存、日志、草稿、中间产物、旧版本和工具记录。只写入，不退出，系统会变脏。

这一层要回答 6 个问题：

1. 文件放在哪里。
2. 哪些内容长期保存。
3. 哪些内容归档。
4. 哪些内容清理。
5. 版本如何回退。
6. 知识库是否重复或过期。

维护层出问题时，常见表现是：

- 项目目录里堆满草稿和临时脚本。
- 旧版本和新版本混在一起。
- 工具改坏后没有回滚路径。
- 中间产物长期占空间。
- 记忆文件越来越重，反而干扰执行。

这一层的稳定产物是目录规范、版本记录、备份、归档策略、清理候选、健康检查和上下文压缩规则。

### 7. L7 工具沉淀层：成功过程能否复用

工具沉淀层负责把有效动作变成可复用能力。

脚本、提示词、模板、SOP、转录流程、手册加工流程、多模态处理组件，都可能进入这一层。进入这一层前，要先经过真实任务验证。

这一层要回答 7 个问题：

1. 这个工具解决什么问题。
2. 输入是什么。
3. 输出是什么。
4. 依赖哪些环境。
5. 适用边界在哪里。
6. 如何验证成功。
7. 失败后怎样回退。

工具沉淀层出问题时，常见表现是：

- 脚本存在，但没人知道怎么用。
- prompt 有效过一次，后来无法复现。
- 工具没有输入输出说明。
- 工具越多，检索成本越高。
- 单个任务加载太多工具，反而变慢。

这一层的稳定产物是工具说明、SOP、模板、脚本、测试样例、失败处理和维护责任。

### 8. L8 业务产出与反馈层：现实是否承认结果

L8 负责系统和现实世界的接触面。

用户看不到你有多少模型、多少设备、多少脚本、多少 Agent。用户能感知的是报告、产品、课程、服务、交付物、节省的时间、减少的错误和更好的决策。

这一层要回答 5 个问题：

1. 产物给谁用。
2. 解决什么真实问题。
3. 用户怎样判断它有用。
4. 是否被使用、采纳、付费或复购。
5. 外部反馈是否回流到系统。

L8 出问题时，常见表现是：

- 内部工具很多，客户仍然不买单。
- 产出很多，读者没有行动。
- 报告写得完整，但不能帮助决策。
- 用户反馈只留在评论区，没有进入下一轮任务。
- 系统越来越复杂，现实价值没有增长。

这一层的稳定产物是产品、报告、手册、课程、服务、客户反馈、使用数据、收入记录、复盘结论和下一轮改动。

### 9. 八层怎么用：从失败现象定位责任

八层系统最实用的用法，是把失败现象放进去定位责任。

例子 1：Agent 做了一半，窗口关了，没人知道下一步。

- 优先看 L3 任务层。
- 检查任务卡、当前 phase、结果路径和下一步。
- 如果电脑重启导致任务中断，再补看 L2 设备层。

例子 2：你有多个模型，但任务越来越慢。

- 先看 L1 流量层：模型路由是否混乱。
- 再看 L7 工具层：工具选择成本是否过高。
- 最后看 L3 任务层：任务是否拆得太碎。

例子 3：读了很多材料，系统没有变强。

- 优先看 L5 学习层。
- 再看 L4 数据入口层：材料是否经过筛选。
- 最后看 L6 维护层：沉淀内容是否重复和过期。

例子 4：脚本很多，用户仍然不认可。

- 优先看 L8 业务产出与反馈层。
- 再看 L7 工具层：工具是否真的服务交付。
- 最后回到 L3：任务验收标准是否只看内部完成。

### 10. 本篇先记住一张分组图

八层可以先分成 4 组：

1. 执行底座：L1 流量、L2 设备、L3 任务。
2. 认知输入：L4 数据入口、L5 学习。
3. 长期生存：L6 维护、L7 工具沉淀。
4. 现实检验：L8 业务产出与反馈。

这张图要和第 2 篇的 Task Card 连起来看。

Task Card 主要解决 L3，但它会牵动其他层：input 会接到 L4，bad case 会接到 L5，result 会接到 L6，工具说明会接到 L7，人工验收会接到 L8。

所以八层系统是在任务卡基础上继续追问：这个任务的模型、设备、数据、学习、维护、工具和现实反馈是否都站稳了。

## 小结

- 八层系统是一张责任图，用来定位 AI 任务失败的位置。
- L1 到 L3 负责执行底座：模型、设备和任务状态。
- L4 到 L5 负责认知输入：材料入口和系统学习。
- L6 到 L7 负责长期生存：维护增长和沉淀工具。
- L8 负责现实检验：产出、用户反馈和业务结果。
