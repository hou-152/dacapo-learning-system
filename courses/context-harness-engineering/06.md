## 正文

### 先说一处概念错位：影响最大的一个

你的大费曼开头写的是：

> 上下文工程主要由以下几个维度构成：LLM、Harness、驾驶者、草原

这里有个错位。**LLM 不是 context engineering 的组成部分。**

01 建立的四元结构，说的是「一个 agent 系统由哪四个元素构成」：

```text
agent 系统 = 野马（模型）+ 马具（harness）+ 骑手（人）+ 草原（context）
```

Context engineering 是这四个里的**一个**——你对草原做的工作。模型是另一个独立元素，你不对它做工程，你只是选它、然后喂它。

为什么这处错位值得单独拎出来：它会连带影响你后面所有的归因。如果「模型」被算进 context engineering，那模型不给力的时候，你会去改 context；context 有问题的时候，你也会怀疑模型。四个元素混在一起，出问题就没法定位。

这门课后面三篇（03 的 harness 三变量、04 的三分法、05 的 window 管理）能分开讲，前提就是这四个元素是分开的。

修正后的一句话：

> Agent 系统由四个元素构成：模型、harness、骑手、context。其中 context 这一元素上的工程工作，叫 context engineering。

### 小费曼：analogy 对了，方向错了

你写的：

> 每个 token 的注意力并不是平均分配的，而是越到后面越少。类比我们的大脑：读一篇东西，读到越往后，常常会把前面给忘了。

**对的部分**：工作记忆这个类比，和官方用的类比完全一致——Anthropic 那篇就是拿人的工作记忆上限来解释注意力预算的。你自己想到的那句「讲着讲着目标就偏移了」，描述的是真实现象。

**错的部分**：「越到后面越少」这个方向。

05 里那条 lost in the middle 说的是另一回事：**开头和结尾的召回最好，中间最差。** 是一条 U 形曲线，不是单调下降。原论文的说法是 performance 在信息位于 context 开头或结尾时最高，在模型必须访问中间信息时显著下降，并且把这个现象类比成人的首因效应和近因效应。

这个方向错了会直接改变你的做法。按「越到后面越少」，你会把关键约束往前堆；按 U 形，你要做的是**别把关键约束埋在中间**——前面和末尾都是好位置，一次长会话里，最后几轮反而是高召回区。

**还有一处该拆开**：你把两个机制合成了一个。

| 机制 | 说的是什么 | 和位置有关吗 |
|---|---|---|
| 注意力预算 | 总量有限，每个新 token 都消耗一点 | 无关，是总量问题 |
| lost in the middle | 同样长度下，中间位置的召回更差 | 有关，是分布问题 |

一个是「装了多少」，一个是「装在哪」。两个都成立，但对应的动作不同：前者让你少装，后者让你注意摆放位置。

### 中费曼：这题你答的方向需要转一下

你写的：

> 1. compression：应该就是我们的上下文，也就是我们的 harness
> 2. 笔记：就是我们的 context
> 3. sub-agent：就是野马

先说那个最该指出来的地方：第 1 条里「上下文，也就是我们的 harness」——context 和 harness 被当成同一个东西了。这两个的区分是 01 整篇在建立的，也是上面那处概念错位的同一个根。

再说这题本身。我出这题的问法有歧义，你按「把三个手段分别归类到三个元素里」来答，是被问法带偏的。这题真正想问的是**谁在动、动了什么**。

答案是：**三个手段都是马具在动。** compaction、笔记、sub-agent 全部由 harness 实现——Claude Code 的 `/compact`、写文件的能力、spawn subagent 的能力，都是 harness 提供的。它们的区别在于动了草原的哪一部分：

| 手段 | 马具做的事 | 对草原做了什么 |
|---|---|---|
| compaction | 把窗口里的内容压成摘要，重开窗口 | 只动**装进窗口的那一份**，草原本体没变 |
| 结构化笔记 | 把中间结论写到窗口外的文件 | **往草原里写**——这次任务的产出变成了长期资产 |
| sub-agent | 派一匹新马，带干净窗口去干一段活，回来交摘要 | 借另一匹野马的窗口，读草原的一个角落 |

第二行是最值得记的：**笔记是唯一一个往草原写的手段。** compaction 和 sub-agent 都只是在管「这次装什么」，做完就没了。笔记做完，草原变大了一点。

这也和 02 第三层那句「skill 是长出来的」接上了——一次任务里写的笔记，反复出现三次之后，就是下一个 skill 的雏形。

你第 3 条说 sub-agent 是野马，这个方向抓到了一半：确实多了一匹马。补上另一半——它还自带一个干净窗口，这才是它能省 context 的原因。它烧掉几万 token 探索，回来只交 1000–2000 token 的摘要，主线窗口只付摘要那部分的钱。

### 大费曼：几处点名修正

先说结论：**结构是对的，四个元素都在，趋势判断也对。** 下面是逐条修正。

**一、「Harness 就是我们的 Agent Cloud 平台」**

这句要改。Claude Code 和 Codex 都跑在你自己的电脑上，不是云端平台。

而且这处不只是用词——03 讲 harness 三变量的时候，第一个变量就是「它能访问什么」，本地和云端的差别正是那里最大的一条。把 harness 说成云平台，等于把这个区分抹掉了。

改成：harness 是模型之外的一整套装备（agent loop、工具、记忆、沙箱……），可以跑在本地，也可以跑在云端，这两种的效果差别很大。

**二、「已经有 OpenAI、Stability AI 这些铺垫在前面」**

Stability AI 是做图像生成的（Stable Diffusion），不做 agent harness。

这里该点的两家是 **Anthropic**（Claude Agent SDK → Claude Code）和 **OpenAI**（Agents SDK → Codex）。

**三、「2W1H（What, Why, How）」**

02 和 04 里给的框架是四段：**why / what / how / how good**。

你这里丢掉的是 how good ——验收标准。这一段在 agent 场景下的分量比另外三段更重，因为它决定 agent 什么时候停、以什么标准自查。少了它，agent 会自己猜一个标准，而它猜的标准通常比你的松。

04 里说「一个 issue 就是一次任务的 context 包」，包里最不能缺的就是这一段。

**四、「Harness 的系统文件在变少，包括我们的 Agent 数量也在变少」**

前半句对。后半句是把两件事混了：03 里那组数字（18 个 agent 定义从 8798 行到 664 行）说的是 agent **定义文件的行数**变少，agent 的**个数**没变，还是 18 个。

「定义变薄」和「数量变少」是两个不同的主张，而且方向可能相反——正因为单个定义变薄了，你反而更容易多养几个 agent。

**五、「猎马」**

是野马。这个词在我们这门课里是个固定术语，写错了以后回看会绕。

### 一个诊断：你的大费曼里最薄的一段

数一下你大费曼四段的篇幅：

| 段落 | 你写的量 |
|---|---|
| LLM | 一整段，有趋势判断，有具体做法 |
| Harness | 一整段，举了工具，讲了趋势 |
| 驾驶者 | 一整段，有自己的观察 |
| 草原 | 三行 |

草原那段是这样的：

> 什么是个人草原？就是你所拥有的个人上下文、你对业务的理解，以及你的各种灵感。

这段话对，但它是一句定义，不是一段解释。而 01 那篇的核心主张恰好是：草原是四个元素里唯一不可替代的一个。

这个反差本身是信息：**在你已经能讲清楚的部分里，主张价值最高的那一块，讲得最薄。**

这不奇怪。模型和 harness 是公开的，读几篇文章就能讲；草原是你自己的，讲它必须调用你自己的具体材料——几百个信息源、九个 skill、一万多条素材、你对信息质量的分级标准。那些东西在你脑子里，没有在这段费曼里被调出来。

下一次做大费曼的时候，可以只讲草原这一段，用你的内参系统当例子，把「你对业务的理解」拆成三条具体的判断规则。那一段写出来，会比前面三段加起来更有价值——因为前三段别人也能写，那一段只有你能写。

## 小结

1. LLM 不属于 context engineering。四个元素分开，出问题才能定位。
2. 注意力预算（总量）和 lost in the middle（位置）是两个机制。位置那条是 U 形，中间最差，别把关键约束埋在中间。
3. compaction、笔记、sub-agent 三个手段都由 harness 实现，区别在对草原做了什么。笔记是唯一往草原写的那个。
4. harness 可以本地也可以云端，这个区分是 03 三变量里最大的一条。
5. 框架是四段：why / what / how / how good。how good 在 agent 场景下分量最重，它决定 agent 什么时候停。
6. 「agent 定义变薄」和「agent 数量变少」是两个不同主张。
7. 「骑手要持续纠偏」是你自己补的一条，和 05 的 window 管理咬合，值得留下。
8. 你讲得最薄的一段（草原）恰好是主张价值最高的一段。下次的大费曼可以只讲它。
