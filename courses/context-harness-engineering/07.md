### 那 23 行几乎全部通过单行测试

| 原文 | 少了它强模型会更差吗 | 判定 |

## 问题一：一个围栏 bug，让约 100 行指令变成了代码块

这是优先级最高的一条，因为它是 bug 而非风格问题。

`~/CLAUDE.md` 全文只有**一个**代码围栏，在第 132 行：

```text
第 132 行：  ```text
第 233 行：  （文件结束，围栏始终没有闭合）
```

后果是，从第 132 行到文件末尾——约 100 行——全部落在一个未闭合的 `text` 代码块里面。里面装着：

- 飞书桥（日报章节顺序、高光检测规则、本地命令、可用 skill）
- 通用工作规范（语言排版、对话方式、格式转换、写作规则、文件组织、安全删除、隐私脱敏）
- **整章安全策略**（权限控制、防套路、提示词注入防护、供应链投毒防护、凭证管理、破坏性操作）

**为什么这件事重要。** 围栏里的内容，模型倾向于当作「被展示的文本」处理，而不是「对我下的指令」。这是围栏这个语法本来的用途——你贴一段代码给它看，它不会去执行那段代码里的话。

也就是说，你整章安全策略现在的处境，接近于「一段被引用的示例文本」，而不是「一条常驻规则」。这条修掉之后，后面那 100 行才真正在起作用。

**改法**：在第 136 行附近（关系协议总判断那段格式说明结束处）补一个闭合围栏。

这份文件影响你所有项目，我没有直接改。你说一声我来动。

## 问题二：密钥规则，两份文件互相矛盾

这是 03 里 overconstraining 的活体标本。

两条原文：

```text
~/.codex/AGENTS.md
密钥仅存私密、未提交文件，不读／回显

~/CLAUDE.md 第 227 行
输出脱敏：API Key 只显示前 4 位 + ****
```

一条说不回显，一条说回显前 4 位。同一次请求里两条都在，模型要自己仲裁——而你无法预测它会挑哪条。这就是 03 说的「一条冗余指令的代价不是零，它是一个冲突」。

**建议保留严的那条**（AGENTS.md 的不回显），删掉 CLAUDE.md 第 227 行。理由是失效模式不对称：不回显最坏是你要多跑一条命令自己确认；回显前 4 位最坏是密钥前缀进了某个日志或截图。

如果「确认配的是哪个 key」这件事确实高频，另一个做法是把例外写进 AGENTS.md 那一条里——你明确要求确认时才显示前 4 位。这样规则仍然只有一处。

**这条我也没动。** 涉及安全边界的规则，改动应该由你决定，不该由我在诊断过程里顺手放宽。

## 问题三：常驻文件里有三成是一个该搬没搬的 skill

`~/CLAUDE.md` 第 54–136 行，共 83 行，是一整套微信关系语料库的加工规范：核心原则四条、禁用句式、固定输出格式。

> 更正：这里原写「68–136 行，约 69 行」。复查行号时发现起点是第 54 行——那一行是 `- 强制加工框架：微信摘要 → 关系语料库对象`，作为一个列表项挂在「进度更新模式」标题下面。按 68 行切会漏掉 14 行，而且会留下一个挂错父标题的残段。

同一套东西已经作为独立文件存在：

```text
~/.reasonix/skills/wechat-relationship-corpus.md    存在
```

所以它在两个地方各有一份：一份按需加载，一份跟着每次请求跑。

拿 04 的三分法过一遍：

| 维度 | 判断 |
|---|---|
| 强模型推不出来吗 | 推不出来——这是你自己的方法论 |
| 每次都要用吗 | 不是——只在处理微信私聊时用 |
| 应该落在哪格 | **搬**（推不出来 × 偶尔用） |
| 现在落在哪格 | **留** |

这就是 04 说的「多数人的 AGENTS.md 臃肿，问题出在右上格」的实物：内容本身有价值，位置放错了。

**改法**：删掉这 83 行，在 skill 索引区留一行指针。

```markdown
| 微信关系语料库 | `~/.reasonix/skills/wechat-relationship-corpus.md` |
```

注意这是「搬」不是「删」——原文已经在 skill 文件里，所以这次搬走没有丢东西的风险。这一点和 04 里那条警告（删掉一条真实的坑，以后再踩一遍）的区别就在于：搬之前先确认目的地已经有了。

顺带一个附带收益：这 83 行删掉之后，那个未闭合围栏的问题也一起消失了——第 132 行那个围栏正是这段的最后一部分。

## 问题四：三处跨文件重复

除了密钥那条冲突，还有三个话题在两份文件里各写了一遍：

| 话题 | AGENTS.md | `~/CLAUDE.md` | 状态 |
|---|---|---|---|
| 中文排版规则 | 全局约定第 1 条 | 第 165–167 行 | 内容一致，重复 |
| 删除移至 `.trash/`、留存 30 天 | 内容第 3 条 | 第 194–196 行 | 内容一致，重复 |
| 密钥处理 | 内容第 3 条 | 第 227 行 | **内容冲突** |

前两条现在还一致，所以暂时无害。风险在于以后：你改了一处，另一处留在旧版本，就变成第三条那样的冲突。04 里说这是 Single Source of Truth 冲突最常见的来路——同一话题在多处写过，三处都不算错，但迟早有一处过期。

**改法**：全局适用的规则留在 AGENTS.md，`~/CLAUDE.md` 里删掉这些行。判据很简单——这条规则跟「AI 内参这个项目」有关吗？无关的就是全局规则。

## 问题五：三个 skill 目录，21 个重名

三个都是真实目录，不是软链：

| 目录 | 数量 | 有 git 吗 |
|---|---|---|
| `~/.claude/skills` | 23 | 无 |
| `~/.agents/skills` | 100 | **有** |
| `~/.reasonix/skills` | 259 个 `.md`（目录项 309） | 未查 |

`~/.claude/skills` 的 23 项里，**21 项和 `~/.agents/skills` 重名**——包括 `dbs-learning`（也就是现在正在跑的这个）、`neican` 系列、`lobster-daily` 系列。

也就是说，同一个 skill 有两份拷贝，各自可以独立被改。这正是 04 讲的漂移场景，只是发生在 skill 层：现在两边可能一致，改过一次之后就不一定了。

02 建议的做法是把自己维护的 skills 收到一个目录，让 Claude Code 和 Codex 都指向它。**你已经做了一半**——`~/.agents` 有 `.git`，有 `.skill-lock.json`，说明真源意图是它。缺的是最后一步：`~/.claude/skills` 里那 21 个重名项应该指过去，而不是各存一份。

另外 `~/.agents` 下还有两个备份目录：

```text
skills-backup-20260727-232821
skills.backup-20260531-175050
```

备份本身合理，但它们在 skills 的同级目录里。如果哪天有工具递归扫这个目录，备份里的旧版 skill 会被一起扫进来。

## 一个观察

这份配置的病症，和 03 里官方那篇描述的一模一样：

| 官方那篇的诊断 | 你这份配置里的对应物 |
|---|---|
| 一次请求里几条指令互相冲突 | 密钥规则两份文件矛盾 |
| 把 context 文件当成 central repository | 83 行 skill 内容塞进常驻文件 |
| 跨层重复 | 三处话题在两份文件里各写一遍 |
| 该搬的没搬 | 同上那 83 行 |

Anthropic 有 coding evals 兜着，所以他们能量化地发现这些问题。你这边没有 evals——所以这些问题会一直在，而且因为它们一直在，你会注意不到。03 里那句「每一次请求上的一笔小额税，收好几个月」，说的就是这个。

好消息是，这份配置的底子不错：全局那 23 行密度很高，`~/.agents` 已经有版本控制。问题集中在一个文件和几个目录里，都是位置问题，不是内容问题。

## 小结

1. 全局双文件约定做得对，那 23 行几乎全部通过单行测试，可以当范例。
2. `~/CLAUDE.md` 第 132 行有个未闭合的代码围栏，让约 100 行指令（含整章安全策略）落在代码块里。这是 bug，优先级最高。
3. 密钥规则在两份文件里冲突——一条说不回显，一条说显前 4 位。建议保留严的那条。
4. 常驻文件里约三成半（83 行）是一个已有独立 skill 文件的内容，该搬没搬。
5. 三处话题跨文件重复，现在还一致，以后会变成冲突。
6. 三个 skill 目录，`.claude/skills` 有 21 项和 `.agents/skills` 重名。真源意图已经是 `.agents`，缺最后一步。
7. `.reasonix/skills` 有 12 个 check 族变体和若干 40–50 字节探针残留。清理前需要逐项确认，按你自己的规则走 `.trash`。
