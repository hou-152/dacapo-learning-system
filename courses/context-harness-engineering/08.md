## 修复三：密钥规则冲突

**两条原文**：

`~/.codex/AGENTS.md`（全局约定 > 内容）：

```text

```

`~/CLAUDE.md` 227 行（凭证管理）：

```text

```

一条禁止回显，一条规定回显几位。同一次请求里两条都在。

**这条我不替你选**，因为它是安全策略的取舍，不是笔误。两个方向：

**方向 A：保留严的，删掉宽的**（推荐）

```diff
 225| ## 凭证管理
 226| - 绝不明文存储 API Key / Token / 密码
-227| - 输出脱敏：API Key 只显示前 4 位 + `****`
 228| - API 密钥、Token、Webhook 地址等敏感信息集中存放在单独权威配置文件，不在 CLAUDE.md 出现
```

删掉 227 行，AGENTS.md 的「不读／回显」成为唯一规则。代价：你没法让 agent 帮你确认「配的是哪一个 key」。

**方向 B：给严的那条开一个明确例外**

改 `~/.codex/AGENTS.md` 那行，把例外写进真源：

```text
密钥仅存私密、未提交文件，不读／回显；仅在用户明确要求确认某个 key 时，可回显前 4 位
```

同时删掉 `~/CLAUDE.md` 227 行（规则归到真源，项目文件不重复）。

两个方向都比现状好，因为现状是两条规则打架，模型仲裁到哪边不可预测。
