# 03｜判断操练 + 议程设置：先能判断，再讲 IP 与议程

## 这一篇要解决的问题

你 02 反馈写的是「我无法判断」——两问没有例题时就是空话。这一篇先补例题：拿你候选池里的真实候选，示范「多少人被卡住 × 能不能讲穿」怎么打，再给你一道更小的判断题。然后按计划进入议程设置 vs IP 定位：IP 是结果不是起点，议程是观众判断，话题分类是低级分类、判断分类是高级分类。

## 正文

### 先接「我无法判断」：两问的示范

02 让你从 149 条候选里挑一条、用两问打分，你说无法判断。正常，问题在我：两问没有例题。这篇先看我怎么打。

从你的候选池拿两条真实候选：

**候选 A（熵增｜02）：** 「一个信息系统的质量，取决于它把输入压缩成行动判断的能力。」

- 第一问「多少人会一秒被这个问题卡住」：切口在「信息系统」上——多数人第一秒没有感觉。打分：少。
- 第二问「你的框架能不能讲穿」：能，你学过熵增。
- 结论：内容可用，切口窄，需要抽象上升——把「信息系统」升到「人怎么处理每天的信息」，或者像博主那样找一个具体疑问开头。

**候选 B（如实所现｜02）：** 「叙事是带有情绪的切片，短时间内让你感觉很好，长时间看会让你失去行动力。」

- 第一问：刷短视频爽但没行动，很多人有体感。打分：中到大。
- 第二问：能讲穿，如实所现课题就是你的材料。
- 结论：B 比 A 更适合先讲——切口更大，深度也在。

看出两问怎么用了吗：第一问管「有没有人听」，第二问管「你讲不讲得穿」。两个都过就是好题；只过一个，就修另一个（A 修切口，B 不用修）。

**今天给你的判断题（只答第一问）：** 候选池里「把自己当产品卖出去」系列，切口是「多少人会一秒被卡住」——多 / 中 / 少，三选一。不会就写「不会」，不丢人，它告诉我们下一篇怎么放慢。

### IP 定位是结果，不是起点

博主把这件事讲死了。他不可能在做账号第一天就知道自己会持续用维特根斯坦解决问题——是在解决问题的过程里，发现这个方法老是管用，于是狂发 100 条。发了一年，大家才把「维特根斯坦」和他挂上钩。

那个商 K 老板的视频就是证据：群里有人调侃「商 K 老板还看你的视频」，是因为「语言的边界就是思维的边界」是维特根斯坦说的，而维特根斯坦在他的内容里高频出现。哲学博主讲维特根斯坦，是为出现而出现；他讲，是不得不出现——他在用它解决观众的商业问题。区别就在这：**管用才反复用，反复用才绑定，绑定是结果。**

所以他建议的起点不是做 IP 定位，是帮人解决问题，然后看哪个词、哪套方法反复管用。

### 议程设置 = 你想让观众对你形成什么判断

他举了两个管理账号。一个讲「员工老迟到怎么办、不听话怎么办」——观众得到的判断是：管理就是解决员工问题。另一个讲「公司怎么流程化、开会什么流程、什么制度」——判断变成：管理是机制和制度。都是管理，议程不同，卖的产品也不同。

议程的问法只有一句：**「这 20 条发完，观众会对这个人形成一个什么判断？」**

### 低级分类 vs 高级分类

话题分类是低级分类：工具用法、行业、课程名。判断分类是高级分类：专业、干净、负责。

为什么高级分类不是换个标签那么简单——分类方法会改变内容本身。同一个豆包教程：按「工具用法」分类，科普用法就能发；按「专业」分类，就得用出花才能发。你预先给观众什么判断，决定了哪条能拍、怎么拍。

你现在的 149 候选就是按低级分类排的：熵增、如实所现、把自己当产品卖出去……这些都是话题。高级分类要问的是：**这些候选合起来，想给读者留下什么判断？**

### 两套结构：对外合集 + 对内报告

博主说这方法交付给一个人时是两块。对外：合集对应一种判断，合集名和简介就是它的脸（比如实体会馆：「我干净、我负责」——开除员工、跟顾客吵架、装修，全往这一个判断上打）。对内：一份报告解释「这个合集为什么这么设、每条怎么讲才能让判断成立」。

实体餐馆的例子最直观：今天拍菜、明天拍员工冲突、后天拍后厨——每条都独立，观众记不住。换成「我干净」一个判断，所有内容都围绕它，观众就有了印象，就有了基础流量。

### 对接你的飞轮

议程就是你飞轮里「树林框架」的对外呈现。你 06 写的主线是「用树林的知识框架形成判断」——判断给谁？给读者。议程设置就是把这件事显式化：你想让读者形成「这个人用传统学科理论帮人理解内容困境」的判断，那你的 149 候选就得按这个判断重新筛，筛掉的不删，沉到素材层。

### 今日最小动作

1. 判断题：候选池「把自己当产品卖出去」系列，第一问打多 / 中 / 少（不会就写「不会」）。
2. 一句话回答：你的 149 候选如果只留一个「判断」给读者，你希望是什么？答不出就写「没有」——「没有」本身就是 03 要你发现的事，下一篇从那里接。

## 小结

1. 两问有例题了：A 切口窄要修切口，B 切口和深度都够；判断题的答法是多 / 中 / 少。
2. IP 定位是结果：管用才反复用，反复用才绑定；起点是帮人解决问题。
3. 议程 = 观众判断：一句「这 20 条发完，观众形成什么判断」就是议程的问法。
4. 低级分类按话题，高级分类按判断；分类改变内容本身——豆包按「工具」能发，按「专业」要用出花。
5. 两套结构：对外合集对应判断，对内报告解释为什么这么设；你的 149 候选目前是低级分类。
