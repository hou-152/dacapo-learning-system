# 01｜反向创作：从「想搞懂一个问题」出发，流量是验证不是起点

## 这一篇要解决的问题

这个博主的创作流程和主流教程是反的。这一篇拆他的完整流程和两个案例（隐性成本、剩余享乐），说清「知识生产在前、流量验证在后」这条顺序为什么成立，为什么别人抄他抄不走。最后你会发现：他跑的就是一个内容版的自迭代环，和你上一个课题的飞轮是同一台机器。

## 正文

### 这份材料是什么

一个做自媒体两年、涨了 100 万粉的博主，公开了一条原本准备收费的 40 分钟视频，一次性讲他的整套内容生产流程，主题是「从知识生产到 IP 定位：选题、议程设置与流量转化」。你把它从通义听悟下载下来，选它做第一圈验证课题——很合适，因为它的命题和你 06 反馈里的飞轮是同一个：候选稿怎么变成被真实消费的内容。

### 主流的顺序和他的顺序

大多数人做内容的顺序：打开小红书抖音，刷到什么火了，改一改观点，再发一遍。他的顺序反过来：

1. 日常积累一个问题——想搞懂一件事（比如「劣质商品为什么比优质商品赚钱」）；
2. 跟 AI 聊，把问题聊透，聊出一个概念（隐性成本）；
3. 用这个概念去解释一个大众旧认知解释不了的现象；
4. 视频开头先抛出那个现象和疑问，再端出概念。

他举的第一个例子是「老实人为什么发不了财」。这个视频的起点不是爆款选题，是他想搞懂一个经济现象。第二个例子是「剩余享乐」：两个人各花 90 块买了手机支架，这家公司一年在抖音卖 7000 万——为什么买了不用还要买？多数人一秒答不上来，他把问题一路分析到齐泽克的剩余享乐。

注意他给自己流程的定位：90% 的内容来自这种慢生产（从筹备知识到发出来，间隔 3 到 6 个月），只有 10% 是快生产（被纳瓦尔拉黑这种十年一遇的独特事件）。快生产靠运气，慢生产靠积累。

### 为什么别人抄他抄不走

他说得直白：模仿他的人不少，成功的不多。原因在流程——他视频的选题背后有一套理论支撑。「老实人为什么发不了财」这个选题，你去找一个「不是隐性成本、又刚好能解释这几个案例」的理论，找不到。反过来，如果你理解了他的流程，换几个案例（不讲开锁，讲别的），依然可以把隐性成本再讲一遍，因为概念本身不是他原创的。

抄选题会失败，抄流程可以复用。这句话值得记。

### 独特是被迫的

有人以为他是为了与众不同而与众不同。他的说法：他是只能不一样，才能一直发下去。因为理论、现象、案例、开头全部从自己的知识生产里长出来，撞上别人的爆款纯属巧合。独特在他的体系里是副产物，源头是「我想搞懂这个问题」。

### 他也是你的自迭代机器

把这条流程和你上一个课题的机器对一遍：

| 他的环节 | 你的机器里的对应 |
|---|---|
| 想搞懂一个问题（积累 + 跟 AI 聊） | 观察层 / 选题的输入端 |
| 聊出一个概念 | 提炼规则 |
| 做成视频发出去 | 行动（产出候选稿） |
| 流量、涨粉、转化 | 真实回执 |
| 概念解释力不够就回来再聊、再修正 | 经验升级或回滚 |

这就是你 06 反馈写的那台飞轮的内容版：现实新现象 → 树林框架判断 → 文章 → 发布 → 反馈 → 提炼一条规则 → 下一篇验证。他的「隐性成本」是从「劣质商品为什么更赚钱」这个疑问里提炼出来的一条规则，被「老实人为什么发不了财」这条视频验证过，后面还能反复复用。殊途同归第三弹。

一个细节和他的定位也呼应：他说 IP 定位是一年之后才有的事，是因为方法 C 反复管用、狂发 100 条之后才绑定的结果。你上一个课题里说的「策略层只收被下一篇验证过的规则」，和他的「管用才狂发」是同一句话。

### 今日最小动作

1. 从他的流程里挑一个环节，对照你的飞轮写一句差异：哪个环节你已经有（你做过发布），哪个环节你没有（你按流程没做过选题）。
2. 用一句话回答：在「隐性成本」这个案例里，哪个环节是「验证」？
3. 把上一课题的三条死守 / 三条放手带过来对照一下：他的体系里，哪些环节是他自己拍板的，哪些交给了流量反馈？

## 小结

1. 他的顺序和主流相反：从想搞懂一个问题出发，聊出概念，再找大众解释不了的现象，最后才是视频。
2. 案例：隐性成本（开锁匠）、剩余享乐（手机支架 → 齐泽克）；90% 慢生产，10% 快生产。
3. 抄选题会失败，抄流程可以复用；独特是流程的副产物，源头是「想搞懂」。
4. 他的流程就是内容版自迭代环：问题 → 概念 → 视频 → 流量回执 → 修正，和你上一课题的飞轮同构。
5. 「IP 是结果不是起点」和你的「策略层只收被验证过的规则」是同一句话。

## 下一篇预告

下一篇拆他的抽象上升法：讲 Workbuddy 用法没人看，讲「人类如何在 30 分钟学会任何一个新工具」有人看——内容没变，开头扩大了。顺带看他怎么干掉「精准流量 / 泛流量」的二元论，以及「以偏概全 → 合集」怎么同时解决产出体系化和观众看不进书两个问题。
