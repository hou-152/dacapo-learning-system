# 01｜先把自己放到船长位置

> 姊妹课程：[[AI工作流控制权迁移]] 从演化逻辑讲同一件事——控制权正在从 Prompt 迁移到 Loop。本课程从工程实践讲怎么落地。

## 本篇基于的反馈

- 材料核心在讲一个资深工程师如何用 Agent、记忆、技能、工具、验证流水线和多工作树来扩大工程产出。
- 本篇先小步推进，只建立整套工作流的总图，不展开每个工具的配置细节。

## 这一篇要解决的问题

先解决一个基础问题：这套 Agentic Engineering Workflow 的主线是什么？如果只记住一个比喻，应该怎样理解“人、Agent、工具、流程”之间的分工？

## 正文

这篇视频的主线可以压缩成一句话：

一个资深工程师把自己从“亲自写每一行代码的人”，升级成“指挥一组 Agent 完成工程任务的人”。

他用了一个很清楚的比喻：人是 captain，Agent 是 crewmates，工具和环境是 ship，First Mate 是帮 captain 管理多个 crewmates 的副手。

这个比喻很有用，因为它把 Agentic Engineering 的难点从“模型会不会写代码”转到了“你怎样组织一支 AI 工程队伍”。

### 1. 船长负责方向、边界和质量门槛

船长的工作有三件：

第一，决定去哪里。

工程里对应的是任务定义：要做什么、为什么做、用户问题是什么、成功标准是什么。视频里提到，前期要把需求讲清楚，有时还会用可视化规划工具把选项摊开讨论。这个动作减少后面返工。

第二，决定什么算完成。

Agent 很适合在中间执行大量工作，但完成感不能只靠一句 “done”。船长要建立验证流水线，比如让 Agent 重建意图、做对抗性 review、跑端到端检查、留下截图或日志证据，再整理成 PR。

第三，决定风险要看多细。

低风险改动可以主要看验证证据。高风险改动要看设计边界、产品影响、迁移成本和失败后果。这样人的注意力用在判断上，而不是被每一行 diff 消耗掉。

### 2. 船是稳定工作面

视频一开始讲终端、tmux、Neovim、语音输入这些东西，看起来像个人偏好，其实是在搭一个稳定工作面。

稳定工作面解决两个问题：

- 保持流动性：手尽量留在键盘上，减少切换成本。
- 保持可复制：同一套工作流能在不同机器、甚至手机上继续。

在这个框架里，终端不是为了显得硬核。它提供了一个统一入口：启动 Agent、开编辑器、运行测试、切换工作树、查看状态，都发生在同一个工作面里。

你可以不用完全复制他的终端配置，但要抓住背后的原则：Agent 越多，工作面越要稳定。入口越散，管理成本越高。

### 3. 船员需要入职培训

刚启动的 Agent 像新来的工程师。它知道很多通用知识，却不知道这个项目的习惯、坑点、偏好和历史决策。

视频里把入职培训拆成两类：

- memory files：长期放在系统或项目里的常驻记忆。
- skills：按需加载的能力包。

memory files 适合放少量高频规则，比如个人偏好、项目结构、核心约定。skills 适合放条件性知识，比如只有做端到端测试时才需要的检查流程。

这里的关键判断是：常驻信息要少，按需信息要清楚。常驻信息太多会占上下文，按需信息缺失会让 Agent 每次重新踩坑。

### 4. 单个船员先跑通，再开始并行

视频没有一上来就讲多 Agent 并行，而是先讲单个 Agent 怎么工作。

基本节奏是：

1. 人说清任务和约束。
2. Agent 探索代码和上下文。
3. 人在前期确认方向。
4. Agent 执行中间工作。
5. 验证流水线检查结果。
6. 人在末端做质量判断。

这像一个工程经理管理一位工程师：前面讲清目标，中间给执行空间，最后看证据和风险。

如果这个循环没有跑通，直接加多个 Agent 会放大混乱。多个没有边界的 Agent 同时改同一个目录，会产生冲突；多个没有验收标准的 Agent 同时交付，会产生审查债。

### 5. 多个船员需要隔离和调度

并行工作需要两个能力。

第一是隔离。视频里用 git worktree 和 Treehouse 来隔离不同任务。每个 Agent 在独立工作树里工作，减少互相踩文件、互相污染状态的概率。

第二是调度。多个 Agent 同时工作后，人会被迫记住每个任务在哪、进度如何、是否卡住、是否需要处理 PR。这个管理负担会迅速变重。

所以视频最后引出 First Mate。它的角色是替船长调度多个 Agent：创建工作树、分配任务、看状态、推进验证、整理 PR，让人继续站在方向和判断的位置上。

### 6. 一个具体例子

假设你要改一个产品里的“成就系统”。

普通做法是：你打开编辑器，自己查代码，自己想方案，自己改，自己测，自己看 diff。

Agentic Engineering 的做法可以拆成：

1. 你先让 Agent 提出几个方案，并用可视化方式呈现给你讨论。
2. 你选定方向，明确成功标准。
3. Agent 实现。
4. 验证流水线复盘你的原始意图，做 review，跑端到端检查，生成证据。
5. 你根据证据和风险决定要不要看细节。
6. 如果同时还有别的任务，First Mate 帮你开多个隔离工作树并调度多个 Agent。

这个例子里，人没有消失。人的位置变了：少做重复执行，多做方向、判断和门槛设计。

### 7. 本篇先记住这张总图

这套工作流可以先记成 5 层：

1. Ship：稳定的工作环境。
2. Crewmate onboarding：用 memory 和 skills 训练 Agent。
3. Single crewmate：先跑通单 Agent 的任务循环。
4. Crew：用 worktree 和调度工具支持多 Agent 并行。
5. First Mate：让一个更高层的 Agent 管理多个执行 Agent。

后面的学习不要急着记工具名。工具名会变，主结构更重要。你先能讲清“为什么需要这些层”，再去学每一层用什么工具。

## 小结

- 这篇视频的核心主线是：把人放到船长位置，把 Agent 当成可入职、可调度、可验证的工程船员。
- 船长负责方向、边界、成功标准和质量门槛。
- 船提供稳定工作面，减少切换成本，让多个 Agent 工作时仍然可控。
- memory 和 skills 是 Agent 的入职培训系统。
- 多 Agent 并行要靠隔离、调度和验证流水线支撑。
