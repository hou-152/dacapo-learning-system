# 10.5｜最小 Codex loop 行动接口

## 承接说明

你在 10.md 里写了两句关键反馈：`有点困难，我不是程序员出身`，以及 `dbs-learning，“我“完成 n 的反馈，费曼，回锅时，learning 生成 n+2 的，当“我“可以阅读 ok 了`。所以这一篇不继续讲新材料，只把 Loop 换成你的真实场景：让 dbs-learning 在你答完一篇后，怎样生成下一篇。

## 这一篇要解决的问题

10.md 的卡点集中在动作接口。你已经知道 Loop 要有触发、状态、动作、反馈和停止条件，但还没把它写成一个能交给 Codex 执行的小任务。

## 正文

先把术语压成一句话：

```text
Loop = 某个信号出现后，系统按固定步骤行动，拿反馈判断继续、停止，还是交回人。
```

它不要求你是程序员。只要你能说清 5 件事，就已经在写 Loop。

```text
什么时候启动？
启动时要看什么状态？
系统要做什么动作？
看什么反馈判断好坏？
什么时候停止，什么时候交回人？
```

### 1. 不用页面加载速度，先用你的学习任务

10.md 的第一道检验题让你改“优化页面加载速度”，这对非程序员不友好。现在换成你的真实任务：

```text
任务：我答完第 N 篇后，让 dbs-learning 决定下一步。
```

这件事可以写成最小 Loop。

第一阶段的状态是什么？

具体流程是：
1. 当我写完第 N 篇之后，dbs-learning 会去检测我在文章中的批注和批注联想，然后去文章末尾看反馈和回溯。
2. 如果这个状态 OK，系统就会把它和我之前回答过的同样内容打包成上下文，然后交给 Learning 模块。
3. Learning 模块负责打分（设定多少分能通过、多少分及格）。
   (a) 如果分数太低，流程就会停止。
   (b) 这时我需要加一个 10.5 的步骤，让它去再补充一下，然后才能过关。
4. 流程 OK 之后，就会依次生成。当生成到第八篇（或者达到一开始设定的学习记录上限）时，系统停止。
5. 最后由人工来决策：是去复盘、去干嘛，还是直接停止。这部分由人类来决策。
### 2. 先写五槽

```text
触发：
我提交第 N 篇的回锅测试、检验题，或在正文里留下批注。

状态：
第 N 篇正文、我的答案、我的批注原话、learner-log 最近记录、plan.md 里的概念清单。

工具动作：
agent 先生成 N-批注回应报告，再批改答题，最后判断推进、补救还是作废。

反馈信号：
回锅测试分数、本篇检验题分数、行动题四槽是否完整、批注里是否出现误解或好问题。

停止条件：
批注回应完成，答题批改完成，learner-log 写入掌握判定和下一步裁决。
```

这已经比“learning 生成 n+2，当我可以阅读 ok 了”硬很多。

差别在这里：

```text
“我可以阅读 ok 了”是感受。
“批注回应 + 批改 + learner-log 裁决完成”是可检查结果。
```

### 3. 再补最大尝试次数

Loop 不能无限转。它要知道最多试几次。

这个学习 Loop 可以这样写：

```text
最大尝试次数：
同一个核心卡点最多连续补救 2 次。

超过 2 次仍然答不出：
停止生成新篇，转成 good-question，把卡点炼成一个更清楚的问题。
```

这能防止系统一直写补救篇，却没有真正解决断点。

### 4. 最后补人工升级点

人工升级点就是：什么时候不能再让 agent 自己判断，必须回来问你。

你的场景里，人工升级点可以是：

```text
需要人判断的升级点：
1. agent 无法判断某段批注是否来自用户新增内容；
2. 教材材料不足，撑不起下一篇；
3. 答题分数要求补救，但用户明确说这个方向已经偏离自己想学的东西；
4. 某条本人联想可能入 CON，但概念名或含义冲突；
5. 同一断点连续 2 次补救仍不过。
```

注意第 3 条：用户可以决定学不学这个方向，但不能用“我感觉懂了”越过答题门禁。

### 5. 写成完整行动题四槽

现在把它压成你要交卷的四槽。

```text
谁：
dbs-learning agent。

什么时候：
我提交第 N 篇答案和批注后。

做什么：
先回应批注，再批改答题，再把掌握判定、偏好和下一步裁决写入 learner-log。

怎样算完成：
出现 N-批注回应报告；learner-log 有第 N 篇分数、掌握判定、偏好记录和后续动作；如果是推进，再生成 N+1；如果是部分理解，生成 N.5；如果尚未理解，停止新篇并补救。
```

再补两行：

```text
最大尝试次数：
同一核心断点最多补救 2 次。

人工升级点：
材料不足、批注身份不明、CON 入库冲突、连续 2 次补救不过时，交回用户判断。
```

这就是一个最小 Codex loop。

### 6. Harness 在哪里

你问 `harness` 和 Codex / Claude Code 的设计原理是否相似。可以这样理解。

在这个例子里，Loop 是这套步骤：

```text
提交答案 → 批注回应 → 批改 → 写 log → 决定下一步
```

Harness 是让这个 Loop 可靠运行的外围东西：

```text
文件路径规则
learner-log 格式
批注回应报告格式
审计门禁
CON 入库规则
流水线债务上限
材料不足即停
```

Loop 是循环本身。

Harness 是循环能被信任的工作间。

所以 Harness 的工程优先级会很高。没有 Harness，Loop 很容易变成“agent 自己说自己完成了”。

## 小结

- Loop 不要求你会写代码，它要求你写清触发、状态、动作、反馈和停止条件。
- 行动题四槽要写成谁、什么时候、做什么、怎样算完成，不能写成“我感觉 ok”。
- 最大尝试次数防止系统空转。
- 人工升级点说明哪些判断必须回到人这里。
- Harness 是让 Loop 可信的外围机制，Loop 是循环本身。

## 回锅测试

1. 用一句话区分 Loop 和 Harness。
Loop 就是流水线，Harness 就是车间
2. 回看 10.md：你说“如果是总经理 Agent 说测试过了，我觉得可以信”。现在重答：为什么不能只看 Agent 身份，而要看证据？
决策不能外包。

AI 有它自己的判断，但它的判断不一定是正确的，真正的决策只能出自于人。

这就是“人在回路”（Human-in-the-loop）的重要性：有些判断、有些风险必须由人去承担，而不是交给 AI。
