# 11｜我的 Codex 工作流总操作卡

## 承接说明

你说：`如果是以我这个 human agent 为准`，又补充了两条模型路由判断：简单任务交给低模型；遇到交叉学习、Codex 和 Human agent 都拿不准的情况，由你决定用更强还是更便宜的模型。本篇按你的实际操作面收束，只保留 Human agent、Codex agent 和模型路由三件事。

## 这一篇要解决的问题

你每次打开一篇学习材料时，谁先动、谁收尾、什么时候把判断交还给人？

## 正文

### 1. 先写主体

同一件学习任务里有两条 Loop。每条 Loop 都有自己的触发、状态和停止条件。

| 主体 | 负责的工作 | 停止时刻 |
|---|---|---|
| Human agent | 读、判断、口头费曼、决定模型和下一步 | 本篇问题已经讲完，卡点和判断已经说出 |
| Codex agent | 读取答案、整理材料、批改、更新课程状态 | 文件与路径裁决已经写好，等待人阅读或判断 |

把主体写在任务第一行，后面的五槽就不容易混线。

### 2. 你的 Human agent 学习环

```text
触发：Codex 发来需要阅读或回答的当前文章。

状态：00 学习计划、当前文章、批注回应报告和索引已经存在；本篇还有未完成的理解或回答。

工具动作：打开文章，用 Typeless 做口头费曼；需要时回看批注回应报告。

反馈信号：能顺着讲完；讲不下去的位置被说出来；答案已经留在对话或文章中。

停止条件：本篇要回答的问题都已讲完，随后由你发出“下一点”或“下一篇”。
```

这条环服务学习。它的产物是你的解释、卡点和下一步判断。

### 3. 模型路由卡

```text
低模型：重复、摘取、转格式、明确的局部改写；输出可以快速检查。

强模型：跨材料、跨任务、需要比较多个方案的工作。

Human agent：目标变了、材料冲突、模型之间给出不同判断、成本与风险需要取舍。
```

你的“交叉学习”例子正好落在第三行：两个材料放在一起后，先判断问题到底是整理、比较，还是需要改变学习目标；再决定模型能力和投入。

### 4. 一次运行只看四件事

```text
我现在是谁？
我手里有哪些状态？
这一步留下什么可见结果？
到哪里就停，并交给谁？
```

这四句足够把一次学习运行接起来。复杂的工作再往下拆；简单的工作保持短。

## 回锅测试

1. 你在口头费曼时讲不下去，这条信息属于 Human agent 的哪个槽位？它接下来会改变什么？
交给 Codex Agent，说这个东西需要你再给我讲一遍，生成一个过渡的文案，可能是 10.5 或 10.6。

如果多次都回答不了 Good Question，就先降级，然后用那个 Good Question 的
2. 两篇材料出现冲突，低模型和强模型给出不同建议。请写一句话说明此刻为什么要回到 Human agent。
关于决策，因为有些决策是整个 loop 里面的人来做的。

要搞清楚这一点，就必须了解“人在回路”（human-in-the-loop），因为有些判断是没法外包给 agent 的。

## 本篇检验题

选一个你下次准备学的主题，只写 4 行：

```text
主体：Human
当前状态：对一个东西感兴趣，想要强化学习，提高它的学习率
本轮留下的可见结果：Codex Agent，使用 Skill 交互式学习。然后给 Loop、给 Agent 反馈Codex Agent，使用 Skill 交互式学习。
停止后交给谁： 然后每轮结束之后，交给 Agent 去推进课程。
```


## 小结

- Human agent 的工作是学习中的判断、费曼和模型取舍。
- Codex agent 的工作是整理、执行、记录和把材料带回可读状态。
- 两条 Loop 分开写，状态和停止条件才会清楚。
- 低模型处理可快速检查的局部工作；交叉和冲突把判断交还给 Human agent。
