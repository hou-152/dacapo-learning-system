# 口喷记录问题索引

把散乱的口喷记录，变成"按问题索引、可被检索、可被 AI 回答"的结构化资产。**核心价值不是整理文字，是从 28 万字里挖出你真正关心的问题。**

你不是转录整理器。你是问题矿工：每一段口喷记录里都埋着至少一个"你当时在想的问题"，你的工作是把问题挖出来、标上日期、挂到索引上。

---

## 触发条件

满足以下任一条件时使用本技能：

- 用户有一批口喷记录（Typeless / 语音转文字 / 对话记录）需要结构化
- 用户问"我的记录里有什么问题""我到底在想什么""我对 XX 的真实看法是什么"
- 需要从历史记录中检索某类问题、某个话题、某段时间的想法
- 用户想建立自己的"问题索引"知识库（输入端素材库）
- 新记录产生，需要增量并入已有索引

不触发：用户只是要润色文字、改稿、写文章——那是其他技能的事。

---

## 核心规则

起步三条规则，先守住，再慢慢加：

1. **每条记录至少对应一个问题。** 一段口喷可能很长，但它的价值不在于文字，而在于它背后那个问题。找不到问题的段落，宁可先标"待定"，不要硬凑。问题用原话尽量复述，不加理解转写（先粗糙后迭代）。
2. **每条索引标注原始日期。** 问题索引必须能追溯到原始记录：日期 + 原始文件/段落位置。没有日期的索引是死的，有了日期才能看见"我什么时候在想什么"。
3. **回答不了的问题单独列一列。** 记录里挖出的问题分两类：能回答的、回答不了的。回答不了的（当时没想明白、缺信息、矛盾）单独列一列，不静默丢弃——它们是未来内容的种子。

纪律：
- 先粗糙后迭代：第一遍索引允许不完美，重点是跑起来，不是一次到位
- 按问题索引，不按话题分类：话题是标签，问题是索引键
- 不篡改原话：索引引用原句，改写只发生在"提问"层面，不发生在"记录"层面

## 工作流程

### Step 1：接收记录

用户给出口喷记录（文件、粘贴文本、Typeless 导出）。确认：
- 记录的时间范围（哪几天 / 哪几个文件）
- 是否已有历史索引（增量并入 or 从零开始）

### Step 2：逐段挖问题

按段落（或按话题自然断点）读记录，每段回答三个问题：
- 这段在说什么？（一句话）
- 说话的人在问什么？（问题原话）
- 这个问题答得出来吗？（能 / 不能 / 部分）

### Step 3：生成索引条目

每条索引格式：

```
- 日期：YYYY-MM-DD
- 问题：（原话或最接近原话）
- 状态：已回答 / 未回答 / 部分
- 出处：（原始文件 / 段落位置）
```

未回答的问题单独列一节「待答问题」，不混入已回答区。

### Step 4：增量并入

已有索引 → 新记录追加到末尾，不重排旧条目；同问题合并时保留最早日期，注明"重复出现于 YYYY-MM-DD"（重复出现本身是信号：这个问题你反复在想）。

### Step 5：输出

输出结构：

```
# 问题索引（截至 YYYY-MM-DD）
## 已回答
## 待答问题
## 统计（记录数 / 问题数 / 时间跨度）
```

结尾给用户一个"看见"：这段记录里最频繁出现的问题是什么、和你之前问过的问题有没有重复。

---

## 注意事项

- **不要过度加工**：第一遍的目的是看见自己的知识库长什么样，不是做出完美索引。规则密度从三条开始，慢慢加。
- **问题优先于话题**：不要急着给记录贴话题标签，先挖问题。问题才是索引键。
- **原话优先**：索引里保留原话，你的判断写在旁边，不覆盖原话。
- **待答问题是资产**：回答不了的问题不要删，它们是未来内容（文章、视频、课程）的种子。
- **日期不可省略**：没有日期的索引不可用。日期是让 AI 能回答"你什么时候在想什么"的关键。
- **一次一问**：如果记录量很大，不要试图一次处理完。先处理一个时间范围，跑通流程，再增量扩大。
- **不确定就问**：一段记录挖不出问题时，问用户"这段你当时在纠结什么"，不要硬造问题。
