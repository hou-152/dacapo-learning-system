# 10｜重生：用 AI 重建——Claude Code 与 dbskill

## 这一篇要解决的问题

09 讲了被 AI 干掉，本篇讲怎么用 AI 重生：三个星期把 Claude Code 训练成内容流水线（一个不写代码的人怎么用编程助手、从「爹味儿」到「像个人」、27 个技能文件），以及 dbskill 的诞生（从 12,307 条推文到 30 个技能，知识编码是护城河）。开头先正面回答你 09 反馈里的问题：怎么结构化、怎么抄三端、你的 28 万字算不算历史内容。

## 正文

### 〇、先接住你的反馈：你的 28 万字就是历史内容

反馈我读完了。先说最重要的一句：你说「其实我没有历史内容」——你有。Typeless 口喷记录 60 个小时、28 万字，这就是你的素材库原材料。他的原材料是 12,307 条推文，也是每天记录观点攒出来的；你的版本是口喷记录，形式不同，性质一样：思考过程的真实记录。GaryVee 的「document, don't create」你已经实践了 60 小时，你缺的不是记录，是这一篇讲的东西——把记录变成可搜索、可复用、可交付的系统。Document 已经跑起来了，本篇讲 create 的那一半：怎么提炼、怎么编码、怎么复用。

你问「怎么结构化」。三句话，前面几篇都有，本篇串起来：

1. 先粗糙，后迭代。把素材倒进工具，开始提问，看它答得有多差——这一步的目的是看见你的知识库长什么样（5.1 原话）。
2. 按「问题」索引，按「主题」分类。知识库是回答问题的系统，不是存资料的地方。每上传一批内容，同步维护一份索引：这批内容里有哪些观点、对应什么问题、引用时怎么定位（5.1 原话）。你吐槽它「只不过是一个回答问题的系统」——它确实就是，而「能回答问题」正是素材变成资产的标志：结构化的知识才是资产，散乱的知识只是素材。
3. 把模糊的感觉，变成精确的规则。规则密度决定产出质量：字数、句式、分布、禁忌、示例（5.2.3）。

你问「具体该怎么抄」。按公理二，先照抄结构，再填自己的内容。三端分开抄：输入端抄 5.1 的结构化方法（你的 28 万字 + 问题索引）；处理端抄 5.2.3 的技能文件五部分（触发条件、核心规则、工作流程、注意事项、更新日志）——不用 27 个，从 1 个开始；输出端先别抄，等输入端和处理端跑起来再谈。你现在的「对接」冲动就是输出端，顺序反了。

你提 Logseq 反复重启（仰卧起坐）。我猜原因：你把 Logseq 当「存资料的地方」建——分类、标签、完美结构，所以反复重启。正确用法是「回答问题」模式：先粗糙，提问驱动，在答得不好的反馈里迭代。工具本身无所谓，他用 Claude Code，你不用照抄工具——他自己说了：工具会变，今天我用 Claude Code，明天可能有更好的。你反复重启的根因是追求完美结构，而完美结构是长出来的：先建一个粗糙的，再让它慢慢变好，永远比「等想清楚了再建」强。

最后是你那句「我并没有踩过 100 个 Skill，兄弟」。接住：拆 100 个 skill 是 07 的作业，给你编码能力；本篇给你一条更短的路径——dbskill 已经开源了，你先抄 1 个技能文件的结构（现成的），同时把你的 28 万字跑起来（现成的）。踩过 1 个真实 skill 的拆解，加上 1 个自己的最小知识库，比看过 100 个更值钱。

### 一、三个阶段：躲、试、用

被 AI 干掉之后，他用几个月走完了从「恐惧 AI」到「驾驭 AI」的转变。转变分三个阶段：

- 躲：停更了一段时间，不想碰 AI，也不想做内容
- 试：开始研究 AI，看它到底能做什么、不能做什么，用 AI 做分析、做整理，但坚决不让它直接写稿
- 用：确认 AI 的边界之后，大规模使用，把重复劳动全部交给它，把自己解放出来做判断和创造

三个阶段缺一不可。他特意提醒：很多人卡在「躲」或者「试」，永远走不到「用」。注意第二阶段的动作——「试」的时候就不让 AI 直接写稿，这条规矩比大规模使用更早立下。这正是 4.2.3 那条底线的落地顺序：先确认边界，再放手用。

标志性事件：2026 年 1 月到 2 月，他花了三个星期，把 Claude Code 训练成了自己的内容生产流水线。

### 二、一个不写代码的人，怎么把编程助手变成流水线

先说背景：Claude Code 是一个 AI 编程助手，本职是写代码。他几乎不写代码，把它当成了内容生产工作室。

这里要澄清一个误解：用 AI 做内容，不等于让 AI 写内容。在他和 Claude Code 协作的 76 个会话里，真正「生成新内容」的会话只占一小部分，更多的是四类活：筛选（从三千多条推文里筛出适合发小红书的）、优化（把一篇长文改成适合口播的版本）、整理（把几百个文件分类归档）、检查（找出文稿里逻辑断裂的地方）。这些工作 AI 做得又快又好；而「写什么」这个决定，永远是他做的。记住这个分工：AI 负责「怎么做」，你负责「做什么」。

三个星期的数据：76 个会话，平均每天 3.5 个；933 条消息，平均每天 42 条；创建或编辑文件 277 个；新增 31,753 行「代码」——注意，这里的「代码行」其实都是文字内容：文章、视频脚本、小红书笔记、抖音文案。最后 Markdown 文件累计 753 个。

他经常工作到凌晨两点，还在和 Claude Code 讨论小红书标题。有一次它问他为什么这么拼，他说：因为我终于找到了一个「外挂大脑」，我要把过去三年攒的所有经验，全部编码进去。他还有下半句没说出来：验证一个猜想——如果方法论编码得足够好，AI 能不能替他完成 80% 的重复劳动？结果：能。三个星期之后，他的内容产出效率提升了好几倍，精力从「执行」转移到了「设计」。他给这个身份转变下了一个定义：我不再是内容的流水线工人，我是内容流水线的设计师。这个转变，就是「重生」的实质。

为什么是「编码」，而不是「告诉它」？因为告诉它是临时的，它记不住、也用不好；编码是结构化的，它随时可以调用、可以复用。这就像教一个新人：你口头说一遍，他转头就忘；你写一份标准作业流程给他，他照着做就能上手。AI 也是一样，它需要的是「标准作业流程」，不是「口头吩咐」。这也是 dbskill 的核心逻辑：不是让 AI 更聪明，而是把人类的经验变成 AI 能执行的标准。

### 三、从「爹味儿」到「像个人」：立规矩就是知识编码

磨合期里，他教 Claude Code 的第一课，是「什么叫爹味儿」。

最开始，Claude Code 写标题特别「AI」：「创业者必读：如何通过系统化思维提升商业认知，实现可持续增长」。他一看说：太爹味儿了。它懵了，问爹味儿是什么。他说：就是那种居高临下的说教感，像个老父亲在教训孩子。你这标题一看就是 AI 写的，没人会点。

然后他给它改了一个示范：「为什么学了那么多还是不赚钱」。十四个字，直击痛点，留悬念，不给答案。

接着他立了一堆规矩：不要写「通过以下三个步骤，您可以有效提升内容质量」，要写「90% 的人在第一步就错了」；不要写「建议您采用数据驱动的方法进行选题」，要写「我用这个方法，一年涨粉 70 万」；不要写「综上所述，我们可以得出结论」，要写「说白了就一句话」。

他后来回想，那是他第一次做知识编码，只是当时不知道这个词。每一条规矩，都是从失败和成功里提炼出来的经验：标题要留悬念，是他拆了一百条爆款发现的；别用「综上所述」，是他自己写废了几百条内容总结出来的；「90% 的人在第一步就错了」这个句式能火，是他用数据验证过的。这些规矩，就是他的方法论的颗粒。

他教它的最后一句话，后来成了所有 AI 工作流的第一原则：你要像个人，不要像个教科书。「像个人」有三层：语言层，别用「您」「建议」「综上所述」这种教科书腔，用「你」「说白了」「90% 的人」；结构层，别平铺直叙，要制造悬念、冲突、对比，像人说话一样有起承转合；灵魂层，内容里要有你的经历、你的观点、你的态度——这是 AI 无法凭空生成的部分，必须由你注入。他后来检查 AI 产出的所有内容，用的就是这三层标准。

### 四、27 个技能文件：规则密度

磨合期过后，他开始做最重要的事：把过去积累的所有方法论，编码成「技能文件」，交给 Claude Code 使用。

他在项目里建了一个 skills 文件夹，放了 27 个技能文件。每个文件就是一套标准化的作业流程：选题怎么筛、标题怎么写、素材怎么提炼、内容怎么适配平台、文件怎么管理。每个技能文件包含五部分：触发条件、核心规则、工作流程、注意事项、更新日志。

举一个例子：「全平台标题与封面生成」这个技能文件里，他规定了：小红书标题不超过 20 个字；必须留悬念，不给答案；话题范围要广，避免「自媒体」「知识付费」这类缩窄词；标题要有张力——对比、数字、悬念、冲突，至少占两项。他还规定了标题类型的分布：数据加发现型占 20% 到 30%，认知冲突型占 20% 到 30%，金句型占 15% 到 25%，对比型占 10% 到 20%，提问式占 10% 到 20%，且提问式不要超过 30%。

你可能觉得这些规则太细了。但正是这些细到变态的规则，让 AI 产出的内容，从「AI 味」变成了「人味」。这里有一个概念值得记住：规则密度。你对 AI 的约束越细，它的产出就越接近你的标准；你对它的约束越粗，它的产出就越平庸。大多数人对 AI 的用法是「帮我写个标题」，然后抱怨 AI 写得不行。问题不在 AI，在你没有给它足够的规则。

知识编码的实操本质，就一句话：把模糊的感觉，变成精确的规则。因为你的方法论，本质上就是你的审美标准；把它编码成规则，AI 就继承了你的审美。

### 五、dbskill 的诞生：把方法论变成可运行的工具

三个星期的训练让他尝到了知识编码的甜头，但他不满足于只为自己服务：他想把这套方法论做成一个所有人都能用的工具。于是 dbskill 诞生了。

dbskill 的原材料，是他从 2024 年开始在推特上积累的 12,307 条推文。这些推文是他思考过程的真实记录，也是方法论最原始的素材库。但它们太碎了：一万多条碎片，谁看得完？于是他做了一个决定：用 AI 把这一万多条推文全部过一遍——分类、聚类、去重，提炼出几百个知识原子，再组织成 30 个可调用的技能。每一个技能，都是一套可以执行的流程。

dbskill 整合了 30 个技能、4,176 条结构化知识原子，覆盖从选题、写稿、诊断到发布的完整内容生产链路。它背后的理念，他自己的话：「不是我的知识库，而是我的方法论的可执行版本。知识库是死的，你问它才答；技能是活的，你调用它就执行。」dbskill 里的每一个技能，都对应他一个真实的实战场景：发稿前跑「共鸣检查」和「逻辑检查」，选题时调用「选题顾问」，写标题时调用「标题生成」。这些技能不是写出来装点门面的，是他每天都在用的内部工具。

他后来把 dbskill 开源了，理由一句话：方法论不应该被锁在个人脑子里，它应该变成公共基础设施。

注意一个细节，你可以拿它检验你之前的问题（「它和我的区别在哪里」）：dbskill 的「商业诊断」技能，把三大公理变成了三个问题——需求是真的吗？有对标吗？目标清楚吗？这套流程的每一个问题，都是你 04 到 08 学过的内容。你学完这门课再去看它，看到的是「标准」背后的「道」；你之前用它，看到的是「标准」本身。区别就在这里。

### 六、知识编码：AI 时代创作者的护城河

dbskill 的诞生，让他想明白了一个问题：AI 时代，内容创作者的护城河是什么？

答案是知识编码。他给了一个大白话例子：假设你是一个很会写标题的人，你的标题能力值十万块。AI 出现了，它学了十万个标题，你的标题它也能写。你的内容优势瞬间归零。但是，如果你不仅仅「会写标题」，而是「知道为什么这些标题有效、能根据平台和受众设计新标题、能把标题方法论教给别人」，那 AI 就替代不了你——因为你的价值在于标题背后的知识体系。知识体系，就是知识编码。它让 AI 从你的「竞争对手」变成了你的「执行工具」。

他给了一句总结，建议抄下来：与其恐惧 AI 替代你，不如把自己变成一个「可以被编码、但永远无法被完全编码」的人。内容会被 AI 吸收、重组、超越；但知识编码——把个人方法论变成系统、工具、流程的能力——是 AI 替代不了的。因为知识编码的前提，是你有独特的、经过实战验证的、成体系的方法论；而方法论的前提，是你有真实的经历、失败的教训、成功的经验。

最锋利的一句在这里：AI 可以学习你的内容，但学不了你的经历；可以模仿你的表达，但模仿不了你的判断；可以复刻你的方法，但复刻不了你创造方法的那个过程。

他自己就是验证：被 AI 干掉的时候，他只有 20 万粉；想明白知识编码之后，他做到了 70 万粉。差距不在内容，在系统。

### 七、把 10 和你的问题接起来：你的第一个技能文件

现在回到你的 09 反馈。给你两个最小动作，做完你就踩过了自己的第一个 skill：

动作一（输入端）：把 Typeless 的 28 万字导出，丢进任何一个 AI 工具（或 Logseq 加 AI），问它三个你自己的真实问题——比如「我对找对标这件事的真实看法是什么」「我反复重启 Logseq 的原因是什么」。看它答得有多差。这一步的目的是看见你的知识库长什么样。

动作二（处理端）：打开 dbskill 的 GitHub 仓库（开源了，现成的），随便挑一个技能文件，抄它的结构——五部分：触发条件、核心规则、工作流程、注意事项、更新日志。然后为你自己写第一个技能文件，内容建议从你最熟的开始：「怎么把口喷记录变成问题索引」。规则先定三条就够，比如：每条记录至少对应一个问题；每条索引标注原始日期；回答不了的问题单独列一列。规则密度从三条开始，慢慢加。

这两个动作做完，你手里的东西就变成了：一个「看见过自己长什么样」的素材库，加一个「你写的第一份标准作业流程」。这就是「独属于你自己的东西」的起点——它的原材料是你的经历，它的规则是你的判断。

## 小结

1. 你的 28 万字口喷记录就是历史内容：document 你已经实践了 60 小时，本篇讲 create 的那一半——提炼、编码、复用。
2. 三个阶段的顺序：躲、试、用。「试」的阶段就要立下「不让 AI 直接写稿」的规矩，先确认边界，再放手用。
3. 用 AI 做内容不等于让 AI 写内容：76 个会话里大部分是筛选、优化、整理、检查；AI 负责怎么做，你负责做什么。
4. 从爹味儿到像个人：立规矩就是知识编码——每一条规矩都是你从失败和成功里提炼的经验；像个人有三层：语言层、结构层、灵魂层。
5. 规则密度：约束越细，产出越接近你的标准；知识编码的实操本质是把模糊的感觉变成精确的规则。
6. dbskill 的诞生：12,307 条推文 → 30 个技能、4,176 条知识原子；知识编码是护城河——AI 学得了你的内容，学不了你的经历。
