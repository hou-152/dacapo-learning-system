# 直播文稿人物词典与全量清洗：对抗性审计

## 结论

本轮完成的是**保守型 V1 清洗**：32／32 份文稿另存，正文逐行执行 55 组高置信热词纠错，共实施 2,515 次替换、128 种实际「错词 → 正词」组合；标题／来源元数据和行数全部保持。没有覆盖原稿，没有调用 `transcript-cleaner`，没有把私密语料上传到外部服务。

本轮没有做语义改写、删口头禅、自动合并改口或说话人切分。把这些能力伪装成已完成会制造假干净，因此明确留在 V2 候选层。

## 3. 清洗门禁

- 阈值：`threshold=0.97`；候选观察阈值：`similar_threshold=0.90`。
- 仅处理第一个 Markdown 分隔线后的正文；标题和来源块不进入纠错器。
- 每一行独立处理，禁止跨换行合并词语或吞掉段落。
- 只有 `match` 进入清洗稿；429 个 `similar_only` 观察事件全部不改。
- `NPC`、`PPT` 等易误改缩写设置上下文黑名单。
- 全部实际替换类型已枚举复核；对 `房贷指南 → 防呆指南`、`NBC → NPC`、`PPD → PPT`、`电视相对论 → 电商相对论`、`没有意于多吃 → 一鱼多吃` 等高风险类型回看原文上下文。
- `气运加深 → 气运加身` 在第二轮审计中被撤回：前者在语料中出现 8 次，后者仅 2 次，证据不足以强制归一。
- 没有逐条人工阅读全部替换事件；因此「零误改」仍不能宣称。

## 5. 攻击面与失败模式

| 攻击问题 | 审计结论 |
| --- | --- |
| 会不会把嘉宾的话写进姜禹画像？ | 会，若直接使用整批词频。因此所有频次标为「语料级」，画像另以明显主讲段落和跨稿重复作证。 |
| 会不会把同音正常词误改成专名？ | 仍有残余风险。高阈值、黑名单和上下文抽样降低风险，但没有音频就无法彻底消除。 |
| 会不会为了好读而改掉观点？ | V1 不做语义重写，不删口头禅，不补写信息。 |
| 会不会覆盖或污染原稿？ | 不会。`raw/` 与 `cleaned/` 分层，且源 ZIP 哈希冻结。 |
| 会不会把自述资产／公司规模当事实？ | 不会。人物档案分别标 `PUBLIC_SOURCE_SUPPORTED`、`SELF_REPORTED`、`UNKNOWN`。 |
| GitHub 项目是否等于 Typeless 官方？ | 不等于。报告明确区分官方产品文档、第三方复刻和本轮采用的离线组件。 |

## 6. 残留未知

1. 32 份文稿没有统一说话人 diarization，个人词频不能精确计算。
2. 没有音频回听，本轮只能用标题、跨稿稳定形和公开来源确认词形。
3. 公开文章能支持姓名、昵称和作者关系，不能支持全部生平与商业数字。
4. V1 是词典纠错稿，不是可直接出版的编辑稿；若做 V2，必须先完成说话人切分并抽样建立语义保真阈值。
