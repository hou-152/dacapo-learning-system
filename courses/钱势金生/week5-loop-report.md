## 三、用户反馈与系统吸收

### 1. 已被吸收的反馈

`03.md` 的反馈暴露出：用户能感到“钱的姿态会影响内外世界”，但一开始把因果说成了“钱多钱少塑造种子”。系统把它记录为小偏差，并在后续讲解中强调“金钱性格是种子，钱多钱少是压力场”。

`04.md` 的反馈暴露出：用户能讲“钱区”和南北市场差异，但把 `02.md` 的四种钱形态接到 `04.md` 的钱流路线时断开。系统没有继续推进，而是插入 `04.5.md`。

`04.5.md` 的最终补答显示：用户已经能把心灵货币理解成交易后的继续联系，但兑现标准还不够硬。后续应继续追问复购、介绍、试用、背书、下一次合作等可验证动作。

`05.md` 的反馈暴露出：用户理解了打工思维和老板思维的差异，也能区分用时间交换报酬和用结果交换价值；但还没有把“机会、障碍、第一步行动”落到自己的具体项目上。这个缺口已经标记为需要吸收进 `07.md`。

### 2. 本周新暴露的问题

用户指出：“哪个概念全新？”这个问题不应该交给用户回答。一个概念经常有多个同位词，例如“暗知识”和“默会知识”；用户在学习中无法可靠判断某个概念是否真的全新、是否只是同义词、是否和旧概念发生词面撞车。

这个反馈是对的。概念识别应该改成 agent 的工作：

- 先做规范名识别。
- 再做别名识别。
- 再做近义概念识别。
- 再判断是否为新概念候选。
- 只有冲突、不确定或高风险合并时，才问用户。

保留给用户的低负担问题应该只有“下一篇更深、更广，还是保持”。这是偏好选择，不是知识判断。

## 四、当前结构性问题

### 1. 上下文会爆炸

如果每一篇都把所有历史原文、全部答题、全部概念节点塞进上下文，Loop 会线性膨胀，最后变成又慢又不稳的长上下文堆料。

当前更合理的压缩方式是分层：

- 当前教材片段：只读本篇相关源文。
- 计划层：读取 `plan.md` 的课程路线和当前篇号。
- 学习状态层：读取 `learner-log.md` 的压缩结论，而不是把所有历史答题原文塞进去。
- 近邻窗口：只保留上一轮答题、上一课、当前课、必要的 N-2 回锅信息。
- 概念检索层：从 `dbs-content-system` 检索 top-K，跳过 `search_exclude`。
- 个人联想层：只调取与本篇相关的 `[本人联想]`，并显示校验状态。

这样上下文不会随着课程篇数线性增长。旧内容留在文件里，进入上下文的是压缩后的状态和按需检索结果。

### 2. 预生成会产生一拍延迟

当前流水线为了避免用户读完后等待，会允许 N+1 预生成。但这带来一个结构问题：当用户读第 N 篇时，N+1 往往只掌握到 N-1 的批改上下文。

这个问题不能靠“别预生成”解决，否则流水线会慢；也不能靠“继续甩开答题”解决，否则会假装自适应。

更好的机制是：

- N+1 先作为草稿生成。
- 用户答完 N 后，先做 delta patch。
- 小偏差：直接补进 N+1 的侧栏、例子或检验题。
- 中偏差：N+1 局部修订，N+2 重点吸收。
- 大偏差：暂停主线，插入 N.5 补救篇。
- 修订后才把 N+1 视为 locked 版本。

也就是说，预生成只能叫草稿，不能叫已经适配完成。

### 3. CON 现在还是散点，不是知识体系

当前 `CON` 节点已经能保存概念，但从学习科学角度看，散点效率不高。它缺少概念之间的结构关系、先后依赖、同义归并和学习状态。

更准确的分层应该是：

- `CON`：概念原子，保存定义、来源、标签。
- `ALIAS`：同义词和别名层，例如“暗知识 / 默会知识”。
- `MAP`：概念簇和主题地图，把散点组织成结构。
- `REL`：关系层，记录解释、证明、冲突、前置、部分-整体。
- `LEARNER-STATE`：学习状态，记录已掌握、曾卡住、待校验、含误解、需回锅。

下一步真正要优化的不是继续增加 CON 数量，而是给 CON 加上规范名、别名、概念簇、关系和学习状态。

## 五、系统规则需要更新

### 1. 取消“哪个概念全新”的口头问题

旧规则：

> 批改时顺口问：哪段卡住、哪个概念全新、下一篇更深更广还是保持？

建议改成：

> 批改时由 agent 自动识别卡点和新旧概念。用户只需要补充：下一篇更深、更广，还是保持。只有概念冲突、别名不确定或高风险合并时，才向用户确认。

### 2. 给概念节点增加别名与规范名

建议新增字段：

```yaml
canonical_name:
aliases: []
concept_cluster:
```

这解决“暗知识”和“默会知识”这种同物异名问题，也能减少重复节点和词面撞车。

### 3. 给 `[本人联想]` 增加校验状态

建议新增字段：

```yaml
verification_status: 待校验
```

可选值：

- `待校验`：用户费曼表达有价值，但尚未确认正确。
- `已校验`：能被教材原文、后续答题或已有节点支撑。
- `含误解`：保留为误解样本，不进入正常事实检索。

这样可以保住费曼过程的价值，同时避免口误污染知识库。

### 4. 建立上下文压缩规则

建议把每次生成的上下文压缩成固定包：

```text
本篇源文
+ plan 当前路线
+ learner-log 最近结论
+ 上一轮答题摘要
+ N-2 回锅概念
+ top-K CON / ALIAS / MAP 检索结果
+ 待校验本人联想
```

禁止把所有历史 md 全量塞进提示词。
