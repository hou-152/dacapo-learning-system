09｜三分钟决策卡：快速判断一个 AI 工作流是否值得继续用
==============================


本篇基于的反馈
-------


* 你在第 8 篇 Reader 里划线了“它减少的成本”这一段，尤其是整理成本、结构成本、推进成本、同步成本和记忆成本。
* 本轮没有新增文字笔记，也没有口头费曼，所以可见反馈较少。
* 从划线位置看，你这轮关注的是：一个 AI 工作流到底帮我省了哪些具体成本。
* 第 8 篇的 15 问诊断表完整，但日常使用会偏重；这一篇把它压缩成 3 分钟能用的决策卡。


这一篇要解决的问题
---------


这一篇只解决一个问题：当你遇到一个 AI 工具、agent 或自动化方案时，怎么在 3 分钟内判断它值得继续用、缩小范围、加验证，还是先停掉。


正文
--


第 8 篇的 15 问诊断表适合认真复盘。日常决策时，你通常没有那么多时间。


所以需要一张更轻的卡片：



```
3 分钟 AI 工作流决策卡

1. 它省了我哪 3 类成本？
2. 它新增了哪 3 类成本？
3. 它错了以后谁发现、谁负责、怎么恢复？
4. 它有没有把结果压成一个最小行动？
5. 我的下一步是：继续 / 缩小 / 加验证 / 停用

```

这张卡片的目标很简单：让你快速看见成本移动，避免被“产出变多”带着走。


### 1. 第一问：它省了我哪 3 类成本？


先列减少的成本。


不要写大词，直接写动作。


比如你用 AI 做学习文章：



```
它省了：
1. 回忆成本：不用重新翻前几篇找当前进度。
2. 整理成本：不用手动汇总 Reader 划线。
3. 结构成本：每篇固定有反馈、正文、费曼检查和学习反馈。

```

再比如你用 AI 总结行业报告：



```
它省了：
1. 初读成本：先帮我扫出报告结构。
2. 标记成本：帮我列出关键指标和异常点。
3. 对比成本：把本期数据和上一期变化放在一起。

```

如果你说不出它省了什么成本，只能说“感觉挺方便”，这个工具还没进入可判断状态。


### 2. 第二问：它新增了哪 3 类成本？


接着列新增成本。


这一问比第一问更重要，因为 AI 工具经常把成本转移到后面。


比如学习文章工作流新增了：



```
它新增了：
1. 审查成本：我要判断文章有没有讲偏。
2. 反馈成本：我要划线、写笔记或做口头费曼。
3. 依赖成本：Reader、文件和计划要保持同步。

```

再比如 AI 总结行业报告新增了：



```
它新增了：
1. 核对成本：我要检查数字和来源。
2. 判断成本：我要决定哪些异常值得行动。
3. 误用成本：摘要太顺时，我可能跳过原文。

```

这一步要诚实。工具越顺手，越要问它把成本藏到哪里了。


### 3. 第三问：错了以后谁发现、谁负责、怎么恢复？


这是决策卡里最硬的一问。


任何 AI 工作流，只要会影响判断、文件、代码、钱、客户或团队协作，都要回答这三个问题：



```
谁发现错误？
谁负责判断？
怎么恢复现场？

```

以 AI 写代码为例：



```
发现错误：测试、类型检查、代码审查、线上日志。
负责判断：开发者本人。
恢复现场：Git diff、commit、revert、回滚版本。

```

以 AI 生成投资摘要为例：



```
发现错误：原始公告、财报、行情数据、反向观点。
负责判断：做决策的人。
恢复现场：保留来源链接、标注不确定字段、记录判断时间。

```

如果一个工作流答不出恢复路径，它的风险等级要上调。


恢复路径越弱，自动化范围就越小。


### 4. 第四问：它有没有压成最小行动？


AI 工具很容易生成一堆内容。内容变多以后，人还是要决定下一步。


所以你要看它有没有把结果压成一个最小行动。


好输出像这样：



```
下一步：先读报告第 3 节和第 6 节，确认库存和毛利率变化。

```

差输出像这样：



```
这份报告有很多值得关注的地方，包括市场趋势、竞争格局、技术发展、政策变化和公司战略。

```

第一个输出能启动行动。第二个输出只增加阅读负担。


判断一个 AI 工作流是否值得保留，最小行动很关键。它要把复杂内容压成可做的一步。


### 5. 第五问：下一步怎么处理它？


最后不要只给“好 / 坏”判断。直接给处理动作。


处理动作有 4 种：



```
继续：成本明显下降，新增成本可控，有验证和恢复路径。
缩小：有用，但范围太大，先限制输入、输出或影响范围。
加验证：产出有价值，但错误成本高，需要引用、测试、diff、日志或人工复核。
停用：新增成本超过减少成本，或恢复路径太弱。

```

举例：



```
工作流：AI 帮我生成学习文章并同步 Reader

减少成本：
1. 回忆成本
2. 整理成本
3. 结构成本

新增成本：
1. 审查成本
2. 反馈成本
3. 同步依赖成本

恢复路径：
本地 Markdown、学习计划、Reader 链接、文件差异都能追踪。

最小行动：
读完后划线 1-3 处，或写一段口头费曼。

处理动作：
继续，但要求每章至少留下划线或反馈。

```

这个结论比“这个工作流很好”有用，因为它带了条件和下一步。

填卡时不要追求完整。3 分钟内写出第一版就够。


如果写完以后你发现“省下来的成本很虚，新增的成本很实”，这个工作流大概率要缩小或停用。


如果写完以后你发现“省下来的成本很实，新增成本有人接、有验证、有恢复”，它更可能净降熵。


### 7. 什么时候用 15 问，什么时候用 5 问


第 8 篇的 15 问适合三种场景：


* 你准备长期使用一个 AI 工作流。
* 它会影响钱、代码、客户、团队或关键判断。
* 它已经出过错，需要复盘。


这一篇的 5 问适合三种场景：


* 你刚试用一个新工具。
* 你觉得它有点方便，但说不清价值。
* 你想快速决定继续、缩小、加验证还是停用。


日常先用 5 问。重要场景再展开成 15 问。


### 8. 用这张卡看“下一章”这个动作


拿你刚才说的“下一章”做一个小例子。



```
对象：
用户说“下一章”，AI 生成熵增课程下一篇并同步 Reader。

它进入的系统：
个人交互式学习系统。

它省了哪 3 类成本？
1. 启动成本：不用重新描述课题。
2. 整理成本：AI 自动读取计划、上一篇和 Reader 反馈。
3. 同步成本：本地文章、计划、索引和 Reader 一起更新。

它新增了哪 3 类成本？
1. 反馈成本：用户需要划线、笔记或口头费曼。
2. 审查成本：用户要判断文章是否真的接住自己的理解状态。
3. 依赖成本：Reader 反馈和本地计划要持续连上。

错了以后：
- 谁发现？用户阅读时发现，或下一轮计划检查时发现。
- 谁负责？AI 负责修正文件和计划，用户负责指出理解偏差。
- 怎么恢复？通过本地 Markdown、计划记录和 Reader 链接追踪。

最小行动：
读完后划线 1 处最有用的判断，再写一句“这能用在哪个工作流”。

处理动作：
继续，但每章至少留下一个真实反馈信号。

```

这就是 3 分钟决策卡的用法：它不追求宏大解释，只要求你看清成本和下一步。


小结
--


* 第 8 篇的 15 问适合完整复盘，第 9 篇的 5 问适合日常快速判断。
* 3 分钟决策卡先问减少成本，再问新增成本，接着问错误发现、责任和恢复路径。
* 一个 AI 工作流如果不能压成最小行动，通常会增加阅读和判断负担。
* 最后的结论要落到处理动作：继续、缩小、加验证或停用。
* 你下一次可以直接拿一个真实工具填这张卡，不必先写长篇分析。
