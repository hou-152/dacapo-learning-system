这一篇要解决的问题
---------


这一篇只解决一个问题：怎么拿一个真实 AI 工作流，判断它到底是在净降熵、持平，还是净增熵。


正文
--


前面几篇已经讲过系统边界、信息加工、行动接口、工程熵、Git 和净降熵。现在要把这些东西压成一个动作：



> 
> 选一个真实 AI 工作流，画清楚它进入的系统，列出它减少和新增的成本，再决定是否保留、修改或停用。
> 
> 
> 


这一步很关键。很多人谈 AI 效率时会停在“它能做什么”。系统分析要多问一步：“它做完以后，谁来接住结果？”


### 1. 先选一个足够小的工作流


练习对象要小。对象越大，越容易变成泛泛而谈。


合适对象：


* 用 AI 帮你写一篇学习文章。
* 用 AI 总结一份行业报告。
* 用 AI 改一个函数。
* 用 AI 每天生成一份投资信息摘要。
* 用 agent 自动整理一个文件夹。
* 用 AI 把录音转成笔记。


不合适对象：


* AI 提升我的工作效率。
* AI 改变内容行业。
* AI 帮我学习。
* AI 重构我的知识系统。


前一组是工作流，后一组是愿望。工作流可以检查，愿望很难检查。


一个可检查的工作流，至少有 5 个部分：



```
输入 → AI 加工 → 输出 → 人类接手 → 反馈或恢复

```

少了“人类接手”和“反馈或恢复”，它通常只是一个生成流程，还没有成为稳定工作流。


### 2. 画出系统边界


第一步先问：这个工作流进入哪个系统？


系统可以是：


* 个人学习系统
* 内容生产系统
* 工程开发系统
* 投资判断系统
* 团队协作系统
* 文件管理系统


系统边界要写得具体一点。


比如：



```
对象：用 AI 生成下一篇熵增学习文章，并同步到 Reader
系统：个人交互式学习系统
目标：根据上一轮划线和笔记，生成下一篇文章，让学习继续推进

```

这样一写，后面就能判断它服务的是“连续学习”，还是只是在生产一篇文章。


### 3. 写出旧流程和新流程


净降熵要比较变化。没有旧流程，就很难判断新工具减少了什么。


旧流程可以这样写：



```
旧流程：
1. 人自己回看上一篇文章。
2. 人自己整理划线和笔记。
3. 人自己决定下一篇主题。
4. 人自己写下一篇。
5. 人自己维护学习计划。
6. 人自己复制到 Reader。

```

新流程可以这样写：



```
新流程：
1. AI 读取学习计划、上一篇文章和 Reader 划线。
2. AI 总结理解状态。
3. AI 生成下一篇文章。
4. AI 更新学习计划和索引。
5. AI 创建 Reader 文档。
6. 人在 Reader 里阅读、划线、写反馈。

```

比较旧流程和新流程，你才能看见成本移动到哪里。


### 4. 列出它减少的成本


接着列出这个 AI 工作流减少了什么成本。


继续用“生成下一篇学习文章并同步 Reader”作为例子。


它减少的成本：


* 整理成本：AI 帮你把上一轮划线和计划汇总起来。
* 结构成本：文章固定有反馈、问题、正文、小结、口头费曼、下一篇预告。
* 推进成本：你只要说“下一篇”或“08”，课程就能继续。
* 同步成本：本地文件和 Reader 入口可以同时维护。
* 记忆成本：学习计划保留当前进度、卡点、下一步和来源记录。


这些成本下降以后，你更容易保持学习连续性。


这里的核心收益很明确：AI 把“重新进入状态”的成本降下来了。


### 5. 列出它新增的成本


然后列新增成本。很多 AI 工作流的问题都藏在这里。


同一个例子里，它新增的成本可能有：


* 审查成本：你要判断文章有没有讲偏。
* 反馈成本：你需要划线或写笔记，否则下一篇会缺少真实信号。
* 格式成本：文章、计划、索引、Reader 都要保持一致。
* 依赖成本：如果 Reader 同步失败，反馈闭环会断。
* 风格成本：文章可能变得顺滑，但没有暴露你的真实卡点。
* 恢复成本：如果计划写错，需要知道哪里改了、怎么回退。


新增成本列出来以后，判断就更稳，不容易被“文章生成得很快”带偏。


### 6. 找到成本转移点


净降熵诊断最重要的一步，是找到成本转移点。


常见转移点有 5 个：



```
生产成本下降 → 审查成本上升
信息收集下降 → 判断成本上升
写作成本下降 → 反馈成本上升
自动执行上升 → 恢复成本上升
格式统一上升 → 维护成本上升

```

对当前例子来说，最大转移点是：



> 
> AI 降低了写课和整理成本，但把真实反馈成本留给了你。
> 
> 
> 


如果你只让 AI 一篇接一篇写下去，却不划线、不复述、不写反馈，这个系统会慢慢变成“顺滑内容生产”，学习闭环会变弱。


所以，第 8 篇不能继续加概念。它要逼系统进入练习状态。


### 7. 加上人类代价边界


一个工作流要净降熵，必须保护人的注意力、判断力和恢复能力。


你可以给它加 4 个边界：



```
范围边界：一次只推进一篇，不预生成未来文章。
验证边界：每篇都要读上一篇 Reader 反馈。
行动边界：每篇末尾只要求一个短口头费曼或一段学习反馈。
恢复边界：本地文件、学习计划、索引、Reader 链接都可追踪。

```

这些边界让 AI 工作流更像一个学习系统，而非内容流水线。


边界越清楚，人越敢把下一步交给工具。


### 8. 做出总判断


现在可以填总判断。



```
对象：用 AI 生成下一篇熵增学习文章，并同步到 Reader

减少的成本：
- 整理成本
- 结构成本
- 推进成本
- 同步成本
- 记忆成本

新增的成本：
- 审查成本
- 反馈成本
- 格式成本
- 依赖成本
- 恢复成本

关键转移点：
- AI 降低写课成本，但真实理解仍然要靠划线、反馈和口头费曼暴露出来。

已有降熵结构：
- 固定文章结构
- 学习计划
- 来源记录
- Reader 划线
- 本地文件
- 不创建未来占位文件

缺口：
- 口头费曼还没做
- 真实案例练习还没由你亲自完成

总判断：
- 当前是净降熵，但前提是你继续提供 Reader 划线、文字反馈或口头费曼。

```

这个判断有条件。条件就是：反馈必须回来。


没有反馈，AI 继续写也能产出文章，但学习系统的验证能力会下降。


### 9. 把综合练习变成你的模板


以后你可以直接复制下面这张表，评估任何 AI 工作流。



```
AI 工作流净降熵诊断表

1. 工作流名称：

2. 它进入哪个系统？

3. 它的输入是什么？

4. AI 做了哪一步加工？

5. 输出交给谁？

6. 人类接手后要做什么？

7. 错了以后怎么发现？

8. 错了以后怎么恢复？

9. 它减少了哪些成本？
   判断 / 验证 / 沟通 / 恢复 / 维护 / 其他

10. 它新增了哪些成本？
    阅读 / 审查 / 配置 / 误用 / 依赖 / 恢复 / 其他

11. 最大成本转移点是什么？

12. 它有没有降熵结构？
    schema / 引用 / 测试 / diff / 日志 / checklist / Reader 反馈 / Git / 其他

13. 它有没有最小行动？

14. 总判断：
    净降熵 / 持平 / 净增熵

15. 下一步调整：
    保留 / 缩小范围 / 增加验证 / 增加恢复路径 / 停用

```

这张表的用途是让你看见成本移动。


看见成本移动，你就更少被“AI 做得更多”吸引。


小结
--


* 综合练习要从一个足够小的 AI 工作流开始，先写清输入、加工、输出、人类接手和恢复路径。
* 净降熵判断必须比较旧流程和新流程，否则看不见成本减少和成本转移。
* 当前课程生成工作流能降低整理、结构、推进、同步和记忆成本，但它依赖你的划线、反馈和口头费曼。
* 如果反馈断掉，学习闭环会变弱，AI 产出会逐渐偏向内容生产。
* 最小行动是：选一个你真实使用的 AI 工作流，填完上面的 15 问诊断表。
