# 04｜从语言模型到具身智能：六个台阶各自跨过什么

## 这一篇要解决的问题

你在上一篇反馈里希望回到 AGI 主线，系统了解语言模型、CoT、Agent、持续学习、AI 自我迭代和具身智能。这一篇先搭一张总地图：每一层增加了什么能力，解决了上一层的什么限制，哪些环节已经能够工程化，哪些仍是材料中的路线判断。

## 正文

### 先看整张地图

材料把技术路线概括为：

> 语言模型 → CoT → Agent → 持续学习 → AI 参与迭代下一代 AI → 具身智能

这条线可以用三个问题来理解：

1. AI 能处理多复杂的信息？
2. AI 能把能力延伸到多长的任务和时间范围？
3. AI 能否从语言世界进入组织环境与物理世界？

六个环节分别扩大了一种边界：

| 环节 | 新增的核心能力 | 主要跨过的边界 | 仍然留下的问题 |
|---|---|---|---|
| 语言模型 | 从大量数据中学习语言与知识模式，根据上下文生成结果 | 从固定程序走向通用表达和任务迁移 | 能力受训练结果与当前上下文约束 |
| CoT | 在一次回答中投入更多推理步骤 | 从直接作答走向多步推演 | 推理结束后，经验通常没有沉淀到下一次任务 |
| Agent | 围绕目标调用工具、观察结果、调整动作 | 从回答问题走向执行任务 | 跨任务的记忆、经验积累和稳定性仍然有限 |
| 持续学习 | 长期吸收环境、反馈和经验，改变后续行为 | 从一次性任务走向长期适应 | 错误积累、灾难性遗忘、权限和验证都很难 |
| AI 自我迭代 | 参与数据、代码、实验和评测，帮助研发下一代 AI | 从使用工具走向加速工具自身的研发 | 加速效果取决于评测、资源、人类目标和安全边界 |
| 具身智能 | 感知物理环境并采取现实动作 | 从信息世界走向物理世界 | 现实环境的连续性、不确定性和安全成本更高 |

这张表表达的是能力依赖关系。现实研发更像一张并行展开的网络：机器人团队可以在持续学习完全成熟前研究具身智能，Agent 团队也可以借助外部记忆改善长期任务。因此，“六级阶梯”适合用来理解材料中的战略顺序，暂时不能当作行业公认的唯一路线。

### 第一层：语言模型提供通用能力底座

语言模型先把大量训练数据压缩进参数，再根据当前上下文生成后续内容。它获得了语言理解、知识调用、代码生成和一定程度的任务迁移能力。

可以把它想成一位知识面很广、进入会议室后才开始接收项目背景的专家。材料完整、任务清楚时，它能迅速工作；组织里的隐性背景缺失时，它只能根据眼前信息推断。

语言模型扩展了“能处理什么”。它的时间范围主要由训练阶段和本次上下文决定。

### 第二层：CoT 增加一次任务里的思考长度

`CoT` 是 `Chain of Thought`，可以理解为多步推理过程。模型面对数学题、规划题或复杂判断时，通过中间步骤分解问题、保留阶段结果，再形成答案。

比如直接问“这个项目值不值得做”，模型容易快速给出宽泛结论。把任务拆成市场需求、资源约束、机会成本、失败条件和验证动作后，它获得了更长的计算路径。

`CoT` 扩展了“这一次能想多深”。这些推理步骤的作用范围通常停留在当前任务；若要改变模型参数或沉淀为几个月后的组织经验，还需要额外机制。

### 第三层：Agent 把推理接到行动和反馈上

`Agent` 通常由几个部分构成：

1. 一个目标；
2. 负责理解和决策的模型；
3. 浏览器、代码执行器、数据库等工具；
4. “行动—观察—调整”的循环；
5. 停止条件和权限边界。

语言模型可以告诉你怎样订机票；Agent 可以查询航班、比较价格、填写信息，并在支付前等待确认。它的关键变化发生在行动回路：输出文字只是中间步骤，环境反馈会决定下一步动作。

Agent 扩展了“这一次能做多远”。一个 Agent 即使能连续执行 30 步，也可能在下周遇到相似任务时再次犯同一个错误。执行长度和经验积累属于两个不同维度。

### 第四层：持续学习要求经验改变未来行为

“持续学习”这个词容易混入几种不同能力：

| 能力 | 发生了什么 | 例子 |
|---|---|---|
| 长上下文 | 把更多历史内容放进本次输入 | 把过去 3 个月的会议记录一次性交给模型 |
| 外部记忆 | 把事实保存到数据库，需要时再取回 | 记住“小王负责采购” |
| 检索增强 | 从文档库查出相关知识，再交给模型使用 | 回答前检索公司制度 |
| 工作流更新 | 人或系统修改规则、提示词与工具 | 失败后给审批流程增加一步检查 |
| 模型或策略适应 | 经验稳定改变系统以后处理同类问题的方式 | 多次项目后学会识别本公司的风险信号 |

材料用“新员工工作两个月后知道小王是谁”说明持续学习的重要性。这个例子只证明了长期组织背景很重要，还不足以单独证明模型参数必须持续更新。

如果系统通过数据库查到“小王负责采购”，它完成了记忆调用。如果系统在多次协作后发现“小王处理紧急订单更可靠”，验证这条经验，并在以后自动调整任务分配，它开始接近系统层面的持续学习。

持续学习的难点也由此出现：系统怎样判断一次反馈是否可靠？错误经验怎样撤销？新知识怎样避免覆盖旧能力？谁有权让经验进入长期记忆或模型？这些问题共同决定“学习”能否安全地发生。

材料把持续学习称为 Agent 之后的主要瓶颈，并承认尚未形成成熟方法。这里属于材料中的技术判断，课程现有证据无法把它升级为行业定论。

### 第五层：AI 自我迭代形成研发反馈回路

AI 参与下一代 AI 的研发，可以形成这样的循环：

> 当前模型辅助整理数据、编写代码、设计实验和分析失败 → 研发效率提升 → 下一代模型变强 → 更强的模型继续参与研发

当每一轮改进都缩短下一轮实验时间，整体进展可能呈现非线性。材料把这种过程称为“AI 加速 AI”，并把它与逐渐到来的“奇点”联系起来。

这里需要区分两个强度：

- 辅助研发：AI 承担部分编码、检索、标注、评测和分析工作，人类仍然设定目标并审核结果。
- 高度自主迭代：AI 能提出有效研究方向、执行实验、判断结果并稳定改进下一代系统。

两者之间还隔着可靠评测、算力与数据供给、实验可复现性、错误控制和目标治理。AI 参与研发已经可以成为工程流程；它能否形成稳定、自主、持续加速的闭环，仍待验证。

### 第六层：具身智能把能力接入物理世界

具身智能要求系统通过传感器感知环境，通过机器人或其他设备采取动作，再从现实结果中获得反馈。

在语言环境里，生成一段错误文字通常可以重新修改。在物理环境里，机械臂抓错物品、车辆判断失误或护理机器人动作过大，都可能产生即时且不可逆的成本。因此，具身智能还要面对实时性、空间理解、硬件磨损、现实安全和责任归属。

材料把具身智能放在路线末端，理由是：持续学习和 AI 自我迭代成熟后，系统才能更广泛地承担现实世界的人力需求。这是 DeepSeek 材料中的路线选择。另一种合理路径是让具身系统更早进入真实环境，用物理反馈反过来推动学习。现有材料无法判定哪种顺序最终占优。

### 把六层放进一个具体例子

设想一个公司采购助理：

1. 它能阅读采购制度并回答问题：语言模型。
2. 它能把供应商选择拆成价格、交期、质量与风险：CoT。
3. 它能查询库存、发送询价、比较报价并提交审批：Agent。
4. 它能从多次履约结果中更新供应商风险判断：持续学习。
5. 它能帮助研发团队发现评测缺口、改进采购 Agent 的下一版本：AI 自我迭代。
6. 它能控制仓库机器人完成收货、验货和搬运：具身智能。

这个例子也展示了每一层的验收标准：验收应落到它完成的新增动作上，响亮的名称本身不构成能力证明。

## 小结

1. 语言模型提供通用能力底座，CoT 增加单次任务中的推理长度，Agent 把推理连接到工具、行动和环境反馈。
2. 长上下文、外部记忆、检索增强和持续学习属于不同能力；经验能否稳定改变未来行为，是判断“学习”的关键线索。
3. AI 自我迭代依赖可靠评测、资源供给和错误控制，辅助研发与高度自主迭代之间仍有很长距离。
4. 具身智能把 AI 接入物理世界，也带来实时性、安全性和不可逆成本。
5. 六级阶梯是材料中的战略路线。现实技术可能并行推进，最终顺序仍待验证。
