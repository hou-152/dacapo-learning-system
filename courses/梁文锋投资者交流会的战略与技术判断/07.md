# 07｜低成本能拉出“斩杀线”吗

## 这一篇要解决的问题

你提出了一条明确的非对称竞争路线：算力落后时，避免复制对手的规模路径，用低成本推动应用、本地部署和市场重估。这一篇先校正相关事实，再检验低成本在什么条件下能形成“斩杀线”，又会在哪些地方失效。

## 正文

### 先把市场事件校准

你记忆中的事件存在三个混合点：

| 你的记忆 | 核对结果 |
|---|---|
| `DeepSeek R3` | 官方发布的是 `DeepSeek-R1` |
| 去年 2 月发布 | 官方发布日期为 2025 年 1 月 20 日 |
| “GPT 股票”下跌 20% | `GPT` 是模型名称；2025 年 1 月 27 日，NVIDIA 股价下跌接近 17%，纳斯达克综合指数下跌 3.1% |

DeepSeek 的[官方发布记录](https://api-docs.deepseek.com/news/news250120/)确认了模型名称和发布日期。1 月 27 日的市场数据来自 [AP 对当日收盘的记录](https://apnews.com/article/wall-street-stocks-dow-nasdaq-5d20431d9fc3ac27d054709cf4d2d1a0)。

这个事件可以支持一条较窄的判断：

> DeepSeek-R1 改变了市场对“先进 AI 能力需要多少计算投入”的预期，进而冲击了部分 AI 基础设施公司的估值。

单日股价反应表达投资者预期变化，无法单独证明某种成本路线已经摧毁竞争对手。

### 低成本来自一套效率系统

你把“低成本”与“参数比较低”连接起来，这里需要拆开。

DeepSeek 官方仓库显示，完整的 `DeepSeek-R1` 有 671B 总参数，每个 token 激活 37B 参数。它采用 `MoE` 架构，通过每次只激活部分专家降低计算量。官方同时开放了 1.5B、7B、8B、14B、32B 和 70B 的蒸馏模型。[模型参数和蒸馏版本可以在官方 GitHub 中核对](https://github.com/deepseek-ai/DeepSeek-R1)。

所以，低成本可能来自多条路径：

1. 每次只激活部分参数；
2. 改进模型架构和训练方法；
3. 提高算子、通信和集群利用率；
4. 使用缓存、批处理和量化；
5. 把大模型能力蒸馏进较小模型；
6. 针对任务选择足够用的模型。

总参数量可以很大，单次推理成本仍然得到控制。企业本地部署时使用的也可能是蒸馏版或量化版，与完整 R1 属于不同部署对象。

### “几块显卡就够”需要补齐部署条件

官方仓库给出了用 2 路张量并行启动 32B 蒸馏模型的示例，但它没有承诺任意两块显卡都能满足企业生产要求。实际资源取决于：

- 模型参数量；
- 权重精度和量化方式；
- 上下文长度；
- 并发用户数；
- 输出长度；
- 延迟目标；
- 显卡显存；
- 是否还要微调。

小模型确实更适合一部分本地任务，尤其是分类、抽取、检索编排、固定流程和领域问答。B 端选型时，合理目标是找到“通过业务评测的最小模型”。

如果 7B 模型只能完成 70% 的采购审核，32B 模型可以完成 92%，而业务要求至少 90%，那么 7B 的硬件成本再低也没有完成任务。成本比较应落到“每次成功任务的总成本”，其中还包括人工复核、错误返工、部署维护和风险损失。

### 少算力团队仍然需要实验

你把“更大模型、更多实验、更好数据”合在一起视为梭哈。三者的风险结构其实不同：

| 投入方向 | 风险特征 | 适合的做法 |
|---|---|---|
| 直接训练超大模型 | 单次投入大，失败代价高 | 等训练方案成熟后再扩大 |
| 小规模效率实验 | 单次投入小，结果高度不确定 | 多人并行探索，快速淘汰 |
| 高质量数据 | 积累慢，效果依赖标准 | 持续建设，反复复核 |

少算力团队更需要提高实验的“信息收益”：每消耗一单位算力，尽量回答一个关键问题。它可以先在小规模上验证架构和数据方法，再把有限的大规模训练机会用于已经获得证据支持的路线。

这种打法仍然有风险，但它属于受限资源下的投资组合：

- 大部分资源维持确定性改进；
- 小部分资源探索高赔率方案；
- 达到验证门槛后再增加投入；
- 失败方案及时停止。

一次性押注未经验证的大模型接近梭哈。小成本、多轮次、可停止的实验更接近购买期权。

### 成本“斩杀线”成立需要六个条件

你提出的“用低成本拉出斩杀线”是一个有力量的竞争假设。它要转化成可检验判断，需要同时观察六个条件：

| 条件 | 要检查的问题 |
|---|---|
| 能力接近 | 低价产品能否完成客户的核心任务 |
| 成本优势持久 | 优势来自架构和工程积累，还是短期补贴 |
| 需求对价格敏感 | 降价能否显著增加使用量和客户数量 |
| 供给可以扩张 | 用量增长后，服务是否仍然稳定 |
| 切换成本较低 | 用户能否方便地从现有供应商迁移 |
| 对手难以跟进 | 对手能否降价、交叉补贴或推出小模型 |

缺少其中几项时，低成本可能只产生短期震动。

例如，大公司可以用其他业务利润补贴模型服务；客户也可能因为生态、数据迁移、合规、品牌和稳定性继续留在原平台。此时，价格优势能够打开一部分市场，却很难直接迫使对手退出。

因此，“斩杀线”可以改写成一个更可操作的定义：

> 当竞争对手维持同等任务质量时，其长期可持续成本高于市场可接受价格，同时又无法通过生态、差异化或补贴弥补差距，成本优势才可能进入生存线。

### 低价也可能扩大整个市场

低价带来的结果至少有四种：

1. **替代**：用户从昂贵模型切换到便宜模型。
2. **扩容**：原本舍不得使用的任务开始调用 AI。
3. **升级**：Agent 可以执行更多步骤、调用更多工具。
4. **商品化**：模型价格下降，利润向应用、数据和分发环节移动。

第三种与你说的 Agent 和 Harness 发展直接相关。复杂 Agent 一次任务可能调用模型几十次甚至更多。单次调用成本下降后，原本经济上不可行的长流程开始有机会落地。

但 Agent 和 Harness 早于 R1 已经存在。低价和开放模型降低了试验门槛，能够加速它们的发展；生态能否繁荣，还取决于工具接口、评测、稳定性、权限、可观察性和业务需求。

“模型层倒逼应用层”可以进一步写成一条条件链：

> 模型能力达到任务门槛 ＋ 调用成本下降 ＋ 开放接口和权重 ＋ 应用团队找到高价值场景 → Agent 与 Harness 的实验数量增加

其中任一条件缺失，应用层增长都可能低于预期。

### 低成本战略的飞轮怎样闭合

一条完整的成本飞轮可以这样运行：

> 效率研究 → 训练和推理成本下降 → API 与本地部署门槛下降 → 使用量和应用实验增加 → 获得更多收入、反馈与生态支持 → 继续投入效率研究

这条飞轮需要三个闭环条件：

1. 新增用量能够转化成收入、反馈或生态价值；
2. 低价服务仍然保留足够利润支持研发；
3. 模型层在开放和降价后仍然拥有可持续的能力或效率优势。

如果价格下降快于成本，飞轮会消耗现金。如果开源伙伴获得大量价值，模型提供方却无法获得收入、反馈或行业位置，生态扩张也未必反哺研发。

这正好回到前几课讨论的“克制”：DeepSeek 希望让应用伙伴保留利润，同时从模型服务、效率和生态位置中获得合理回报。低成本在这里承担两种功能——它既是竞争工具，也是利益分配机制。

### 你的判断可以升级成一张检验表

以后再说“某个低成本模型会打穿市场”，可以先填 5 个变量：

| 变量 | 需要填写的内容 |
|---|---|
| 目标任务 | 客户具体用模型完成什么 |
| 达标质量 | 业务可以接受的最低成功率 |
| 每次成功任务的总成本 | 模型、人工复核、返工、部署和风险合计 |
| 切换障碍 | 数据、流程、生态、合规和人员培训 |
| 对手反应 | 跟价、小模型、补贴、绑定生态或质量升级 |

你可以用这张表重新表达自己的观点：

> DeepSeek 的成本优势最可能先在哪一类任务上形成“斩杀线”？C 端通用聊天、Agent 高频调用，还是 B 端本地部署？请选一个，并说明其任务门槛和对手最可能的反应。

DeepSeek 的成本优势主要在 C 端通用聊天。我记得 V4 Flash 是调用最多、最频繁的那个模型，因为它便宜，就算你把整个 workflow 拉满，它也很便宜，成本低。

作为 C 端用户，我很喜欢用它，效果不错，勉强过得过去，谁会跟钱过不去呢？

所以，这叫做用价格去打下沉市场。有没有可能，我只是为了修复利润，让回本周期变长一点？也就是说，我是走量的，慢慢回本。

但是任务门槛是什么？首先我要便宜，我要有知名度，还要用得过去。那对手是什么呢？对手跟我卷价格，我也跟你卷价格，没有问题。

## 小结

1. 2025 年 1 月发布的是 DeepSeek-R1；随后 NVIDIA 单日下跌接近 17%，市场反应体现预期冲击，不能直接证明竞争终局。
2. 完整 R1 拥有 671B 总参数和 37B 激活参数，低成本来自架构、激活方式、工程效率、蒸馏和部署策略等多种机制。
3. 少算力团队可以通过小规模、多轮次、可停止的实验提高信息收益；一次性训练未经验证的超大模型才具有更强的梭哈特征。
4. 成本“斩杀线”依赖能力接近、优势持久、需求敏感、供给扩张、低切换成本和对手难以跟进。
5. 低价也可能扩大市场并推动 Agent 使用量，能否形成飞轮取决于收入、反馈和生态价值能否回流模型研发。
