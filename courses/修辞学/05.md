# 05｜论证：怎样让判断站得住

## 这一篇要解决的问题

上一篇你的 Reader 反馈里出现了一个关键推进：你想到能不能设计一个 AI Agent，只给它一个判断，它就自动拟合内容和修辞。这个想法已经进入 logos 的核心：一个判断要站得住，需要被证据、机制、反例和动作支撑。

## 正文

### 本篇基于的反馈

我从你的 Reader 笔记里看到 4 个理解状态：

1. 你认可“降低被攻击感”的写法，说明你已经开始看见情绪处理和论证接收之间的关系。
2. 你高亮了“信任、具体场景、可执行出口”，说明你在关注一个判断成立所需的支撑条件。
3. 你提出“给一个判断，让 AI 自动拟合内容和修辞”，这已经接近写作 Agent 的任务定义。
4. 你把“第二句更容易执行”标成“最小 MVP”，说明你在寻找可开始、可验证、可复用的表达单元。

所以这一篇讲 logos 时，不写成逻辑学术语课，先讲怎样把一个判断做成可站立、可展开、可交给 Agent 的结构。

### 1. logos 先看判断有没有骨架

一篇文章的论证，起点通常是一句判断。

比如：

> 收藏越来越多，作品却没有变多。

这句话有力量，因为它有一个反差：输入增加，输出没有增加。

但它还只是一个判断。要让它站得住，需要补 4 个支点：

1. 场景：这个判断发生在哪里？
2. 证据：读者凭什么相信它存在？
3. 机制：为什么会这样？
4. 出口：读者下一步能做什么？

把这 4 个支点补上，就会变成一段更稳的论证。

场景：

> 你每天都在补课、收藏、整理资料，却越来越不敢开始写。

证据：

> 收藏夹越来越厚，真正发布的文章、课程片段、销售页和交付清单没有增加。

机制：

> 输入越多，选择项越多；行动标准不清楚时，选择项会变成压力。

出口：

> 今天只选一段材料，写 3 行：它能帮我判断什么、改什么、验证什么。

这段内容没有复杂术语，但它已经有 logos：判断清楚，证据可看，机制可解释，动作可执行。

### 2. 判断要能被读者检查

很多文章的问题出在判断太满，检查入口太少。

比如：

> 大多数人都在用学习逃避行动。

这句话有冲击力，但读者很难检查。它会引发认同或反感，却很难带来稳定理解。

可以换成可检查版本：

> 如果一个人持续收藏课程和方法，却很少把它们变成作品、销售页、交付清单或复盘问题，他的卡点可能已经从学习不足转向行动标准不清。

这句话更长，但更稳。它给了条件，也给了可观察信号：

- 持续收藏课程和方法。
- 很少形成作品、销售页、交付清单或复盘问题。
- 卡点可能从学习不足转向行动标准不清。

读者可以拿它对照自己。符合，就继续读；不符合，也知道这句话暂时讲的场景和自己有距离。

logos 的一个基本要求就是：判断要给读者检查入口。

### 3. 机制比结论更能形成信服

结论告诉读者你站在哪里，机制告诉读者你怎么走到这里。

比如：

> 你应该少收藏，多输出。

这是一句结论。

加上机制以后：

> 收藏会增加可选项。可选项变多以后，如果没有行动标准，大脑会不断比较、犹豫、补材料，最后输出被延后。

读者听到机制后，会更容易接受结论：

> 所以今天先不新增收藏，打开最近一条笔记，把它改成一个正在使用的小判断。

这个顺序很重要：

1. 先描述现象。
2. 再解释机制。
3. 最后给行动。

很多有力量的文章，强就强在机制讲得清楚。它让读者感觉自己看见了事情运转的齿轮。

### 4. 反例能保护论证

一篇文章如果只顺着自己的判断往前推，容易显得很满。读者心里会出现反例：

> 有些人收藏多，后来确实输出了。

> 有些阶段就是需要大量输入。

> 有些内容适合安慰，不一定要立刻行动。

这些反例如果完全不处理，读者会自己在心里处理。处理结果可能是：这篇文章说得太绝对。

更稳的写法是主动给边界：

> 大量输入本身有价值。问题发生在输入长期无法进入作品、项目、交付或决策。这个时候，继续补材料会让行动标准更模糊。

这句话保护了论证。它承认输入的价值，同时指出问题发生的条件。

反例的作用是给文章增加边界。边界清楚以后，读者更愿意相信你的判断。

### 5. 给 Agent 的最小论证模板

你提到“给一个判断，让 AI 自动拟合内容和修辞”。这个想法可以先做成一个最小 MVP。

不要先追求自动写完整文章。先让 Agent 根据一个判断，生成一张论证卡。

模板可以这样：

```markdown
## 判断
我想表达的核心判断是什么？

## 场景
这个判断发生在哪个具体场景？

## 读者
谁最容易遇到这个问题？他现在处在什么状态？

## 证据
有哪些可观察信号、例子、数据或过程？

## 机制
为什么会发生？中间的因果链是什么？

## 反例
在哪些情况下这个判断不成立，或需要调整？

## 动作
读者看完以后，能做哪个最小动作？

## 修辞入口
开头用场景、反差、问题、故事，还是一句判断进入？
```

这张卡就是 logos 的工程化版本。它把“观点”拆成 Agent 能处理的结构。

比如输入判断：

> 收藏越来越多，作品却没有变多。

Agent 应该先生成：

| 模块 | 内容 |
|---|---|
| 场景 | 学了很多课、存了很多笔记，但迟迟没有发布或交付 |
| 读者 | 想写作、做课、做产品，但总觉得准备不足的人 |
| 证据 | 收藏夹、笔记、课程列表增长；公开作品和交付物增长慢 |
| 机制 | 输入增加带来选择项增加，行动标准不清导致犹豫 |
| 反例 | 项目初期需要集中输入；研究型任务需要长时间积累 |
| 动作 | 今天只把一条笔记改成一个可用判断 |
| 修辞入口 | 先写具体处境，再给反差判断 |

有了这张卡，再让 AI 写正文，质量会稳很多。它会沿着论证骨架展开，减少凭感觉续写。

## 小结

- logos 关心判断怎样站得住：场景、证据、机制、反例和出口都要跟上。
- 判断要给读者检查入口，条件和可观察信号越清楚，信服感越稳。
- 机制比结论更能形成信服，它让读者看见事情怎样发生。
- 反例能保护论证，让文章边界更清楚。
- 给写作 Agent 的最小 MVP，可以先做“论证卡”，再让它拟合内容和修辞。
