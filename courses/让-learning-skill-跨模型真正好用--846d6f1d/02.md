# 02｜能力不是模型分数，而是接口设计的结果

## 要解决的问题

你在上一课写道：

> 可能用一个比较聪明的模型，不用工程治理也能做得很好，因为它有反复的 review 和反复的推测；但是用一个比较差的模型，它就做不到。

这句话已经抓住了关键，但还差一个可设计的中间层：**为什么同一个模型换一种接口，表现会突然变好或变坏？**

本课实际改变上一课的切入方式：不再只讨论“模型够不够聪明”或“治理要不要存在”，而是用机器人控制案例把责任拆开，判断哪些困难应该留给模型，哪些困难应该由 Harness、工具和确定性程序先接住。

本课依据 AI 内参对 Anthropic 机器人研究的加工 Markdown。文中的实验数字和结论是材料转述；作者主张是“机器人能力同时取决于模型、身体和控制接口”，课程重构则是把这个机制映射到 Learning Skill，不把机器人实验冒充为学习效果证据。

本课重构的教学改变是：下一课从机器人控制接口这个具体案例切入，把同一模型在低层控制、程序化控制、预训练策略和高层导航接口上的差异，映射成 Learning Skill 中哪些责任应由 Harness 承担、哪些责任应留给模型；同时给出一个记录总人工成本的最小实验。

## 正文

### 同一个模型，换接口就像换了题目

材料把机器人任务拆成几种控制接口：

1. 直接输出关节力矩或力；
2. 编写 Python 控制器；
3. 调用已经训练好的高层策略，只给出速度、方向等命令；
4. 设计奖励和训练流程，让强化学习自己找到策略。

这些接口面对的是同一个模型，却把不同难度交给了模型。直接输出低层力矩，模型必须同时处理重力、惯性、接触和实时性；调用高层步态策略时，模型只需要看图像、判断目标，再给出前进或转向命令。模型没有突然“变聪明”，只是接口替它承担了不同的工作。

机制链可以写成：

~~~text
低层责任全部交给模型
→ 实时约束与错误累积超过语言接口的承受范围
→ 换成程序、预训练策略和高层命令接口
→ 模型把能力集中在目标判断、规划与纠错
~~~

材料报告，在真实运动控制中，机器人可能需要约 83 Hz 的连续控制，而当时模型调用速度远低于这个数量级。因此，直接让语言模型充当电机回路，本身就是一个不匹配的接口。把低层物理交给预训练策略后，同一个模型反而能够完成导航、搜索和闭环纠错。

这里有一个完整例子：

- **可观察的事实是**：模型直接输出关节动作时，某个高自由度人形机器人几乎无法稳定站立；换成预训练步态策略后，模型只输出速度和方向，便能在部分任务中完成导航。
- **自动解释或课程推断是**：失败不一定说明模型“不会机器人”，也可能说明它被要求承担了不适合语言模型的实时控制责任。
- **结果与下一步动作是**：评估模型前先固定接口；如果接口改变，分数不能直接横向比较。工程师应先决定哪些物理约束由策略、工具或程序承担，再评价模型剩下的判断能力。

### 这对 Learning Skill 意味着什么

把这个机制搬回交互式学习，可以得到四类责任：

| 责任 | 更适合由谁承担 | 例子 |
|---|---|---|
| 语义理解与教学判断 | 模型 | 找出学习者唯一关键缺口，选择推进、桥接或重讲 |
| 状态、顺序与证据完整性 | Harness | 保存原答、绑定课文哈希、阻止没有反馈就续课 |
| 目标与取舍 | 学习者 | 决定这轮要解决什么真实问题，判断时间是否值得 |
| 可观察验收 | 两者协作 | Harness 自动记录时间和事件，模型设计迁移任务，学习者完成任务 |

如果把第一行也全部硬编码，系统会失去自适应；如果把第二行全部交给模型，弱模型就可能漏记回答、跳过证据或把“生成”误判为“掌握”。好的接口不是让 Harness 代替模型教学，而是让模型不必每一轮都重新发明状态机。

这正是你上一课说的“工程治理”的中间含义：治理不是学习目的，而是把容易反复出错、可以确定检查的部分从模型的工作记忆中移出来。模型因此可以把注意力用在解释、诊断和迁移，而不是反复确认自己有没有忘记上一条回答。

### “更便宜”必须连同接口一起计算

如果一个低成本模型需要自己记住课程指针、拼接所有历史、判断哪些回答已经消费，再同时写出教学正文，那么它的低价格很可能被纠偏时间吃掉。反过来，如果 Harness 自动提供当前课、完整回答闭包和允许的下一步，模型只需完成语义判断，便可能在较低成本下达到足够的效果。

因此，比较两个模型时，至少要固定四个条件：

1. 相同的来源和任务锚点；
2. 相同的可用接口与工具；
3. 相同的学习者时间预算；
4. 相同的新情境迁移测试。

然后自动记录：

- 模型实际运行时间；
- 学习者等待和纠偏时间；
- 需要人工重述或返工的次数；
- 原答到下一课的有效能力变化。

这些记录不是学习本身，而是帮助我们发现“便宜账单是否换来了更贵的人力”。真正的胜负仍然由学习者能否独立完成新任务决定。

### 接口设计也有边界

接口不是万能药。它不能修复错误的任务锚点，也不能把错误的来源变成真理；把更多规则塞进 Harness 还可能增加启动时间、限制模型探索，甚至让学习者觉得自己在填写表格。

所以每次把责任从模型移到 Harness，都要回答：

- 这项责任是否可以稳定、低成本、可重复地检查？
- 移走它后，模型是否获得了更多用于教学判断的空间？
- 学习者是否因此少做了一项机械工作，而不是多看一张配置表？

如果答案都是否，新增的实体就应当删掉。这是剃刀原则在接口设计里的用法。

## 费曼到任务

请为一次 dbs-learning 学习回合画出一个四行责任表。每行只写“谁负责什么”，并在最后加一句：

> 哪一项责任绝不能完全自动化？为什么？

四行必须分别是：模型、Harness、学习者、验收者。请用一个你真实会使用的学习主题来填写，不要只复述机器人案例。

## 检查站

1. 为什么不能用“模型在低层机器人控制上的分数”直接代表它在高层导航或教学中的能力？
2. 如果把“保存状态和绑定回答”从模型移到 Harness，你认为减少了哪一种错误，又可能增加哪一种摩擦？

回答后，我会检查你的责任分工是否真的改变了接口，而不是把所有事情重新命名一遍。
