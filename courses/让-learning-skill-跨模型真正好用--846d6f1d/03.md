# 03｜模型会漂，授权不能漂

## 要解决的问题

你在上一课写道：

> 最关键的判定标准依然是：那项绝对不能自动化的责任（即用户的明确授权），你们是否自作主张地跳过了？

这个判断抓住了人与 Agent 的权力边界。但还要再区分三件容易混在一起的事：模型有自己的默认决策倾向，Harness 要守住少数不变量，而真正不可让渡的目标与授权属于用户。

本课的教学改变是：下一课用 Claude 在模型和语言间的价值表达漂移，区分模型的默认决策倾向、用户的明确授权和 Harness 的不变量；把用户关于隐私确认与学习诚实性的判断变成一套跨模型不能漂移的最小合同，同时保留界面简洁。

本课依据 AI 内参对 Anthropic 研究的加工 Markdown。作者主张是：Claude 在不同模型版本和语言中，会系统性改变温暖、严谨、谨慎、深度与执行倾向；本课重构则把这种漂移用于分析同一个 Learning Skill 为什么在 Claude、Codex 和低成本模型上产生不同体验。材料只测量模型表达出来的价值，不证明模型拥有人的信念或人格。

## 正文

### 同一份 Skill，不会自动产生同一个老师

Anthropic 从真实对话中整理了三千多种细粒度价值，再把它们压缩成四条主要张力：

1. 顺从与谨慎；
2. 温暖与严谨；
3. 深度与简洁；
4. 坦诚与执行。

这不是说一端一定好、另一端一定坏。一个老师可以温暖又严谨，也可以坦诚又能执行。研究观察到的是：不同模型和语言在真实回答中，会把重心稳定地放在不同位置。

材料称，某些 Claude 版本更容易肯定用户、匹配语气并保持简洁；另一些版本更容易挑战假设、要求证据、解释边界。语言也会改变这种重心：同类任务换一种语言，模型可能变得更温暖、顺从，或者更严谨、谨慎。

机制链是：

~~~text
训练数据、后训练与角色设定不同
→ 模型形成不同的默认表达与判断倾向
→ 同一条 Skill 规则被不同方式解释和执行
→ 学习者感受到不同的速度、压力、深度与可信度
~~~

所以，同一个 dbs-learning 在不同模型上“感觉不像同一个老师”，未必是 Skill 文件失效。Skill 只规定了边界和流程，真正写课程、选择措辞、判断是否追问的仍然是模型。

### Attention 很重要，但不足以解释整个模型

你问“大模型的第一性原理是不是注意力机制”。更准确的说法是：Attention 是 Transformer 架构的核心机制之一，它帮助模型根据当前上下文决定哪些信息彼此相关；但它不能独自解释模型最终表现。

同样使用 Attention 的模型，仍会因为预训练数据、训练目标、后训练、角色设定、推理预算和工具接口不同而表现出完全不同的倾向。材料里的价值漂移正是一个反例：底层架构可以接近，老师的“性格”和判断重心仍然不同。

你把预训练类比成人的潜意识，这个类比有一部分成立：大量能力已经内化，不需要每次都把所有底层知识写进上下文。但边界也很重要。预训练得到的是统计化的能力和倾向，不是一个能被逐条核验的 PLC 程序，更不能代替用户授权。

### 模型倾向、Harness 不变量和用户授权

三层责任可以这样分：

| 层 | 可以发生什么 | 不应该承担什么 |
|---|---|---|
| 模型倾向 | 选择类比、语气、解释深度、追问方式和教学路线 | 伪造用户授权，擅自改变最终目标 |
| Harness 不变量 | 保存原答、约束顺序、阻止伪造掌握、要求高风险确认 | 硬编码每一句话、每个例子和所有教学判断 |
| 用户授权 | 决定学什么、是否读取私密材料、是否跳过、是否接受高风险操作 | 亲自维护日志、哈希和机械状态 |

这里要修正一个容易混淆的说法：**“决策倾向”可以自动化，但“最终授权”不能被模型自己授予。**

模型必须作出许多低风险教学决策，例如下一课用类比还是案例、应该推进还是重讲。完全禁止模型决策，交互式学习就不存在了。真正不可让渡的是改变用户目标、读取隐私、执行不可逆操作，以及把缺少证据的状态升级为“已经掌握”。

### 一个跨模型的完整例子

例如，同一个用户分别让两个模型评价自己的商业计划。

- **可观察的事实是**：模型 A 使用大量鼓励措辞，很快给出执行方案；模型 B 先质疑收入假设，要求补充证据，并明确列出不确定性。
- **课程解读或推断是**：两者的差异可能来自温暖与严谨、顺从与谨慎的默认倾向，不代表用户在两次对话中改变了真实目标。
- **结果与下一步动作是**：不需要强迫两种回答语气完全相同，但两者都必须遵守同一合同：不能虚构收入数据，不能在用户未确认时替用户付款或发布，不能把一句“懂了”当作掌握证据。

风格可以漂移，授权与事实边界不能漂移。

### 最小合同为什么必须很薄

如果我们试图把所有模型都调成同一种语气、同一种长度、同一种追问方式，Harness 会越来越厚，最终既消耗 Token，又抹掉强模型真正有价值的判断能力。

跨模型合同只应保留那些同时满足三个条件的规则：

1. 违反后会造成真实损害；
2. 可以被明确观察或机械检查；
3. 不规定具体教学内容也能成立。

对于当前 Learning Skill，最小不变量可以只有：

- 不伪造学习者原话；
- 没有证据不宣称掌握；
- 不擅自改变任务锚点；
- 涉及隐私、不可逆操作或高风险结果时取得明确授权。

至于课程是更温暖还是更直接、用工业机器人还是健身做类比、检查站是一题还是两题，都可以留给模型和学习者反馈共同决定。这就同时保留了工程治理和交互速度。

## 费曼到任务

请用一个你真实会使用的学习主题，写出一份三层最小合同：

~~~text
用户授权：只有用户能决定什么？
Harness 不变量：最多写 3 条跨模型不能改变的规则。
模型自由：最多写 3 项可以根据模型能力和学习反馈自由调整的事情。
~~~

最后再补两句：

- Claude 与 Codex 出现什么差异是可以接受的？
- 出现什么差异就必须判定为合同失败？
