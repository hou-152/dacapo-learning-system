>我想起了之前在某一个考试当中，我记得在 GP 那个时代，大家经常会说某个模型跑分怎么样。但大多数情况下，其实都只是跑分高而已。实际用起来，它的“AI 味”很够，或者说“AI 味”太重了。我不知道这是否和训练模型的参数有关，感觉就像是类似的应试教育。

>对，我最近在网上刷抖音、刷视频的时候，发现很多公司的产品和它的管理是脱节的。

>比如像腾讯这么大一个公司，没有一个产品做得好。它其实是一个组织的工程，我感觉这应该叫“组织的工程化管理”。

>也可能是我最近学到了“工程治理”这个词，我很喜欢用它：逻辑编排、工程治理。

>从第一性原理出发，不是不要指标，而是要厘清指标的本质。

>当你想判断的东西太难、太贵、太慢或太复杂时，我们会先用一个更容易观察的“替代指标”（代理指标）来帮助判断。替代指标的概念，就是拿容易看到的表面信号，去近似判断难以直接验证的真实质量，但它绝对不能替代目标本身。

>很多时候指标之所以失效，就是因为“替代指标”一旦被当作真正的目标，就会导致误判。

>怎么说呢？比如你看着自己的量化数据（比如 AGI 给你的数据），觉得“哇，我都进步了这么多”，从而觉得自己很厉害、很牛。但这其实是一种傲慢与无知。

>一个好的替代指标，需要满足两个条件：
1. 与真正目标有相关性
2. 不能被轻易伪造或操纵

现在的智能很便宜，但一个模型的性价比，不仅取决于它 tokens 的价格，还取决于它对人注意力的消耗。

比如说，一个 token 很便宜的模型（比如deepseek v4 Flash），虽然账单上看起来更便宜，但如果它经常出现问题，导致一个流程我需要花两个小时去纠正它，那它对人注意力的浪费是不可逆的。毕竟人的注意力一天就只有那么多。你选择便宜的模型，但它经常出现 bug、经常出问题，你的注意力就会被白白浪费。

怎么样才算达到一个平衡的度（或者说怎么算赢）？

比如面对一个更强的模型（比如 Pro），如果我的模型：
1. 速度比它快
2. 能达到它 80% 的效果
3. 价格只有它的四分之一甚至十分之一
4. 对人注意力的侵占和浪费相对较低（可能只多消耗十分之一的注意力）

这样才算真正有性价比。

嗯，有点道理，有点道理。这些如果能自动就好了

但是 30 分钟之后就可以了。

而最可能欺骗我们的代替指标和人工成本的，毕竟人工成本的叫做……这个我还没想到。

>这个属于工程治理。

如果把它完全删掉的话，它会变成一个又臭又长的东西。可能用一个比较聪明的模型，不用工程治理也能做得很好，因为它有反复的 review 和反复的推测；但是用一个比较差的模型，它就做不到。

现在没有把它完全删除掉，主要是为了保证它的稳定性，不会出现太大的问题。但如果把它当成最终的成功，那就叫做“道法器术”，你反而偏离了学习的本质、学习的“道”，也就是追求一个循环

>虽然我是学工业机器人的，但其实并没有用到相关的 AI。我自己的经历，工业机器人更多的是用 PLC 去控制。

>在这个过程中，我发现它涉及非常多的数据，比如模拟量、数字量、real、int 等各种各样的数据。你需要去写各种常开、常闭触点，需要去调用传感器，去调用主轴。

>如果把人比作一个 Agent，学习这些东西的成本是非常高的。你要懂机械、懂电气自动化、懂 ABB、懂制图、懂数学、懂物理，它是一个非常复杂的交叉学科。在这个交叉学科里面，有些内容简单，有些内容困难。而对应到我们人，每个人的智能程度不同，学习能力也不同。

>我想表达的是，这本身就是一个极其复杂的学科。而如果要求模型去同时理解并构建一个由这么多复杂内容、复杂学科组成的系统，我认为这是一件非常困难的事情。

>大模型的第一性原理是注意力机制（不知道这个观点是否正确）。

我们可以拿人体运动来做个类比。我有健身，人体的运动框架简化来说，基本上就是大关节的屈和伸，以及关节上的肌肉。但从生物学或生理学的角度来看，我们的大脑拥有“潜意识”功能，帮我们处理了大量复杂底层的信息。比如我伸手把手掌张开，一下子就能做到。

但如果要让机器人做同样的动作，你必须告诉它：电信号是什么、关节要转多少角度、里面的步进电机和减速器要怎么协同运动。

如果把这些底层的控制细节全部塞进大模型的上下文里，我认为会直接吃爆它的上下文。

所以，有些东西交给预训练。预训练在模型中扮演的角色，反而就有点像人类的这种“潜意识”

>模型主要是提供一个大脑、提供智能、数据和知识库。面对如此庞大的数据量，我们需要对学习内容进行排兵布局（比如 02.md、Da Capo 模式）。当用户提出想学心理学时，系统会去检索相关内容并进行排序。通过用户提供的上下文，我们可以画像出用户可能更倾向于什么。

关于模型与 Agent（代理）的协作，我总结了以下几个核心逻辑：

1. 模型的核心责任与非自动化边界
模型的哪项职责绝对不能自动化？我的答案是“决策倾向”。
比如在课题选择上，用户想学心理学，系统绝对不能自作主张给选个生物学。这从一开始就违背了用户的学习目标。有些高风险或涉及用户明确意愿的决策，绝不能通过自动化一笔带过，因为这会损害用户的利益。

2. Hermes：为模型构建血肉
如果说模型是大脑，那么 Hermes（框架/Agent 配置文件）就是让模型长出血肉的工具。它包含了 Tool、MCP、Memory 以及用户画像等：
• 调用工具：可以去撰写文章，或者调用外部 Skill。
• 调取记忆（Memory）：记录与用户交互的上下文和需要记住的条款。
• 用户画像：基于用户评估和特定要求（如费曼技巧、Da Capo 模式）生成的学习路径。

3. 确认机制与隐私红线
在发挥模型能力的同时，必须引入“确认机制”，尤其涉及隐私和系统安全时。
我们不能为了效率就直接暴力读取用户的硬盘或私密文件，这种“暴力自动化”是不行的。在高风险操作前，必须有明确的确认步骤。如果用户还没下达“可以开始”的指令，Agent 就直接行动，这是绝对的失职。

4. 学习的诚实性原理
学习能力的认证其实很简单，核心在于面对内心时的“诚实”与“开放”。
在跟 Agent 对话、跟自己内在对话时，要有一种有一说一的态度。不能因为没耐心不想学了，就对 Agent 撒谎说“我已经会了，跳过吧”。这不仅是对学习的亵渎，也让后续的验收失去了意义。

5. 验收者检查站
我作为验收者，检查的地方非常明确：就是你们在执行“费曼技巧”任务时的检查站。我会去看产出的文章或 SOP 是否有问题。最关键的判定标准依然是：那项绝对不能自动化的责任（即用户的明确授权），你们是否自作主张地跳过了？

>关于分数，有些东西确实可以好好掰扯一下。

有人认为，你在低层控制拿到的分数，也代表了高层导航或教学中的能力。但我认为，它的评价体系所展示出来的能力并不是相通的。虽然分数的代理指标相同，但它们的内核和所需的能力圈是完全不同的。

你懂我意思吗？

如果我用一个风控模型（或者说评测模型）在底层机器人上面刷分——也就是“对着问题出答案”，反过去对这个路径进行训练——那我确实可以拿到 100 分。但到了高层级，我可能就只能拿到 0 分。

这不闹呢？

如果把保存状态和绑定回答拿到 harness（这个问题我不是很懂），它可能会增加摩擦。

把这个 harness 的层堆叠得太厚了，对用户的反馈不及时，而且基本上开头上下文有点浪费 tokens。

接下来是哪种错误呢？就是可能有些东西（比如复盘迭代这些东西）得有人去编排、编制，那你把它放到 harness 上，它就可以更自动化。

比如说，别的什么你上过了，我这个用户的转款从来也是直接说“哦，过了过了”，OK。这时候我必须失败了。
我们为什么不能、也不应该要求模型在回答上保持完全一致？
因为这就像前面说到的，每个模型的底层逻辑和构建过程都不同：

1. 训练数据与训练方式不同：
   打个比方，就像不同人的成长和训练方式不一样，他们给出的表达和带给你的感受自然也不同。即使问同一个问题，不同人的回答也会有各自的侧重点。
2. 偏好与架构设计不同：
   每个模型的注意力机制、数据分布和框架设计都不同。比如在设计导向上，有些模型偏重推理，有些则偏重数据。
3. 预训练与微调过程不同：
   模型的预训练和调教过程不同，决定了其智能程度和“智商”存在差异。

所以，模型的回答是不可能完全一致的，除非所有的输入、数据和参数选择都做到了绝对的平均化。

本篇内容主要讨论 AI 授权工作流的边界，以及在自动化流程中，哪些思考过程可以外包给 AI，哪些核心判断必须保留给用户。

我之前提到过一个关于 AI 授权工作流的观点，这其实是一个顺理成章的道理：模型的决定是重建还是推进，都必须基于用户的授权。

以我之前做的一个 AI 授权自动化工作流为例（比如在电脑电量低时，自动运行一个视频生成流水线）：
1. **执行与回退的授权**：
   如果模型在运行过程中发现某个信息图讲得不好、表现形式不佳，它会面临两个选择——是回滚还是停下来？
   此时，模型会向用户确认。当我决定“把它停下来”之后，流程就会暂停。
2. **状态保留的确认**：
   在流程暂停后，模型不能擅自将未完成的包发布到平台上。它需要进一步确认：“我确定保留 Proof（P-R-O-O-F），并把当前状态固定下来。” 只有得到这样的明确授权，模型才能将该状态固定。

**AI 外包的边界在哪里？**

你可以把具体的执行和推演过程外包给 AI。例如，让 AI 去评估：
* 这个步骤是要推进还是退回？
* 整个流程是要重新构建还是如何调整？

你可以让 AI 辅助你梳理这些逻辑，但最终的决定权在用户。因为这涉及你的核心判断与核心理解——凡是要求进行主观判断和深度理解的地方，模型绝对不能擅自替你做决定。
