### 二、先放下一个误会：它不需要你训模型

Hindsight 是一个软件系统：一个服务 ＋ 一个数据库 ＋ 调用现成模型的代码。它用到机器学习的地方只有两个现成零件：

- **embedding**：把一段文字变成一串数字（可以想成坐标），意思相近的文字，坐标离得近；
- **rerank**：用一个模型给一堆候选排个先后。

你不需要训练任何模型，也不需要懂反向传播。要说和你已有的经验对得上的地方——它和工作台是同一类东西：存东西、找东西、让 AI 用这些东西；区别只在于它把「存什么、怎么找」做得更细。

### 三、上篇那三条的答案（重新讲一遍）

1. 「这个 API 的 rate limit 是 60 次/分」→ **世界事实**：关于世界的、谁都能查证的事。
2. 「上次这样调用被限流了」→ **经验**：agent 自己的经历——做了什么、结果如何。
3. 「重试要加退避，置信度 0.8」→ **观点**：从经验里长出来的判断，带一个「我有多确定」的分数。

第四条留到 04 篇：如果撞了几次不同的限流，总结出「所有外部 API 都要假设会限流」，那就是**观察**——从多段经验里压出来的规律，也是 reflect 干的活。

为什么值得分开：三种东西的处置方式不同。事实错了就改事实；经验是记录，不改；观点可以调置信度；观察可以整个推翻重写。

### 四、结构那句话，用一句具体的话走一遍

【原文】新记忆先进入「世界事实」或「经验」两条通路之一，再被表示为实体、关系、时间序列的组合，并配稀疏／稠密向量。

翻成人话。假设你 `retain` 一句：「Alice 在 Google 工作，2026 年 3 月加入。」系统会把它拆成几样：

| 拆出来的东西 | 这句里的样子 | 有什么用 |
|---|---|---|
| 实体 | Alice、Google | 以后顺着它连线 |
| 关系 | works_at | 「谁在哪上班」这类问法 |
| 时间 | 2026-03 | 「六月发生了什么」这类问法 |
| 向量 | 整句话变成一串数字 | 问「她在哪上班」也能命中 |

存的地方叫 **bank**（库），用 `bank_id` 分开——工作一本、私人一本、某个客户一本，互不串味。

取的时候（`recall`）同时跑四路，然后合并：

- **关键词**：原文有「Google」，直接命中；
- **语义**：问「她在哪上班」，靠向量命中「works at Google」；
- **图**：从 Alice 连到 Google，再连到别的相关记忆；
- **时间**：按时间范围筛。

四路结果合起来排序，再按字数预算裁剪，最后交给模型。一句话概括：**存的时候拆成零件，找的时候四路并跑，最后按预算交货。**
