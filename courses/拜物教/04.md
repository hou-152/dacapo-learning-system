# 04｜你睡着后，谁在替你做决定？

## 这一篇要解决的问题

你描述了一个很具体的体验：你给 AI 设定目标后睡着了，它在你没有回应时继续运行，看起来像在自己做决定。另一边，当你完全不知道 AI 视频的 SOP 时，又会把“给我一个完美 skill”体验成近似许愿。

这两件事共同指向第三层：人怎样把判断、行动和责任委托给 Agent。要看清它，先把“系统继续运行”拆回流程中的授权与默认规则。

## 正文

### 1. 先把事实、推测和未知分开

**已确认的事实**：你设定了一个目标；你休息期间没有继续回应；Agent 随后继续了某些行动。

**合理推测**：它可能沿用了既有的权限、任务状态、超时策略或默认工作流。你此前设置的目标和规则，给了它在一定范围内继续行动的空间。

**暂时无法确认的部分**：它在何时触发继续、做过哪些分支选择、是否调用了外部服务、能否回滚、哪些步骤需要人工确认。这些需要查看具体 run 的日志、配置和权限记录。

这一区分很重要。“它看我没反应”是对体验的自然描述；在流程层面，系统更可能处理了一个可计算的状态：等待超时、缺少输入、达到下一阶段，或满足某条默认条件。

### 2. “用户没有回应”本身也是一条规则

一个能持续运行的 Agent，必须对用户不回应作出某种处理。常见选择只有几类：

| 发生的事 | 系统可采用的默认分支 | 谁应当预先决定 |
|---|---|---|
| 用户暂时不回复 | 暂停并等待 | 用户、工作流设计者或部署者 |
| 用户暂时不回复 | 在可逆范围内继续生成草稿或证据 | 用户、工作流设计者或部署者 |
| 用户暂时不回复 | 自动执行有成本、外部影响或不可逆的动作 | 必须有明确、可追溯的授权 |
| 系统遇到歧义或风险 | 升级给人处理 | 用户、组织规则或产品策略 |

因此，沉默不是流程之外的空白。系统会把它映射成“继续”“暂停”“降级”或“升级”的一个分支。超时只会触发既有规则，不能被解释成新的或扩大的授权。Agent 运行得越久，这条分支就越关键。

### 3. 目标不等于授权

“帮我做一个 AI 视频”表达了目标，仍然留下大量需要决定的事：文案可否改动、视觉能否自由发挥、是否允许调用付费服务、是否能上传素材、何时可以发布、失败后能否自动重试。

这些问题可以用一张“决策权卡片”写清：

| 决策类型 | 例子 | 建议的默认权限 |
|---|---|---|
| 可逆的准备工作 | 检索资料、生成候选方案、低清 proof、整理日志 | 可以自动进行 |
| 会改变内容或质量判断的动作 | 改写冻结文案、选择最终视觉风格、接受质量取舍 | 先征求确认 |
| 有外部影响或难以撤回的动作 | 付费、发布、共享私密素材、删除原始文件 | 明确授权后才执行 |
| 遇到证据不足或目标冲突 | 来源不清、版权不明、两个质量目标互相冲突 | 停下来升级给人 |

这张卡片聚焦一件事：你愿意把哪些决策暂时交出去。用户睡着后 Agent 继续运行，通常说明其中一部分决策已经被预先委托了。在既有范围内，Agent 可以作执行层的选择；是否允许某类行动，则由先前授权和超时策略决定。

### 4. “请赐予我完美 SOP”为什么会带来神谕感

SOP 可以把已经做过的选择、顺序和验收条件写成可重复执行的流程。它不能凭空替你决定尚未说明的目标、受众、审美、预算、风险承受度和责任归属。

当你对 AI 视频生产一无所知时，“给我一个完美 skill／SOP”会把大量未声明的判断压进模型的默认输出。模型给出的路径因此容易显得像一个完整答案；实际情况是，它在替你填补缺失的标准。

这就是“查神谕”体验最容易发生的地方。它提示你：此时值得补上的，也许是几条属于你的决策标准。工具仍然可以承担检索、生成候选方案和执行明确步骤等工作。

### 5. 它和商品拜物教怎样连起来

Agent 在授权范围内继续运行，首先属于委托性自动化。它表现的是人把某些行动交给系统执行。

商品拜物教的连接出现在另一层：当产品把这些由人设定的目标、权限、默认规则、数据、基础设施与责任关系，呈现为“Agent 自己天然会规划、判断和负责”的能力时，社会关系就更容易退到后台。

所以，“AI 自己做决定了”可以改写成一个更准确、也更有力的问题：

> 这一步行动是谁预先授权的？默认分支由谁写入？谁可以中止或回滚？如果结果出错，谁承担后果？

四个问题把神谕感重新拆回可追踪的关系。

### 6. 一个适合你的视频流水线的睡前规则

如果你希望 Agent 在你休息时继续推进，可以先写一个极简规则：

```text
目标：完成低清 proof 的准备工作。
可自动：整理素材、生成候选视觉方案、跑可逆的验证、输出日志。
必须暂停：改动冻结正文、调用付费服务、公开发布、删除或覆盖原始素材。
无人回应时：只继续可逆工作；遇到歧义或外部影响时停在待确认状态。
责任人：我负责最终内容、预算、发布与不可逆决定。
```

这份规则先给 Agent 一条清楚的边界，让“继续做”与“替我决定”不再混在一起。

责任也不应只落在“用户”或“AI”身上。委托方负责目标与明确授予的权限；部署或运营方负责默认规则、监控、升级与日志；工具提供方对产品安全、说明与合同义务承担相应责任。具体法律责任还要看司法辖区、合同、实际控制能力和过失情况，本篇不把这张卡片当作法律结论。

## 小结

- 用户不回应会被工作流映射成默认分支，沉默本身不是流程空白。
- 目标、授权范围、默认策略、人工升级点和责任归属需要分开写。
- “完美 SOP”的神谕感常来自未声明的判断被模型默认填补。
- Agent 持续运行首先属于委托性自动化。
- 当这些人设定的关系被包装成 Agent 天生的自主判断时，才更接近商品拜物教的分析。
