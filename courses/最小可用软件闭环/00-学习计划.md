# 最小可用软件闭环｜学习计划

## 学习目标

亲手完成一个最小软件闭环，最终产出一个**可运行、可展示、能通过自己验收**的作品。拆成可检查的能力：

1. 能写出一个真实困境卡（四行 + 四问，落地到自己的具体场景）；
2. 能把这个困境收缩成最小闭环 + 列出明确的非目标；
3. 能和 Agent 真实完成一轮"复述→追问→比较方案→定最小版"的对话；
4. 能接一份真实数据/来源并验证它真的进了链路；
5. 能完成一次真实返工（复现步骤 + 实际 vs 期望 + 证据，修完跑回归）；
6. 能回到原始困境亲自验收，产出一个可打开、可操作、别人能看的作品。

## 完成标准

- 用户明确表示学完；或
- 六站路径全部走完，最后一篇反馈判定为 pass，且用户完成一次输出（交付一个亲手做完、通过验收的作品链接/截图 + 一句话说明它解决了什么）；或
- 用户说目标变了 → 结题，目标变化按新课题处理。

## 停止条件

任一触发时先问用户，不自动续写：

- 同一卡点连续 2 次判定 bad_case；
- 连续 2 篇没有真实反馈；
- 用户明确要求暂停；
- 超过约定节奏仍无反馈，提醒一次后按上一条处理。

## 学习节奏

- 承诺频率：每篇一个「试试看」动作，做完反馈后再推进下一篇（不设固定天数，以动手为准）
- 到期没来 → 提醒一次，不自动替用户往下写
