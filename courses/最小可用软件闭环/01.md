# 01｜先把一个真实问题抓到手里

## 这一篇要解决的问题

不讲理论。你已经看过这门课，缺的是动手。这一篇只做一件事：让你把一个**真实、反复发生、你愿意接手的**小麻烦，写成一纸可以开工的困境卡。写不出来也没关系，写的过程就是发现卡点的过程。

## 正文

纤依课的核心循环是：

```text
本人 → Agent → 循环 → 验收
```

而这个循环的第一步，不是你去找 Agent，也不是去装部署包，是**你说得清自己到底卡在哪个麻烦上**。这一步做砸了，后面全白搭。

这里不是说"我想做个待办清单""我想做个网站"。这些是答案，不是问题。真正的问题是：

> 我每天会在什么地方，反复花掉时间 / 漏掉事 / 靠脑子记不住，而且这件事有明确规则，可以被一个只服务我的小软件接住。

你可以先不判断它"值不值得做成软件"，先把现象写下来。写的时候只抠四个点：

1. **什么时候发生**（具体到场景：每天晚上整理时 / 每次切换工具时）
2. **多久一次**（每天都这样 / 一周几次）
3. **浪费了什么**（时间 / 注意力 / 会忘事）
4. **解决后你看见什么变化**（不是"变高效"这种空话，是能目击到的：某件事不再漏、某个数字能自动累计、某个记录能一键查到）

写完这四行，再拿课程里的"四问"过一遍，只是帮你判断它合不合适现在动手，不是考试：

- 高频重复（反复发生，不是一次性的）
- 规则明确（核心动作能说清、能复现）
- 输入输出清楚（知道从哪开始、到哪结束）
- 结果可验收（成没成，你能一眼分清）

最后补一句「第一版明确不做」，把你脑子里那个越想越大的东西按住。

## 小结

- 真实问题优先于"我想做个 X"。
- 四行 + 四问 + 一句非目标，就是一份能开工的困境卡。
- 这一步的判断权在你，我只看证据、不替你答。

## 试试看

给你 5 分钟，直接在下面"学习反馈"里写一份你的困境卡（四行 + 顺便过一遍四问 + 一句非目标）。写你自己生活、学习、自媒体、当组长管组里催作业时遇到的真实麻烦都行**。写不满四行也没关系——你卡在哪，就照实说哪一行写不出来，那一行就是下一篇要专攻的卡点。
