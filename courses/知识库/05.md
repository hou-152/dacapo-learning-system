# 05｜落地：用四层 + 四法给你的库做一次体检

## 这一篇要解决的问题

理论骨架齐了（四层、四法、两个雷）。现在回到你最初那句话：「我对自己库一窍不通，用的时候一堆问题」。这一篇给你一把尺子，把你手上的东西——小龙虾 + dbs-content-system、Ima、飞书、Obsidian、28 万字口喷记录——往四层上一放，看每层有没有、卡在哪，最后定最小的一步。

## 正文

### 先把你的现状摆出来

从项目里能看到的你的装备：小龙虾（带 USER.md、MEMORY.md、长期/短期记忆）、dbs-content-system 加工管线、28 万字 Typeless 口喷记录、闪电说，以及 Ima / 飞书 / Obsidian 这些知识库工具。你之前说「自己在执行中感受出语境那套」，说明这套装备已经在跑了，只是零件没按层摆放。

「一窍不通」的解法：把现有零件对号入座，缺的补上，其余照用。下面是对照表。

### 四层对照表：你的库现在长什么样

| 层 | 你手上对应什么 | 检查点 |
|---|---|---|
| 1 会话元数据（内存） | 小龙虾会话机制自带 | 不用管 |
| 2 用户结构化数据（JSON） | MEMORY.md / USER.md、飞书多维表格字段 | 关于你的事实有没有一个可键值拿的地方？改了会不会叠着写？ |
| 3 近期摘要（向量库） | Ima / 飞书知识库 + dbs-content-system 加工资产 | 进去的是加工过的问答对、洁癖笔记，还是原文堆砌？ |
| 4 滑动窗口（原文） | 对话本身自带 | 不用管 |

### 你的库大概率卡在三个地方

**卡点一：第三层的原料没加工。** 28 万字口喷记录是原文，口语凌乱。直接进库，检索出来的片段质量就烂——这你早就预判过（「预判知识库会垃圾，Typeless 内容口语凌乱」）。这一步的解法就是四法之三、之四：压缩成问答对 + 洁癖笔记。dbs-content-system 干的就是这道工序，你缺的是让它覆盖到那 28 万字。

**卡点二：第二层缺位。** 关于你自己的结构化事实（你是谁、在做什么、关键决定）散落在聊天记录里，没有一份「键值可拿」的用户档案。检查动作：你换城市了，MEMORY.md 里是改掉旧地址还是叠着写？叠着写就是状态冲突，03 篇的雷就埋在这。土办法：每个事实标注「从哪天生效」，更新时掐旧启新。

**卡点三：别名没建表。** 第三个雷。你库里写着「上下文工程师」，你问「Context Engineering 怎么入门」，语义检索可能漏。同一个东西多个叫法，embedding 对中英混用、缩写、同义词的相似度不稳定。

### 别名（第三个雷）怎么排

从土到洋三档：

1. **土办法**：维护一张别名表（别名 → 规范名）。建标签时把同义词都写进元数据；提问时先把别名换成规范名再检索。
2. **查询扩展**：检索前把问题里的关键词扩展成一组同义词，多个 query 一起搜，结果合并。
3. **生产级**：实体归一（entity resolution）——文档里的每个提及先链接到实体库里的实体 ID，检索和生成都基于实体 ID 而不基于字面词。「上下文工程师」和 Context Engineering 链接到同一个实体，谁问都找得到。

别名表也能挂时间戳：同一个概念不同时期叫法不同（比如一个词 2024 年叫 A，2026 年叫 B），别名记录标上有效期，就是 03 的双时间戳推广到命名上。

### 最小的一步

别一口吃下 28 万字。取一小块料，跑一遍完整工序：

1. 从口喷记录里挑 10 条（你最关心的话题）。
2. 按四法加工：打时间戳 → 按功能语义打标签（顺手把别名写进标签）→ 压缩成问答对 → 洁癖笔记。
3. 进你的知识库（Ima 或飞书都行）。
4. 问三个你自己的真实问题，看它答得怎么样。答得差的地方，就是你下一轮要补的标签和时间戳。

这一步的目的你已经知道了：「看见你的知识库长什么样」。四层和四法，是你「看见」之后用来定位问题的那把尺子。

## 小结

1. 你的装备已经齐了（小龙虾、dbs-content-system、Ima / 飞书 / Obsidian、28 万字），缺的是按层摆放。
2. 三个卡点：第三层原料没加工（原文堆砌）、第二层缺结构化档案（叠着写导致状态冲突）、别名没建表（检索漏）。
3. 别名三档解法：别名表（土）→ 查询扩展（中）→ 实体归一（生产级），别名也能挂时间戳。
4. 最小一步：10 条口喷记录走完四法进库，问三个真实问题，用答得差的地方定位下一轮动作。
