# 素材原文｜AI 岗面试，8k vs 50k 的候选人差别有多大？

> 来源：用户下载的 docs 原文（.docx），2026-08-23 归档到本课题目录。
> 对应主题：面试问到 Agent 记忆，面试官到底想听什么？ #Agent #秋招 #AI大模型

## 00:00

创新是多少？8K Agent 是怎么做记忆管理的？用向量数据库存历史对话，然后 RAG 捞出来直接拼到 prompt 里面去。这个人没在生产环境里真正跑过。

如果 Agent 要去查手机号、订单号这种精准的信息，但是向量库会返回语义相近的片段，这种情况查不准你应该怎么办？——那我多检索几条，让模型自己选一下。

用户如果先说我在上海，后面又说搬到了北京，两条同时被捞了出来，Agent 分不清，带着过期的信息来进行决策，你怎么解决？——我让用户重新说一遍，或者清一下缓存。

## 00:31

两个生产级隐患一个都没解决。向量库加 RAG 是常规操作，但真上生产有两个坑：精确信息查不准，时间维度上的状态混乱。

所以我做了四层架构：

1. 会话元数据：会话 ID、入口渠道，放内存，用完就扔。
2. 用户结构管理：身份、偏好、历史关键决策，走 JSON 存储，查的时候直接键值拿，不碰语义搜索。
3. 近期规划摘要：把最近几次对话压缩成主题和关键实体，语义检索只在这一层用，还能压 token。
4. 滑动窗口：当前这轮的原始材料，超了就处理。

四层各司其职，不要让向量库一统天下。

## 01:02

状态冲突，用双时间戳。比如用户搬家，不是增加一条，而是把旧地址有效期掐断，新的地址从那天算，只读当前有效。底层 ledger 只追加不删，views 按任务投影，policy 管读写和合规遗忘。

重复任务沉淀 Skill，直接调用。说白了记忆不是塞数据，而是让 Agent 越用越像。

## 01:06

老员工月薪 50K，这道题实际上就考两件事：

1. 你知不知道精确查询和语义检索是两回事？
2. 你有没有处理过用户信息变更之后的状态冲突？

这两个坑，只跑过 demo 的人永远都遇不到，但一上生产全是雷。
