## 最小知识地图

### 1. 「强模型」强在哪——Skill 里哪些东西可以删了

04 讲过驱动力 A：模型能力内化。你在 04 里回应说「当智能越来越强的时候，有些东西它就不用提」。这个体感是对的。

具体来说，「强模型」吃掉了 Skill 里的三类内容：

**第一类：思考脚手架。**
```
删除前：请认真思考、从多个角度分析、使用第一性原理、保持批判性思维
删除后：（空白——模型自己会做这些，不用你叮嘱）
```

对这个我也会认为，有些思维确实需要你是一个很聪明的人才能拥有。虽然我这里不是唯智商论，但客观描述来说，有些东西确实是你的智商上去了，自然而然就会拥有的。

如果说智商有什么能够量化的标准，或者说量化完之后有零点零几正相关的，可能就是你的学位、你的学历、你的院校之类。但这些东西都是可以通过后天去培养的。

我想要表达和论证的是，这些思维和能力，其实等你智商上去了，你自然而然就会拥有。我觉得这有点道理。

这类内容在 GPT-3.5 时代是雪中送炭。在 Claude 5 / GPT-5.6 时代是画蛇添足——模型本来就会多角度思考，你的指令只是在浪费上下文。

**第二类：人设描述。**
```
删除前：你是顶级内容策划，拥有 20 年经验，对用户需求有深刻洞察
删除后：你的任务是：从以下 3 篇文章中提取与「控制权迁移」直接相关的段落
```
模型不需要你告诉它「你是谁」。它需要你告诉它「这一轮的具体任务是什么」。

对，这让我想起来，中国这边喜欢去搞落地的、垂直的、专业化的 AI 应用；而像 OpenAI、Anthropic 这种开源或前沿的 AI 公司，它们更多的是想搞一个非常牛逼的智能。这种智能进化到后面，根本不需要那么多花里胡哨的东西。

对，这确实是在智能不足时的一些妥协。

但是现在智能已经很足了，可以说是两条腿走路：一方面智能足够，另一方面这些落地化、垂直专业化的方向也发展得不错。

而现在的 Agent 在 ToB 公司的落地，更多的是成本问题。也就是说，用高智能模型确实没问题，但是太贵了，企业负担不起。所以，大概率是要把任务分流：
1. 一些简单的东西，就交给便宜的模型，比如 GPT-4o Flash、DeepSeek
2. 一些难的任务，就交给 Fable 5

**第三类：通用方法论。**
```
删除前：使用以下方法论分析：SWOT、波特五力、第一性原理、金字塔原理
删除后：（不需要——这些方法论已经在模型训练数据里了。如果局部任务需要特定方法论，写到 Harness 层而不是 Skill 里）
```

删掉这三类内容之后，Skill 还剩下什么？三样东西：
- 这个 Skill 在什么状态下被触发
- 它需要的输入是什么
- 它做完的标志是什么

这就是「薄 Skill」。

### 2. 「薄 Skill」长什么样——四字段

你在 05 的费曼练习里已经给 Harness 画了五层。薄 Skill 就是每一层 Harness 能调用的最小执行单元。它只需要四个字段：

```
Skill: {名称}
触发条件: 系统出现什么状态时调用？
输入: 解决问题所需的最小信息
动作: 具体做什么（可以被执行、也可以被检查做完没有）
验证: 怎么知道做对了？失败后做什么？
```

用你系统里的「龙虾日报」来试一下——从现在的厚描述改成薄的：

**改之前（CLAUDE.md 现状）**：
> 「龙虾日报：每日凌晨 cron / 手动指令 → 龙虾日报 skill」

这只有触发条件（定时/手动），没有输入、动作、验证。

**改之后（薄 Skill 四字段）**：
```
Skill: 龙虾日报
触发条件: 日报数据库中存在发布时间在过去 24 小时内、且未生成摘要的条目 ≥ 1
输入: 符合触发条件的所有条目的标题、正文、来源
动作:
  1. 为每条生成 3 句话以内的中文摘要
  2. 按「速览→统计→🌳核心人物→✨高光→💡案例→❓问答→🧩能力→🔧工具→💰商机→🔥话题」排列
  3. 标记高光条目（对话被 5+ 人回复/拍一拍/转述）
验证:
  - 每个章节至少有一条内容（允许某些章节为空但必须有标注）
  - 高光条目附带原文引用
  - 失败处理：章节不全 → 补充检索 1 次；仍不全 → 标注「部分章节数据不足」并继续发布
```

注意看：改之后的 Skill 没有「请认真阅读每一条内容」「从社群角度深度分析」「使用第一性原理」这类东西。不是它们不重要——是模型不需要你告诉它这些。需要被写下来的只有：**什么时候做、用什么做、做什么、怎么知道做对了。**

你在 05 里自己说的：「厚 harness、薄 skill、强 model」。薄 Skill 就是这句话里「薄」的落地方式。不是功能变少，是只保留模型自己不能推断的东西。


### 3. 「厚 Harness」厚在哪——你费曼练习的五层已经回答了

你在 05 费曼里写的五层分析，恰好是「厚 Harness」的五个方向：

| 你的费曼 | 对应「厚」在哪 |
|---------|-------------|
| 规则层：定时心跳触发 Skill | 以前靠人记得每天早上看一眼，现在系统自动触发 |
| 记忆层：Agent 的交互方式、任务、边界存在 Harness 里 | 以前每次会话开头重新交代一遍，现在跨轮持久化 |
| 工具层：基于 MCP，明确能/不能用的工具 | 以前模型自己决定调什么工具，现在 Harness 层做权限控制 |
| 验证层：review agent 对抗性审计 + 人最终判断 | 以前靠人对结果「感觉对不对」，现在有审计+报告机制 |
| 公理层：不能不懂装懂、硬约束 | 以前靠 prompt 里的「请诚实」，现在是系统级硬边界 |

每一层「厚」，对应的就是这一层以前靠 prompt 口头约束、现在靠 Harness 系统级约束。

但「厚 Harness」不等于「复杂的 Harness」。每个 Skill 仍然是薄的——四个字段。Harness 的厚体现在：它管的不只是一个 Skill，而是所有 Skill 的调度、验证、权限、记忆。

一个类比：餐厅厨房里，每道菜的做法（薄 Skill）不需要写「请认真烹饪」「请从食材本质出发」，只需要写食材、步骤、火候、摆盘标准。但厨房的运营系统（厚 Harness）管的是：谁来接单、食材库存、出品检查、食品安全底线。Harness 厚，Skill 薄，就是这个分工。

### 4. 拿你自己的一个真实判断来练一次「从厚改薄」

你在 04 费曼里写了一条判断：

> 「AI不外包判断 = 能外包思考过程，不能外包理解本身。」
> 「简单工程判断（yes/no、0/1）可让 AI 介入，但核心判断不能外包。」

现在把这条判断从「你脑子里的信念」改成「一个薄 Skill」：

```
Skill: 判断外包检查
触发条件: 任一 Agent 即将做出涉及发布、结论、对外输出的决策
输入: Agent 当前决策的描述（1-3 句话）
动作:
  1. 判断这个决策属于「工程判断」（yes/no/0/1/格式校验/存在性检查）还是「价值判断」（领域判断/发布判断/对错判断）
  2. 如果是工程判断 → 放行，但要求 Agent 附上验证依据
  3. 如果是价值判断 → 停止执行，将决策描述提交给人，等待人的确认
验证:
  - 过去 7 天内，是否有价值判断被错误标记为工程判断而自动放行？
  - 如果有 → 升级该 Skill 的分类标准，添加新的识别规则
```

你 05 检查站里说「要把 AI不外包判断从 prompt 移到 Harness，实际需要改 agent 这个文件」。方向对——改的就是 Agent 在执行决策前必须检查的约束文件。但具体落地的形态不是「在文件里加一段话」，而是**把一个信念拆成触发条件+输入+动作+验证**。信念是被相信的，Skill 是被调度的。

### 5. 你自己走通的「厚 Harness、薄 Skill、强模型」——一句话收束

把你这五篇学到的、加上你自己推导出来的，压成一句话：

> **模型变强吃了通用能力，所以 Skill 只需要写模型自己不能推断的东西（薄）。被吃掉的那部分控制权没有消失，它从 prompt 文本迁移到了系统规则、权限、验证和调度逻辑里（厚）。人不再盯过程，只在高价值判断节点介入。**

这三件事——强模型、薄 Skill、厚 Harness——不是三种可选的路线。它们是同一条演化线的三个面。你刚才跟 GPT 对话时自己走到这个结论，说明不需要我再讲一遍了。

## 小结

1. 「强模型」吃掉了 Skill 里的三类内容：思考脚手架（「请认真思考」）、人设描述（「你是顶级XX」）、通用方法论（SWOT 等）。删掉这些，Skill 只剩下模型自己不能推断的东西。
2. 「薄 Skill」= 四个字段：触发条件、输入、动作、验证。不是功能变少，是不写模型已经会的东西。
3. 「厚 Harness」≠ 复杂的 Harness。它厚在调度、验证、权限、记忆、公理五个维度——你费曼练习已经画出来了。
4. 一个信念（「AI不外包判断」）变成薄 Skill 的过程 = 拆成触发条件+输入+动作+验证。信念被相信，Skill 被调度。
5. 你走通的公式可以压成一句话：模型变强吃通用能力 → Skill 变薄 → 控制权迁移到 Harness → 人只做必须人做的判断。

```
现状（CLAUDE.md 里的一句话或一个段落）：
{粘贴原描述}

改薄后：
触发条件:
输入:
动作:
验证:
```
改完之后，当我去丢给它一个很长的文章，并输入触发条件“/”和对应的“三级笔记” Skill 时，整体流程是这样的：

1. 输入：我给它一些文章。
2. 动作：让它使用“三级笔记”这个压缩过的方法进行处理。不用重点去体现它的格式，只要告诉它“不要过度压缩文章”这个动作即可。
3. 产出：产出后让 Agent 让人去看一眼，确认这个三级笔记大概没有问题，这样就 OK 了。
不用写完美。重点是感受一下：哪些东西你原本写在 Skill 里、但模型其实不需要你告诉它。
