# 09｜Harness 会越来越厚，还是越来越薄？——强模型时代智能与控制的第一性原理

## 这一篇要解决的问题

你在第 8 篇形成了“厚 Harness、薄 Skill、强模型”的判断，也亲手留下了一条证伪条件：模型继续变强，Harness 反而变薄，这个判断就要被修正。2026-07-26 与 2026-07-27 两期 AI 内参恰好提供了这种信号。本篇追问 Harness 究竟是什么、厚薄指什么，以及模型越强时控制为什么会迁移。

## 正文

### 新材料撞上了你的旧判断

两期材料里有三条相关线索：

1. Thariq 的材料主张，面向新一代模型的 Claude Code 系统提示词曾缩短约 80%，编码评测没有出现可测量损失。
2. Claude 官方博客把上下文工程的新变化概括为：让模型使用判断力、通过接口表达意图、按需加载上下文、使用更高保真的引用。
3. Anthropic 的 Opus 5 官方发布强调长任务中的自我验证、持续迭代和缺少工具时主动构造工具。

证据边界也很清楚：“缩短 80%”是特定团队、特定模型和特定评测下的材料主张；第三方系统提示词仓库没有获得 Anthropic 确认；两期相似内容属于连续来源簇，不能计算成两次独立验证。详细绑定见 [260726—260727 来源包](assets/260726-260727-opus5-context-engineering-source-pack.md)。

即便保留这些限制，它们仍然提出了一个有效问题：

> 系统提示词大幅缩短时，Harness 也变薄了吗？

回答它之前，先要知道 Harness 的“厚”究竟在描述什么。

### What 1：Harness 是什么

模型拥有从训练中获得的通用能力。它可以写代码、理解语言、规划步骤、识别模式。这些能力在调用发生前已经存在，可以称为**模型潜能**。

一次具体任务还包含另外四样东西：

- 模型此刻看见的信息；
- 模型可以调用的工具；
- 模型依据什么判断结果好坏；
- 模型越过能力或权限边界后由谁接管。

Harness 把这些部分组织成一个可以行动的系统。它连接模型、上下文、工具、状态、反馈、权限和停止条件，让模型潜能在具体环境里变成有效行为。

可以把这层关系写成一个概念式：

> 有效智能 ≈ 模型潜能 × 可见世界 × 行动能力 × 反馈质量

就我的理解，这几个概念的具体含义如下：

1. 模型潜能：指模型的智商、长任务能力、COT（链式思考）推理链等。
2. 可见世界：我更多的理解为用户的上下文（Context Window）。（注：我不确定这会不会跟我的“大世界模型”混淆，它有点像具身智能涉及到的那种世界模型，但我对世界模型这方面认识不深。）
3. 行动能力：指 Tool、MCP、Skill 这些。
4. 反馈质量：应该是指用户描述的那种清晰度，也就是语言能力。

这不是数学测量公式。乘号表达的是互相制约：任何一项接近零，整个系统的表现都会明显下降。

一个能力很强的模型，拿不到关键事实时只能在错误世界里推理；拥有完整信息却没有工具时只能提出建议；能够行动但没有反馈时无法知道自己是否偏离目标。

因此，Agent 的有效智能来自模型与环境之间的关系。Harness 管理的正是这段关系。

### What 2：Harness 的厚薄至少有四种含义

“厚 Harness”听起来像一个单一指标，其实混合了四个维度。

| 维度 | 它在描述什么 | 可能的变化方向 |
|---|---|---|
| 文本厚度 | System Prompt、规则、示例占用多少 token | 模型越强，通常可以减少 |
| 结构深度 | 是否具备检索、记忆、工具路由、状态管理和反馈 | 长任务越复杂，通常会加深 |
| 控制粒度 | 系统预先规定每一步，还是只规定目标、边界和验收 | 模型越强，控制可以上移 |
| 责任覆盖 | 谁授权、谁承担后果、哪些动作不可逆 | 能力越强，责任边界越需要清楚 |

这四个维度可以朝不同方向变化。系统提示词缩短，证明的是文本厚度下降。动态检索、工具路由、自动验证和权限隔离同时增强时，结构深度仍然在增加。

于是，“Harness 变薄”与“Harness 变强”可以同时发生。一个系统可以少写很多话，同时更准确地决定模型在何时看见什么、能够做什么、怎样知道自己做对了。

你的原判断需要先完成定义：

- 如果“厚”指规则数量和上下文体积，新材料正在挑战它。
- 如果“厚”指系统组织上下文、行动和反馈的能力，新材料暂时没有推翻它。

### Why 1：模型越强，为什么显式规则可以减少

早期模型缺少稳定判断时，外部规则会替它完成判断。规则告诉模型什么能做、什么不能做、遇到某种情况走哪条路径。它们相当于把人的经验提前展开成大量条件分支。

模型能力增强后，三件事发生了变化。

第一，模型内化了更多通用规律。代码风格、文档密度、常见工具使用方式和基本任务规划，可以从环境中读取并自行判断。外部规则继续复述这些规律，新增信息很少。

对，像是很多。我们在之前使用 AI 的时候，经常跟它说什么第一性原理，还有各种各样所谓的“芒格 100 种思维模型”，比如说贝叶斯、逆向思考、奥卡姆剃刀模型这些。

我觉得它不仅通用了规律，而且还通用了一些思维模式。

第二，固定规则会产生协调成本。规则散落在多个位置时可能重复、冲突或只适合旧环境。模型需要先解决指令之间的矛盾，再处理任务本身。

对，因为在大模型里，当你在做一个大的产品或者一个大的项目时，它的规则本身就是冲突的。可能因为人的原因，比如 brief 和 PRD 没有设置好，规则之间就会起冲突。

而且这些规则还不清楚，有着模糊的界限，有点像要去打官司的法律条文。在法律条文打官司的过程中，遇到的问题就是“上有政策，下有对策”。

AI 其实很聪明，它会钻漏洞瞎弄，导致规则越来越多。这就是“熵增”，熵增特别多。

第三，现实任务拥有大量变化。固定规则只能枚举设计者提前想到的情况。模型的判断力提供了一种适应变化的能力，让系统用目标、参照物和反馈覆盖更多未知情形。

对对对，因为项目它不是设计出来的，而是跑出来的

控制论里有一个重要思想：控制器想应对环境的变化，自身必须具备足够的变化能力。固定规则通过增加分支获得这种能力；强模型通过理解和推理吸收了一部分变化。模型内化得越多，外部系统越可以减少逐项规定。


这解释了 Prompt 为什么会变短。被删除的部分没有凭空消失，其中一部分已经进入模型能力，另一部分转移到了环境、接口和反馈结构里。

### Why 2：Prompt 变短，为什么上下文工程更重要

强模型扩大了可选择的行动空间。它能检索更多材料、调用更多工具、规划更长步骤，也能在缺少明确指令时自行决定。选择空间扩大后，模型看见什么、把什么当成目标、依据什么反馈纠正自己，会产生更大影响。

上下文至少划定了三个边界：

1. **认识边界**：模型能够知道什么。缺失的事实不会自动进入推理。
2. **行动边界**：模型能够改变什么。工具与权限决定建议能否变成现实动作。
3. **规范边界**：什么结果算好，什么代价不可接受，谁拥有最终决定权。

Prompt 时代的控制常常停留在“这一步怎么做”。上下文工程把控制推向更高一层：

- 让模型进入哪个世界；
- 给它什么目标；
- 开放哪些行动；
- 用什么证据判断成功；
- 哪些后果必须由人承担。

模型获得了路径上的自由裁量权。人保留了对世界、目标、评价和责任的元判断。

这就是控制权迁移的深层含义：控制没有消失，控制对象发生了变化。系统逐渐减少对动作过程的逐项规定，把更多力量放在环境选择、反馈设计和责任边界上。

### Why 3：能力越强，为什么仍然存在人的判断权

能力回答“能不能做到”。授权回答“可不可以替别人做决定”。两者属于不同问题。

模型可以理解多个目标，也可以预测不同选择的后果。它仍然无法仅凭能力获得合法授权，因为目标之间常常包含利益冲突、价值选择和责任分配。

例如，一个 Agent 可以判断哪种内容最容易传播。是否牺牲作者原意换取传播，属于价值选择。它可以判断某次发布通过了自动检查。是否愿意承担公开发布后的声誉风险，属于责任选择。

委托提高了执行范围，却没有消除委托人的责任。Agent 越有能力，人越少参与细节；人的判断会收缩到少数更高价值的位置：

- 选择目标；
- 判断证据是否足够；
- 处理价值冲突；
- 决定不可逆动作；
- 承担最终后果。

这也解释了你之前那句话为什么仍然重要：

> 能外包思考过程，不能外包理解本身。

“理解本身”包含你为什么选择这个目标、愿意付出什么代价、怎样的证据会让你改变判断。模型可以参与这些问题的推演，决定权仍然需要一个承担后果的主体。

### 现在怎样回答“厚还是薄”

目前最稳妥的答案包含四层：

1. **文本会变薄**：强模型吃掉通用规则，重复说明和过细示例减少。
2. **结构会变深**：上下文检索、工具路由、状态、反馈和权限继续组织模型行为。
3. **控制会上移**：逐步命令减少，世界、目标、证据和责任成为主要控制点。
4. **人的判断会收缩**：介入频率可以下降，留下的是更难外包的元判断。

所以，“厚 Harness、薄 Skill、强模型”还没有被这两期材料直接推翻。它需要一次概念修订：厚度不能只用规则数量衡量。

一个更精确的候选表达是：

> **强模型、薄文本、深结构、硬责任。**

这句话目前仍是候选判断。它是否比“厚 Harness”更准确，要看你怎样定义 Harness，以及未来模型能否连上下文选择、验证和责任判断也一起内化。

## 小结

1. Harness 管理模型与上下文、工具、反馈和权限之间的关系，把模型潜能变成有效行为。
2. Harness 的厚薄至少包含文本厚度、结构深度、控制粒度和责任覆盖，四个维度可能朝不同方向变化。
3. 强模型内化通用规律并吸收环境变化，因此外部系统可以减少逐项规则。
4. 模型行动空间扩大后，上下文决定认识、行动和规范边界，控制权由过程规定迁移到元层选择。
5. 当前候选判断是“强模型、薄文本、深结构、硬责任”，它等待你的定义和反例继续修正。

本篇还可以直接回答一个核心问题：

> 当你说“厚 Harness”时，你指的是规则多、系统能力强、控制点密，还是责任边界完整？新材料有没有改变你的原判断？

新材料确实改变了我的判断。

当我说“厚 Harness”的时候，首先指的并不是规则多。因为在智能越来越完善的阶段，像这种强约束或硬约束是没有必要的。

应该说，像之前那种“你必须去怎么样”的强约束，在这里已经不用刻意写进去了。比如像 Agent 要去调用，是要去走 CLI 还是 MCP，这两个就没必要专门去写一个强约束给它。

更重要的应该是：
1. 责任边界完整
2. 索引够清晰：比如告诉它真源在哪里
3. 更清楚自己的边界

如果我们用“道、法、器、术”的框架来理解：
“法、器、术”这些东西是可以外包的，也就是由 Harness 去负责。而“道”（原判断、责任）这方面，还是由人去处理。

这确实改变了我的判断。
