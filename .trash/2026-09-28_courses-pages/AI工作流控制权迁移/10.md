# 10｜上下文、世界模型与反馈：Agent 到底生活在哪个世界

## 这一篇要解决的问题

你在第 9 篇里把模型潜能理解为智商、长任务能力和 CoT，把行动能力连接到 Tool、MCP 与 Skill；你也明确提出：可见世界是否等于 `Context Window`，它会不会与具身智能中的世界模型混淆。本篇拆开环境、上下文、Context Window、世界模型和反馈，回答 Agent 到底通过什么接触世界。

## 正文

### 先接住你的概念图

你对“有效智能”四部分的理解已经搭起主体：

1. 模型潜能来自模型内部能力；
2. 可见世界与上下文有关；
3. 行动能力与 Tool、MCP、Skill 有关；
4. 反馈质量决定系统能否修正。

其中有三个位置值得进一步校准：

- `Context Window` 描述容量与工作记忆边界，可见世界描述 Agent 此刻实际能够接触的部分；
 口误了，应该是 Content Engine
- 世界模型是模型内部形成的理解与预测结构；
- 用户描述的清晰度属于输入质量，反馈发生在行动产生结果之后。

这些概念一旦分开，你提出的“责任边界完整、真源索引清晰、知道自己的边界”会自然落到三种世界边界上。

### What 1：环境、上下文、Context Window 与世界模型

先把四个概念放在同一条链上。

#### 环境

环境包含 Agent 外部实际存在的状态、人物、文件、系统、规则和后果。项目里的源文件、数据库当前状态、用户没有说出口的真实意图、一次发布造成的影响，都属于环境。

环境远大于任何一次模型调用。Agent 无法同时接触其中全部内容。

#### Context Window

`Context Window` 是模型单次推理时能够容纳的 token 范围。它规定工作记忆的容量上限，也规定模型在这一轮可以同时注意多少文本信息。

一个拥有 100 万 token 窗口的模型，窗口里没有装入当前项目真源时，依然看不见真源。容量很大只说明桌面很大，没有说明桌面上摆了什么。

#### 上下文

上下文是这一轮实际交给模型的内容：System Prompt、用户请求、对话历史、记忆、检索材料、工具定义、工具返回结果和输出格式等。

Context Window 像容量，上下文像实际装载的内容。两者共同决定模型这一刻能直接处理的信息范围。

#### 世界模型

世界模型是 Agent 对“世界怎样组成、怎样变化、行动会带来什么后果”的内部表示。

模型训练期间会把大量规律压进参数。当前任务中，它又会根据上下文形成一个临时理解：哪些对象存在、彼此怎样关联、下一步可能发生什么。

在具身智能里，“世界模型”常常更强调感知与行动之间的动态预测，例如机器人向前移动后画面怎样变化、物体受到力后怎样运动。大语言模型也会形成关于语言、社会、代码和常识的内部规律，但把它称为完整、可靠的世界模型仍有争议。这里使用一个更稳妥的口径：

> 世界模型是 Agent 用来解释观察、预测后果和选择行动的内部结构。

四者的关系可以写成：

```text
外部环境
  ↓ Harness 选择与组织观察
当前上下文（装入 Context Window）
  ↓ 模型结合参数中的既有规律进行推理
临时世界模型
  ↓ 选择行动
环境发生变化
  ↓ 结果被观测和比较
反馈进入下一轮上下文
```

### Why 1：为什么上下文可以被称为 Agent 的“可见世界”

这里的“世界”是一种严格受限的说法。上下文没有覆盖完整环境，它构成了**环境向 Agent 显现的那一部分**。

一项事实只存在于外部环境、没有进入观察范围时，它无法直接参与当前决策。模型仍可能根据训练经验猜中，但猜测与读取事实拥有不同的证据地位。

例如，项目已经发布了新的 `SOURCE_OF_TRUTH.md`。模型只拿到旧计划和旧记忆时，它会在一个已经过期的世界里进行合理推理。推理过程可以非常聪明，结论仍然偏离现实。

所以，Context Engineering 处理的不只是信息数量。它处理的是：

- 哪些差异能够被 Agent 看见；
- 哪些事实拥有更高权威；
- 哪些过去状态已经失效；
- 哪些信息只是假设或第三方说法。

你在反馈里强调“索引够清晰，告诉它真源在哪里”，这对应**认识边界**。索引决定 Agent 去哪里接触当前事实，也决定哪些材料只能作为参考。

### What 2：行动能力里，Tool、MCP 与 Skill 各自是什么

你把 Tool、MCP、Skill 都放进行动能力，方向基本成立，但三者承担的角色存在差异。

- **Tool** 提供具体动作，例如读文件、运行命令、发送请求、创建文档。
- **MCP** 提供一种把外部数据与工具接入 Agent 的协议和接口层。
- **Skill** 提供针对某类任务的程序性知识、判断顺序与材料入口，也可能指导 Agent 调用 Tool。

Tool 与 MCP 更直接地扩展 Agent 能做什么、能观察什么。Skill 更接近一套局部策略：面对某类任务时怎样组织注意力、材料和动作。

一个 Agent 拥有“发布 Skill”却没有发布工具，它只能给出发布步骤。它拥有发布工具却缺少授权边界，行动能力已经存在，合法行动范围仍然不清楚。

你所说的“更清楚自己的边界”，对应**行动边界**：Agent 知道自己有哪些能力、哪些权限、什么时候必须停止并交给人。

### What 3：反馈质量与输入清晰度有什么区别

你把反馈质量理解为用户描述的清晰度。这个理解抓到了语言的重要性，但它对应的是**输入质量**。

输入发生在行动前，告诉系统目标、背景和约束。反馈发生在行动后，把实际结果带回系统，并与目标进行比较。

高质量反馈通常包含四个特征：

1. **可观测**：系统能看见真实结果，不能只听执行者宣称“完成了”。
2. **可比较**：结果能够与目标、标准或前一状态对照。
3. **可归因**：系统能判断差距可能来自哪个步骤或假设。
4. **够及时**：反馈到达时，系统仍有机会修正行动。

用户说“这篇写得很好”是一种反馈，但它提供的误差信号很少。用户指出“方向错了，我要研究 what 和 why”，反馈质量明显更高，因为它指出了偏差所在和新的方向。

测试结果、运行日志、真实用户反应、市场结果和人的批注，都可以成为反馈。语言清晰度影响反馈能否被理解，反馈质量还取决于它是否真实反映行动后果。

反馈使 Agent 的世界具有时间。没有反馈时，模型只面对一个静态截面；反馈回流后，系统才知道自己的行动改变了什么，并据此更新下一轮世界模型。

### Why 2：为什么有效智能属于模型与环境之间的关系

模型潜能仍然属于模型。一个更强的模型通常拥有更好的推理、迁移和规划能力。

有效智能描述这些潜能在具体任务里实现了多少。它受到观察、行动和反馈共同限制。

因此，第 9 篇的概念式可以进一步收紧：

> 有效智能 ≈ 模型潜能 × 观察质量 × 行动空间 × 反馈闭环

我之前很早、还在读高中的时候，我喜欢的一个博主就经常跟我说，要尊重规律，要去总结复盘。这些话听起来很大，但确实言简意赅、清晰易懂，非常质朴。

其实到了现在，在人和 Agent 这方面，这些规律其实是通用的。只不过人的上下文窗口更短，可能个体差异比较大，个体智能也有所不同。

- **观察质量**包含上下文是否相关、当前、可信，以及是否覆盖关键差异；
- **行动空间**包含可用工具、权限和可选择路径；
- **反馈闭环**包含结果能否被观察、比较并用于下一轮修正。

同一个底层模型，放进两个不同 Harness，会形成两个表现差异很大的 Agent。一个只读旧文档、只能输出文字；另一个能读取当前真源、调用工具、观察结果并修正。底层潜能相同，实际可用的智能不同。

Agent 因此更像一个持续运行的系统过程：

> 模型＋当前状态＋记忆＋目标＋工具＋反馈循环。

模型提供能力底座，Harness 提供 Agent 所处世界的接口。

### Why 3：谁组织上下文，谁就在参与塑造 Agent 的世界

你在第 9 篇修正后的“厚 Harness”有三项：

1. 责任边界完整；
2. 真源索引清晰；
3. 清楚自己的边界。

它们刚好对应三个层次：

| 你的表述 | 对应边界 | 它决定什么 |
|---|---|---|
| 真源索引清晰 | 认识边界 | Agent 可以把什么当成当前事实 |
| 清楚自己的边界 | 行动边界 | Agent 可以做什么、何时停止 |
| 责任边界完整 | 规范边界 | 什么后果不可接受、谁有最终决定权 |

这三条比“规则越多越厚”更接近 Harness 的深层结构。Harness 通过它们塑造 Agent 的可见世界、可行动世界和可负责世界。

你提出“法、器、术可以外包给 Harness，道由人处理”，这个方向成立。还可以增加一条限定：Harness 可以承载“道”的代理表达，例如原则、优先级和不可触碰的边界；它无法仅靠执行能力获得这些原则的合法来源。

人提供价值方向并承担后果，Harness 把方向转化成系统可执行的认识、行动与规范边界。模型在这些边界内进行推理和行动。

### 这一篇的核心区分

最后用两句话收束你最关心的混淆：

> **上下文是 Agent 当前能够接触的世界切片。世界模型是 Agent 对这个切片以及既有规律形成的内部理解。**

> **Harness 负责组织观察与行动的接口，反馈负责让这个世界随行动结果持续更新。**

具身智能中的世界模型更强调物理环境、感知和动作预测；你现在讨论的 Agent 世界更宽，还包括文件、规则、角色、工具、社会关系、权限和责任。

## 小结

1. 环境是外部现实，Context Window 是容量，上下文是实际装入的观察，世界模型是 Agent 内部的理解与预测结构。
2. 上下文构成环境向 Agent 显现的世界切片；未进入观察范围的事实无法直接约束当前判断。
3. Tool 与 MCP 扩展观察和行动，Skill 主要提供局部程序性知识与策略。
4. 输入清晰度发生在行动前；反馈质量取决于行动后的结果能否被观察、比较、归因并及时回流。
5. 真源索引、能力边界和责任边界分别塑造 Agent 的认识世界、行动世界和规范世界。

## 学习反馈

本篇可以优先回答：

> 如果同一个模型因为上下文、工具和反馈不同而表现得像两个不同的 Agent，你认为“智能”主要属于模型，还是属于模型与环境组成的系统？为什么？

如果一个模型因为上下文和工具反馈而表现得不同，甚至表现得像两个不同的 Agent，这确实很值得思考。

刚才跟 GPT 对话、获取更多相关信息的时候，我其实想到了一个比喻。我曾经在重点班，班里有两种学生：

第一种就像我的好兄弟。他不用怎么认真学，很快就能触类旁通。他极有天赋，在学习上非常聪明。这种可以称为“力大砖飞”的打法。他不需要很多次的反馈去微调，也不需要很多辅助工具，直接凭借强大的原生智能和超大的上下文（Context Window），直接“力大砖飞”。对于一个题型或一个问题，我们把题型泛化，把分数泛化为结果。在这个从问题指向结果的过程中，他不需要反复微调去解决，可能只需迭代一两遍，以后遇到同类问题就有了记忆，能很快处理。这种个体的模型机能非常强大。

第二种学生，可能原生的大脑机能不比第一类高，但他有很多工具和教辅，有无数个循环。他的环境足以支持他沉浸式地经历很多次“学习-反馈-微调”的闭环。他就一直刷题、一直刷题。这种叫做“天道酬勤”式打法。

但他们最后的差距并不大，至少没有肉眼可见的那么大，取得的结果是差不多的。

不过，我个人更喜欢跟第一类人玩，因为第一类人很有意思。我跟他聊心理学、聊社会学的东西，他都聊得来，很有灵性。而第二类人表现出来的就相对木讷一些，因为他在为人处事这些方面的投入和反馈微调太少了，时间全都投入到刷题和硬技能那边了。

用这个类比来表达：这得看具体的任务方向。

对于那种原生技能非常强的模型来说，它是“平均的好”，或者说“有偏好的好”。它百家争鸣、百花齐放，技能树全都点满了。

但如果是针对特定问题，那就不一定了。对于特定问题，两者的差距其实并不大。你得具体区分它的表现：
1. **平均很强（第一类）**：原生智能极高，综合能力强。
2. **环境与指标推动（第二类）**：在一个特定的工作环境或指标推动下去完成任务，追求在特定场景下最好的展现效果。

比如垂直类任务，如果我要生图，我肯定去找seedance、Midjourney 或者 Imagen 2.1，我不会去找别的，更不会去找 Gemini，因为在特定垂直领域它确实不够好。
