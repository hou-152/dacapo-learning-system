#### 已确认的事实

- AI 内参中可以找到系统性的 `Context Engineering` 材料。它把上下文工程解释为：选择正确材料、控制上下文膨胀、区分完整记录与工作记忆，并在长任务中使用检索、压缩和结构化笔记。
- Anthropic 对 `Context Engineering` 的公开定义是：在推理期间持续筛选和维护进入有限上下文窗口的信息；Agent 每运行一轮，都需要重新决定下一轮装入什么。[来源：Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

### What 1：Context Engine 到底是什么

AI 内参和 Anthropic 官方材料支持的是 `Context Engineering`。`Context Engine` 目前没有统一的标准定义。本课程给它一个操作性定义：

> **Context Engine 是 Agent 在每一步运行前，从环境、记忆、工具和历史中选择、压缩、排序并组装当前上下文的运行时机制。**

四个相近概念可以这样区分：

| 概念 | 它回答的问题 |
|---|---|
| Context Window | 最多能同时容纳多少信息？ |
| Context | 这一刻实际装入了什么？ |
| Context Engineering | 应该怎样设计和维护上下文？ |
| Context Engine | 谁在运行时执行选择、检索、压缩和更新？ |

一个 Context Engine 至少处理六种选择：

```text
保留什么
丢弃什么
现在检索什么
怎样压缩旧经验
按什么权威顺序排列
哪些结果进入下一轮
```

因此，它很像一个**注意力分配器＋记忆检索器＋证据编排器**。

因为在我学习 Transformer（之前谷歌提出的那个训练框架）的时候，它其实是一个在 3000 多个向量空间里面预测下一个 token 的工具，后面可能就是预训练和反馈微调。

对于这个 content  engine，我自己的理解（我自己的费曼）是：它有点类似“外接大脑”。

比如说，AI 是我的外接大脑，能够在我电脑里 400 多 G 的内容中一下子找到我需要的东西（如果我自己找可能要找很久）。它帮我节省了注意力，帮我去找东西在哪里。

还有什么“真源”对吧？“证据链真源”或者“证据编排器”，它会告诉我说某某文件的真源在哪里。

所以它的目的，我认为是让 content engine的目的，也就是让下一个预测的 token  更准

它接收的输入通常包括：

- 当前目标与任务状态；
- 已知事实和不确定性；
- 长期记忆与外部索引；
- 可用工具和信息成本；
- 上一轮行动及环境反馈；
- 权威来源、权限和责任边界。

它输出下一次推理可以看见的世界切片，答案随后才由模型生成。

### Why 1：选择上下文为什么已经是一种控制权

推理只能基于当前可见的差异展开。一条事实被留下、压缩、降权或删除，都会改变 Agent 后续能够形成的世界模型。

例如，同一个 Agent 要判断项目是否完成：

- 只看到总结报告，它可能接受“已经完成”；
- 同时看到失败日志、验收标准和当前文件状态，它可能判断“仍未闭环”；
- 只看到旧状态，它可能在一个过期世界中做出逻辑完整的错误判断。

Context Engine 因此拥有一种**认识论控制权**：它决定哪些证据有机会参与判断。

这种控制权有四类典型风险：

1. **遗漏**：关键事实没有被检索；
2. **失真**：压缩丢掉了限定条件；
3. **错序**：旧记忆压过当前真源；
4. **自我封闭**：Agent 只检索支持已有假设的材料。

当 Agent 可以自主搜索和选择上下文时，它获得了更大的认识自主性，也同时获得了制造自洽幻觉的能力。

### What 2：Harness 映射到人类时对应什么

Harness 映射到人类时是一整套认知生态，无法压缩成单个器官。

| Agent 系统 | 人类近似映射 | 边界 |
|---|---|---|
| 基础模型 | 大脑、既有知识与先天倾向 | 模型参数和生物大脑没有一一对应关系 |
| Context Window | 工作记忆的有限容量 | token 容量和人类工作记忆属于不同机制 |
| Context Engine | 注意控制、记忆提取、问题意识与信息筛选 | 人还会受到情绪、身体和社会关系影响 |
| 长期记忆 | 生物记忆＋笔记、书籍和知识库 | 外部记录需要检索与重新理解 |
| Tools | 语言、纸笔、软件、搜索、仪器和他人 | 工具扩大行动，不能自动提供判断 |
| Evaluator | 现实后果、老师、同伴、实验和复盘 | 评价标准本身也可能失真 |
| Harness | 习惯、方法、环境、工具、反馈与制度组成的认知生态 | 它同时包含支持、约束和责任分配 |

你说自己是“短上下文窗口的人”，这个比喻抓住了注意力稀缺。它的适用边界也要保留：人类会通过长期记忆、线索唤醒、身体技能和外部环境重建当前思考，工作记忆无法用一个固定 token 数表示。

更准确的说法是：

> **人的当前注意力很窄，但人的认知系统可以跨大脑、身体、工具、他人和环境延展。**

所以，人类的 Context Engine 由三部分共同组成：

```text
内部注意控制
＋长期记忆检索
＋外部信息环境的组织
```

你为什么会被 Claude 的“人味”和判断吸引？因为对话对象也在成为你的外部认知环境。它提供的价值有时是事实，有时是新的问题表征、情绪反馈或你原本没有注意到的关系。

### Why 2：珍惜 token，是否意味着脑中只保留“道”

你的方向成立：高复用、强迁移、能指导判断的结构值得优先内化；易变化、低频和可精确检索的细节适合放在外部系统。

还需要增加两个边界。

#### 第一，抽象需要现实材料供养

“道”是一种高压缩表征。它来自案例、行动和反馈，也要持续接受反例修正。缺少事实与经验后，抽象概念容易变成无法证伪的口号。

#### 第二，一部分“法、术、器”需要形成自动化

语言、基本计算、检索习惯、证据意识和常用操作如果每次都从外部重新读取，认知成本会非常高。它们进入长期记忆和身体化习惯后，反而为高层判断释放工作空间。

因此，内部与外部的分工更接近：

| 优先内化 | 优先外部化 |
|---|---|
| 高复用概念与因果关系 | 易变化的事实和当前状态 |
| 判断边界与个人价值 | 低频工具语法和精确步骤 |
| 发现错误的元认知习惯 | 完整历史、日志与证据包 |
| 需要即时调用的基础技能 | 可以按需检索的专业细节 |

珍惜 token 的含义由此变得更精确：把有限注意力留给当前决策中最有杠杆的差异，让外部系统负责保存和召回其余信息。

### What 3：Curriculum 与 Context Engine 有什么关系

Context Engine 解决“这一刻看什么”。Curriculum 解决“接下来依次经历什么”。

Curriculum 是跨时间的经验选择策略。Bengio 等人在 2009 年的 Curriculum Learning 研究中讨论了训练样本顺序：从较容易的概念逐步进入更复杂的概念，可以改变收敛速度和最终学到的结构。[来源：Bengio 等，2009](https://icml.cc/2009/papers/119.pdf)

对，它其实就是训练样本顺序从比较容易的概念往复杂概念过渡。这符合我们所说的“学习科学”的内容，也就是我们的“知识树”：

1. 树干：代表这个学科的第一性原理
2. 树杈：代表思维模型
3. 树叶：代表概念性问题

而我们从容易的概念进入更复杂的概念，容易让我们的这棵“知识树”更加繁密和复杂。

也就是说，在设计当初，如果我们能有一个比较好的设计，就可以从一个相对简单的概念设计到更复杂的概念。

不过，我觉得这最终还是跟人的内驱力有关。我们可以从外部进行设计，但无法从内部去设计它。这取决于我们个人的内驱力，也就是渴望学习的“高认知需求”——我对这个很好奇、很热爱，我要一直拼命地往下面去学。

对人和 Agent 来说，一段经验的价值取决于当前能力状态：

- 过于简单，几乎没有新的误差信号；
- 过于困难，反馈可能只剩混乱与随机失败；
- 难度适中，系统能够利用已有结构吸收新差异。

婴儿注意力研究观察到类似的“Goldilocks Effect”：实验中的婴儿更愿意关注复杂度适中的视觉序列，对过于简单或过于复杂的序列更容易移开注意。[来源：Kidd、Piantadosi 与 Aslin，2012](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0036399)

Curriculum 因此做两件事：

1. 选择下一个有学习价值的差异；
2. 调整差异出现的顺序，让旧结构可以支撑新结构。

### Why 3：谁写课程表，谁就在塑造智能的发展方向

一个 Agent 的课程表可以来自四个地方：

| 课程来源 | 优势 | 风险 |
|---|---|---|
| 固定题库／Benchmark | 清晰、可比较 | 容易过拟合既定分布 |
| 人类教师／系统设计者 | 能注入目标和阶段判断 | 教师偏见会进入学习路径 |
| 真实环境与任务 | 反馈具有现实性 | 经验稀疏、风险和成本较高 |
| Agent 主动探索 | 能发现未知缺口 | 可能追逐新奇或自证循环 |

这个其实就是最前沿的 Loop engine，或者说叫做学习循环。当这个循环能够彻底完成的时候，我操，嚯，AI 超进化，奇点时刻！

“自主 Agent”也需要分层：

1. **执行自主性**：自己选择怎样完成当前任务；
2. **认识自主性**：自己选择检索什么信息；
3. **发展自主性**：自己选择下一项要学习的任务；
4. **规范自主性**：自己选择最终目标与价值标准。

Context Engine 扩大第二层，自动 Curriculum 扩大第三层。第四层涉及权力、价值和责任，不能随着工具能力增长而默认交给 Agent。

你在前面形成的判断由此得到延伸：

> 人提供“为什么学、什么后果不可接受”，Curriculum 决定“下一段经历什么”，Context Engine 决定“当前看见什么”，Agent 决定“怎样行动”。

### What 4：Learning velocity 到底应该测量什么

“学习速度”至少有三种完全不同的口径：

| 速度 | 分子是什么 | 它能证明什么 |
|---|---|---|
| 内容覆盖速度 | 看过的章节、概念或视频数量 | 接触材料的速度 |
| 辅助表现速度 | 有 AI 帮助时的答题或完成增量 | 人机系统的即时表现 |
| 可持续学习速度 | 撤掉教学支架后仍能保持和迁移的能力增量 | 学习者形成能力的速度 |

短视频中的“一周过完一门心理学”首先证明内容覆盖。要进入学习结论，还需要延迟测试、迁移任务、独立表达和真实应用。

本课程可以把 Learning velocity 暂时定义为：

> **可持续学习速度 ≈ 在陌生任务中仍能调用的能力增量 ÷（时间＋外部干预成本）**

这个式子延续第 11 篇的技能获得效率，强调三个限制：

- 能力需要在 AI 支架减弱后保持；
- 能力需要迁移到表面不同的新问题；
- 速度不能靠转移大量隐形教师成本来虚增。

AI 教育实验之所以会得到不同结果，关键原因也在这里。经过课程设计、问题脚手架和反馈控制的 AI Tutor 可以加速学习；随时直接给答案的 AI 可能加速练习完成，同时削弱独立学习。

教育可及性也要和教育结果分开。AI 可以降低知识解释、个性化反馈和练习陪伴的边际成本，这为更广泛的学习机会提供条件。设备、目标、元认知、反馈质量、家庭环境和判断能力仍然存在差异，所以“获得 AI”本身不能证明教育结果已经平等。

### 回到你想要的第一类 Agent

你提出两个判断 Agent 学会了的信号：Container Image 中形成知识沉淀，以及经验跨任务迁移后形成 Skill。它们分别对应**持久化**和**压缩**，还需要另外两块证据才能形成完整链条：

| 证据 | 要观察什么 |
|---|---|
| 持久化 | 经验跨会话存在，来源和适用范围清楚 |
| 压缩 | 多个案例被提炼成较少的可复用结构 |
| 迁移 | 新任务没有复现旧题面，系统仍能正确调用结构 |
| 干预下降 | 面对同等新奇度的问题，需要的人类纠正减少 |

知识库文件和 Skill 文件只能证明资产存在。Agent 在什么情况下主动检索、怎样处理反例、何时停止使用旧策略，决定这些资产是否已经成为认知系统的一部分。

Container Image 还存在一个特殊边界：它擅长保存稳定快照，却可能冻结过期知识。对动态事实而言，清晰索引和刷新机制比“已经打包进去”更重要。

### 把整条链串起来

```text
人类价值与责任边界
        ↓
Curriculum 选择下一项值得经历的任务
        ↓
Context Engine 组装当前最有价值的世界切片
        ↓
Agent 形成判断并行动
        ↓
环境与 Evaluator 返回结果
        ↓
经验被保留、压缩、迁移或淘汰
        ↓
学习进度改变下一轮 Curriculum
```

Context Engine 管理注意力，Curriculum 管理成长方向，Evaluator 管理误差信号。三者共同决定一个 Agent 最终长成哪一种“学生”。

## 小结

1. Context Engineering 是设计上下文的策略集合；Context Engine 是本课程对运行时选择、检索、压缩和组装机制的操作性定义。
2. Harness 映射到人类时是一套认知生态；人的 Context Engine 近似由注意控制、长期记忆检索和外部信息环境共同组成。
3. Curriculum 决定经验的顺序。选择什么任务、以什么难度出现，会改变学习速度和最终形成的能力结构。
4. Learning velocity 需要区分内容覆盖、辅助表现和可持续能力增长；只有保持与迁移进入测量，速度才接近学习。
5. 知识库和 Skill 提供持久化与压缩证据，跨任务迁移和干预下降才能继续支持“Agent 学会了”的判断。

## 学习反馈

本篇可以优先回答：

> 对你自己这个“人肉 Agent”来说，哪些东西应该进入脑中的长期结构，哪些东西应该交给 Context Engine 按需召回？你怎样区分学习速度的提高与阅读、调用 AI 速度的提高？

关于“如何构建长期结构、区分学习速度的提高、阅读以及提高调用 AI 的速度”，我分享一下我自己的实践和思考。

一、 如何构建知识的“长期结构”？

我个人的做法主要依赖以下三个核心维度：
1. 元认知：对自身认知过程的审视与调控。
2. 对一个问题的反复思考。
3. 内驱力。

在思维模式上，我们要常常去追求“第一性原理”。通过不断的判断与综合，让这些深度的思维产物进入脑子，在脑海中自然生长出知识的“长期结构”。

至于哪些东西应该交出去，转化为“content image”并按需召回？
我的实践是：大部分内容我直接外包给我的 Agent。不过我目前也有没做好的地方，比如对于一个长期问题的持续性回答，我还没有养成良好的记录和沉淀习惯。像“电脑文件在哪里”、“我们现在推进到哪一步了”这类日常琐事，完全可以交给 Agent 去按需召回。


二、 怎么样区分自己“学习速度的提高”与“阅读”？

对于这个问题，我的理解是：
1. 学习速度的提高：
   对我而言，最快的方式已经不是传统的阅读了。我的原则是“如非必要，无需读书”。我用 DBS（dbskill-learning）这种一对一反馈的交互式学习（Learning）来极大地提高学习速度。我现在的微信读书已经完全荒废，会员过期后也一直没有续费。
2. 阅读的本质：
   当然，有些时候我们确实需要牺牲阅读体验，放慢速度去静下心来阅读。就像 Don 哥（Don't Be Silent）提到过的“马斯克定言”或相关原则。这种阅读的目的不是为了快速获取信息，而是在阅读过程中引发深度思考，去感受文字背后的精神和使命感。


三、 如何提高调用 AI 的速度？

关于如何提高 AI 的响应和处理速度，我个人的经验是：
在调用时，一定要先限定并给足它上下文。

比如在交互式学习时，我会直接给它提供一些 AI 内参的 API 和 Skill，并附带上我们聊天时使用的上下文。有了这些充足的背景信息，AI 很快就能理解我们的意图，它的处理和响应速度自然就会快很多。
你可以写：

1. 哪里看懂了？
2. 哪里没看懂？
3. 哪个地方想展开？
4. 这个主题和你的真实问题有什么关系？
