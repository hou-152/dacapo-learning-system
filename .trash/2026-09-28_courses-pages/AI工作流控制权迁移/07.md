## 最小知识地图

### 1. 先理清一个关系：三种驱动力 × 你的三词公式

你在 06 检查站里写：

> 「"厚"是指把强模型的一些东西给内化掉了——利用强大的模型能力，把人设类、规范类的东西进行部分内化。」
> 「"薄"则体现在两个方面：去驱动力、控制迁移变成具体的 Skill。」

把三个东西和三种驱动力的对应关系拉直：

```
强模型（驱动力 A：模型能力内化）
    → 导致：Skill 变薄
    → 原因：模型自己会思考、会分析、懂方法论，不需要你在 Skill 里写
    → 薄掉的内容：思考脚手架、人设描述、通用方法论

厚 Harness（驱动力 B：工程控制点迁移）
    → 导致：Harness 变厚
    → 原因：被模型吃掉的那些控制逻辑并没有消失——它们从 prompt 文本迁移到了系统规则、权限、验证和调度逻辑
    → 厚出来的内容：触发条件、工具边界、验证规则、公理约束

注意力瓶颈（驱动力 C）
    → 导致：这两件事同时发生有价值
    → 原因：如果人的注意力无限，你不需要薄 Skill 也不需要厚 Harness——你每次手动盯着就行
    → 你的原话："什么都重要，就等于什么都不重要"——这就是注意力瓶颈在说话
```

你说的「厚 = 内化」其实是把两件事叠在一起了：模型内化了通用能力 **导致** Skill 变薄（这是驱动力 A 的效果），同时 Harness 变厚来接住那些不能内化的判断和调度（这是驱动力 B 的效果）。不是「厚 = 内化」，是「内化 → 薄 + 剩下的控制 → 厚」。

你的「共同产出 = 对人吝啬的注意力」是对的。三种驱动力最终都指向同一件事：**让人只在必须做判断的节点介入。**

### 2. 什么是「最小 Loop」——不是五个 Agent 跑一天，是一个能闭环的单次运行

你 03 里说 Loop 是「每个任务都有是/否阶段，通过了才推进」。你 04 里说「Loop 的核心在于把一些判断丢给 AI，让 AI 实现自动化」。

现在把这个理解落地：一个最小 Loop 只需要五个组件，跑一次就能闭环。

**心跳（Heartbeat）**：
什么事件触发一次 Loop 运行？不是「每天 9 点」，而是「系统状态发生了什么变化」。比如：阅读库中出现了一篇新文章 = 触发一次 Loop。

**输入（Input）**：
这一轮 Loop 需要的最小信息。来自来源池或上一次 Loop 的产出。比如：新文章的标题、正文、来源。

**处理（Process）**：
一个或多个薄 Skill 被 Harness 调度执行。每个 Skill 只有四个字段——触发条件、输入、动作、验证。比如：三级笔记 Skill 把文章压缩成三层结构。

**验证（Verify）**：
处理完之后，怎么知道这一步做对了？不是「质量达标」，而是可检查的条件。比如：每一层笔记非空、不超过原文 30% 篇幅、关键概念名称未被弄丢。

**决策（Decide）**：
验证通过 → 进入下一步（下一篇文章 / 发布 / 存档）。验证不通过 → 重试 1 次 → 仍不通过 → 标记为「需人工审核」，通知人。

五个组件不是五个独立的软件模块。它们是一次 Loop 运行中的五个阶段。一次跑完就是一圈。

### 3. 用你的「三级笔记」当样本，画一圈

你的三级笔记 Skill 在 06 费曼里是这么描述的：

> 「丢给它一篇很长的文章，触发条件 "/"，使用三级笔记压缩方法。不要过度压缩文章。产出后让 Agent 让人去看一眼，确认没问题就 OK。」

把这段话扩成一个最小 Loop：

```
═══════════════════════════════════════
心跳（触发条件）：
  阅读库中出现了一篇新文章，该文章的「三级笔记」字段为空。

输入：
  该文章的标题、作者、发布日期、正文 Markdown。

处理（薄 Skill: 三级笔记）：
  触发条件: Harness 检测到阅读库中有文章等待三级笔记处理
  输入: 单篇文章的完整正文
  动作:
    1. 第一层（1-2 句）：这篇文章的核心主张是什么？
    2. 第二层（3-5 句）：支撑这个主张的关键论据或案例。
    3. 第三层（2-3 句）：这个主张对我的系统意味着什么？（可操作、可验证的下一步）
  验证:
    - 每层非空
    - 总篇幅不超过原文 30%
    - 关键概念名称和数值未被弄丢（与原文交叉比对 1 次）

验证（Harness 层）：
  - 产出符合上述三个条件？
    ├─ 是 → 写入阅读库该文章的「三级笔记」字段 → 进入决策
    └─ 否 → 重试 1 次 → 仍不通过 → 标记「三级笔记失败」，通知 Da Capo

决策（人的判断节点）：
  系统状态变化：「三级笔记」字段已填充。
  通知 Da Capo：「{文章标题} 的三级笔记已生成，请确认。」
  Da Capo 确认后 → 该文章可以被概念提取 Skill 消费。
  如果不确认 → Da Capo 在笔记上批注修改 → 系统更新该字段 → 进入概念提取的触发条件。
═══════════════════════════════════════
```

注意这个 Loop 的几个关键设计：

**Skill 是薄的。** 三级笔记 Skill 没有写「请深度理解文章」「从多个维度分析」，只写了三层结构 + 不超 30% + 关键信息不丢。模型自己知道怎么理解文章。

**验证是可检查的。** 「每层非空」「不超 30%」「关键概念不丢」——每一项都可以被 Harness 自动检查，不需要人看每一篇。

**人的介入点精准。** 人不是每篇都盯——系统标记失败时才找人。正常通过的，人只做最终确认。你的注意力用在了「判断这篇笔记能不能用」这一个决策上，而不是「阅读→理解→压缩→检查」整个过程。

**产出变成下一个触发条件。** 三级笔记完成后，系统状态从「待处理」变成「笔记已生成」，这个状态变化就是概念提取 Skill 的触发条件。不需要人手动说「好，下一步做概念提取」。Loop 自己往下走。

### 4. 这个 Loop 把你的前六篇全串起来了

| 你学过的 | 在 Loop 里的位置 |
|---------|---------------|
| 任务锚点（02） | 心跳——「三级笔记字段为空」就是本轮锚点：判断这篇文章值不值得做笔记、笔记要做到什么深度 |
| 来源池（02） | 阅读库就是来源池——文章躺在里面，等心跳触发 |
| 证据包（02） | 输入——不是读整个阅读库，只取当前这一篇文章 |
| Loop 决策循环（03） | 处理→验证→决策→下一轮心跳——五步闭环 |
| 三种驱动力（04） | 强模型让三级笔记 Skill 可以很薄；控制迁移让验证规则活在 Harness 而不是 prompt 里；注意力瓶颈决定了人只在最终确认介入 |
| Harness 五层（05） | 心跳→规则层 / 阅读库→记忆层 / 处理→调 Skill / 验证→验证层 / 决策→人的判断节点 |
| 薄 Skill 四字段（06） | 三级笔记 Skill = 触发条件+输入+动作+验证，不写模型已知的通用内容 |

这个 Loop 不是新概念。它就是你把前六篇的零件拼在一起，让它们能自己转一圈。

### 5. 你不需要一次性建完整个系统

你 06 里有一段很实在的分析：

> 「现在的 Agent 在 ToB 公司的落地，更多的是成本问题。高智能模型确实没问题，但是太贵了。所以大概率要把任务分流：简单的交给便宜模型，难的交给 Fable 5。」

这个判断可以直接用到你自己的 Loop 设计上：

- **不需要一上来就把所有 Skill 都改成薄的四字段。** 先改一个你用得最多的——三级笔记或龙虾日报——跑一圈看看。
- **不需要把所有触发条件都自动化。** 先让一个心跳跑通——比如「阅读库有新文章」→ 三级笔记 → 人确认——这一圈跑顺了再加下一个。
- **成本不是你现在的瓶颈，但复杂度是。** 你的系统目前最大的成本不是 token，是「记不住自己有什么规则、什么 Skill、什么时候该用哪个」。一个最小 Loop 先解决这个问题。

## 小结

1. «厚 Harness / 薄 Skill / 强模型» 和三种驱动力的对应关系：强模型（A）→ Skill 薄；控制迁移（B）→ Harness 厚；注意力瓶颈（C）→ 这两个变化有价值。
2. 最小 Loop = 心跳（触发）→ 输入 → 处理（薄 Skill）→ 验证（Harness 可检查条件）→ 决策（继续/重试/交给人）。五个阶段跑一圈。
3. 你的三级笔记工作流已经可以画成一圈 Loop——缺的不是新概念，是把已有的零件拼起来。
4. 人的介入点只有一个：决策。其他四个阶段 Harness + 薄 Skill 自动跑。
5. 不用一次性建完——先改一个 Skill，先跑通一圈，成本不是你现在的瓶颈，复杂度才是。

## 检查站

1. 最小 Loop 的五个阶段是什么？每个阶段产出的东西是什么？
2. 你的三级笔记工作流里，现在最缺 Loop 五个阶段里的哪一个？

最小的 loop（闭环）的五个阶段是：心跳、输入、处理、验证、决策。

这五个阶段的具体运行流程如下：

1. 心跳（Heartbeat）
   心跳任务负责定时检测和触发。比如在某一个工作空间里，系统会去检测有没有新产出什么内容；或者设定一个定时任务，每半个小时触发一次心跳，去检测工作空间里出现了什么新内容，并对其进行预处理。

2. 输入（Input）
   当心跳任务检测到新内容并确认其存在后，就会把这个内容提取出来，丢给 Agent 的对话窗口，作为输入源。

3. 处理（Process）
   Agent 接收到输入后，会按照设定的工作流进行处理。比如调用大模型，采用类似 LLM Wiki 方式对内容进行预处理，并将其整理放入知识库中。

4. 验证（Validation）
   对 Agent 处理完的结果进行验收，检查处理后的内容是否合格。

5. 决策（Decision）
   根据验收结果做出决策。如果确认大模型处理的内容没有问题，就通过并进入下一步。
