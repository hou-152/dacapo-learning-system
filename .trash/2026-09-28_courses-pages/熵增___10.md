10｜从个人工作流到团队协作：AI 使用怎样制造或降低组织熵
==============================

这一篇要解决的问题
---------


这一篇只解决一个问题：同一个 AI 工作流，为什么一个人用时很顺，放进团队以后可能让协作更乱；团队要用什么结构把它接住。


正文
--


前面几篇主要看个人系统：你用 AI 写文章、读报告、改代码、整理信息，重点是判断它有没有减少你的总成本。


一旦进入团队，问题会变复杂。AI 输出不只影响你，还会影响别人怎么理解、怎么接手、怎么审查、怎么追责、怎么维护。


这就是组织熵。


可以先用一句话理解：



> 
> 组织熵 = 团队里的信息、责任、接口、记录和行动越来越难对齐。
> 
> 
> 


AI 工具进入团队后，会放大两种东西：


* 放大好的结构：清晰任务、稳定格式、证据链、责任人、复盘记录。
* 放大坏的结构：模糊需求、口头约定、没人负责、输出堆积、版本混乱。


同一个工具，放进不同组织，结果会完全不同。


### 1. 个人熵和组织熵的差别


个人使用 AI 时，主要成本在你自己身上：



```
我是否看得懂？
我是否能验证？
我是否能行动？
我是否能恢复？

```

团队使用 AI 时，成本会分散到多人之间：



```
谁提出需求？
谁使用 AI？
谁审查输出？
谁决定采纳？
谁执行行动？
谁维护后续版本？
错了以后谁负责？

```

个人系统里，很多东西可以靠脑子记。团队系统里，靠脑子记会迅速增加组织熵。


比如一个人用 AI 总结会议，自己看懂就行。团队用 AI 总结会议，至少要说明：


* 这份总结基于哪次会议？
* 哪些结论已经确认？
* 哪些只是 AI 整理？
* 哪些行动有负责人？
* 哪些内容需要二次确认？
* 后续更新写在哪里？


这些问题没有被接住，AI 总结越多，组织越乱。


### 2. AI 在团队里最常见的 5 种增熵方式


第一，输出没有来源。


AI 生成了一段分析、一个方案、一组结论，但没人知道它基于什么材料。团队讨论时，每个人都在猜这段话的可信度。


第二，责任人消失。


“AI 说的”很容易变成责任真空。有人复制 AI 结论，有人转发，有人执行，但没人对判断负责。


第三，版本分叉。


不同人让 AI 改同一个文档、方案或代码，最后出现多个相似版本。大家看起来都在推进，实际合并成本暴涨。


第四，格式不稳定。


每次输出结构都不一样：今天是长文，明天是表格，后天是清单。接手的人要重新理解格式，维护成本上升。


第五，行动接口缺失。


AI 输出很完整，但没有负责人、截止时间、判断标准和下一步动作。团队获得更多内容，同时获得更多悬而未决。


这 5 种增熵方式有一个共同点：AI 降低了生成成本，但提高了团队对齐成本。


### 3. 团队使用 AI 的四个接口


要降低组织熵，团队要给 AI 工作流加接口。


接口可以很轻。它只是告诉大家：输入从哪里来，输出交给谁，谁判断，错了怎么处理。


可以用四个接口看。


#### 输入接口


输入接口回答：



```
AI 可以使用哪些材料？
哪些材料禁止使用？
材料的新旧版本怎么区分？
输入是否需要附来源？

```

例子：



```
所有市场分析必须基于：
1. 原始公告链接
2. 数据来源日期
3. 最近一次会议纪要
4. 明确标注的假设

```

输入接口清楚，后面就更容易验证。


#### 输出接口


输出接口回答：



```
AI 输出必须长什么样？
哪些字段固定？
哪些字段可以自由发挥？
哪些内容必须标注不确定性？

```

例子：



```
每份 AI 市场摘要固定 5 个字段：
1. 结论
2. 证据
3. 反方信号
4. 不确定点
5. 建议下一步

```

输出接口清楚，接手的人不用重新猜结构。


#### 判断接口


判断接口回答：



```
谁有权采纳 AI 输出？
谁负责否决？
什么情况下必须人工复核？
哪些判断禁止直接自动执行？

```

例子：



```
AI 可以生成候选判断，但涉及预算、客户承诺、代码合并和投资动作时，必须由负责人确认。

```

判断接口清楚，责任就能留在人身上，避免被“AI 说的”稀释。


#### 恢复接口


恢复接口回答：



```
错了以后在哪里查？
怎么知道谁改了什么？
怎么回到上一个版本？
怎么记录这次错误？

```

例子：



```
代码用 Git。
文档用版本记录。
任务用 issue。
关键判断保留来源链接和采纳时间。

```

恢复接口清楚，团队才敢用 AI 加速。


### 4. 一个例子：团队用 AI 写周报


假设一个团队开始用 AI 写周报。


表面上看，它省了很多成本：


* 每个人不用从零写总结。
* AI 能把零散信息整理成完整文本。
* 管理者能更快看到进展。


但组织熵可能开始上升。


常见问题：



```
每个人提交的信息格式不同。
AI 把未确认事项写成确定结论。
周报里有很多漂亮表述，但没有负责人。
本周和上周的口径不一致。
问题被总结掉了，行动没有落下去。

```

如果没有接口，AI 周报会制造一种“看起来很清楚”的幻觉。团队读完以后，仍然不知道谁要做什么。


要降熵，可以给周报加结构：



```
输入接口：
- 每个人只提交事实、阻塞、风险、下周动作四类信息。

输出接口：
- 周报固定输出：本周进展、阻塞事项、风险、需决策问题、下周动作。

判断接口：
- “需决策问题”必须有负责人确认。

恢复接口：
- 每期周报保留原始输入链接，关键改动记录在版本历史里。

```

这样 AI 仍然可以写周报，但它被组织结构接住了。


### 5. 团队 AI 工作流的净降熵检查


个人版决策卡问 5 个问题。团队版也可以压成 5 个问题。



```
团队 AI 工作流净降熵检查

1. 输入是否有来源？
2. 输出是否有固定结构？
3. 判断是否有负责人？
4. 错误是否有恢复路径？
5. 结果是否落到行动人和截止时间？

```

这 5 问可以挡住大部分组织熵。


比如一个 AI 方案文档：



```
输入有来源：引用了用户访谈、数据看板、历史方案。
输出有结构：背景、问题、方案、风险、下一步。
判断有负责人：产品负责人决定是否采纳。
恢复有路径：保留文档版本和变更记录。
行动有接口：每条下一步都有负责人和时间。

```

这样的 AI 输出更容易进入团队协作。


如果 5 问里有 3 问答不上来，先不要扩大使用范围。


### 6. 组织降熵的关键动作：把 AI 输出变成可接手对象


团队不缺内容。团队缺的是可接手对象。


可接手对象有 5 个特征：



```
有来源：别人能知道它从哪里来。
有结构：别人能快速读懂它。
有负责人：别人知道该找谁确认。
有状态：草稿 / 已确认 / 待复核 / 已执行。
有下一步：别人知道接下来做什么。

```

AI 输出只要缺其中两三个，就容易变成组织负担。


比如：



```
“这是 AI 生成的一份竞品分析，大家看看。”

```

这句话会增加组织熵，因为“大家看看”没有接口。


换成：



```
“这份竞品分析基于 3 个官网页面和 2 篇访谈，状态是草稿。请产品负责人只确认第 2 节的差异判断，今天 18:00 前决定是否进入下周需求讨论。”

```

这句话更降熵，因为来源、状态、负责人、范围、截止时间都清楚。


### 7. 个人到团队的升级规则


一个 AI 工作流从个人使用升级到团队使用前，可以先过这张表。



```
个人到团队升级检查

1. 我自己能用顺，不等于团队能接住。
2. 进入团队前，先固定输入和输出格式。
3. 涉及判断时，必须指定负责人。
4. 涉及文件、代码、客户、钱时，必须有恢复路径。
5. 每个 AI 输出都要压成一个行动接口。

```

这张表的核心是：先接住，再放大。


AI 可以放大生产力，也可以放大混乱。组织结构决定它放大哪一边。


小结
--


* 个人 AI 工作流主要看自己的判断、验证、行动和恢复成本；团队 AI 工作流还要看多人之间的信息、责任、接口和记录。
* AI 在团队里常见的增熵方式包括来源缺失、责任人消失、版本分叉、格式不稳定和行动接口缺失。
* 团队要用输入接口、输出接口、判断接口和恢复接口接住 AI 工作流。
* 团队版净降熵检查可以压成 5 问：来源、结构、负责人、恢复路径、行动人和截止时间。
* 一个 AI 输出进入团队前，要先变成可接手对象：有来源、有结构、有负责人、有状态、有下一步。
