# 10.6｜证据齐全才算完成：一个真实文件任务

## 承接说明

你在 10.5 里写了：`agent 完成指令，这样就算完成了。` 这句话暴露了本轮关键断点：完成还停在 Agent 的声明上，没有落到证据。本篇因此继续缩小范围，只练一个真实文件任务：把“下一篇”这件事写成可检查的完成标准。

## 这一篇要解决的问题

这一篇只解决一个问题：怎样把“Agent 完成了”改写成“证据齐全，所以人可以判断接近完成”。

## 正文

你已经有一个好比喻：

```text
Loop 是流水线。
Harness 是车间。
```

现在补最后一块：验收单。

流水线说“产品下线了”，不等于产品能交付。车间说“流程跑完了”，不等于结果可信。人要看验收单。

在 Agent 工作流里，验收单就是证据包。

### 1. 本轮真实任务

我们不用抽象例子，直接用当前课程：

```text
任务：用户说“下一篇”后，Codex 处理 10.5 的答案，并决定是否生成 11.md。
```

这个任务不能用一句话验收：

```text
Agent 已经完成指令。
```

这句话太松。

合格验收要写成：

```text
10.5 的用户答案已经读取；
10.5-批注回应报告已经生成；
learner-log 已写入 10.5 的分数和掌握判定；
路径裁决已经写明：进入 11.md，还是继续补救；
若生成新篇，新篇通过审计；
INDEX 和学习计划已同步更新。
```

这才叫证据齐全。

### 2. 五槽合格答案

同一个任务，写成 Loop 五槽：

```text
触发：
用户说“下一篇”，且 10.5.md 里已经有回锅测试和检验题答案。

状态：
读取 10.5.md 的用户答案、10.5.md 正文、learner-log、00-学习计划.md、INDEX.md。

工具动作：
生成 10.5-批注回应报告；批改 10.5 答案；更新 learner-log；根据掌握判定决定生成 11.md 或 10.6.md；生成后做审计。

反馈信号：
回锅测试分数、本篇检验题分数、五槽是否逐项完整、四槽是否逐项完整、是否把 Agent 声明误当作完成证据。

停止条件：
批注回应报告存在；learner-log 有 10.5 记录；路径裁决明确；新篇文件和审计文件存在；计划和 INDEX 已同步。
```

你后面写任何 Agent 任务，都可以照这个格式。

### 3. 四槽合格答案

再写成行动四槽：

```text
谁：
Codex 里的 dbs-learning agent。

什么时候：
用户说“下一篇”，且上一篇已有可批改答案时。

做什么：
结算上一篇答案，写批注回应报告，更新 learner-log，按掌握判定生成下一篇或补救篇。

怎样算完成：
回应报告、learner-log、新篇或补救篇、审计文件、学习计划和 INDEX 都已更新；人能打开这些文件检查路径裁决。
```

注意最后一句。

完成标准一定要让人能检查。

### 4. 最大尝试次数

你写过：“学了两遍还是学不会，需要一个 good prompt 去干预，搭一个更好的脚手架。”

把它改成可执行规则：

```text
最大尝试次数：
同一个动作接口断点最多补救 2 次。

超过 2 次仍然不过：
停止生成新篇；
把断点转成 good-question；
只做一个更小的脚手架练习。
```

这条已经很接近合格。

关键是把“学不会”换成可观察证据：

```text
连续 2 次检验题中，五槽或四槽仍缺 2 项以上。
```

这样系统知道什么时候停。

### 5. 人工升级点

你写“skill 导出来之后，要怎么去升级”，这个方向偏大。

当前任务里，人工升级点可以更具体：

```text
需要人判断的升级点：
1. 10.5 的答案无法判断是不是用户新增内容。
2. 10.5 的分数显示需要补救，但用户想换学习目标。
3. 同一断点已经补救 2 次，仍然缺 2 个以上关键槽位。
4. 下一篇需要引入新材料，但当前主教材不够。
5. 是否把课程收束成 skill，需要用户决定。
```

你看，第 5 条才是“skill 怎么升级”。

它可以存在，但要排在更具体的学习升级点后面。

### 6. 一张通用验收单

以后你可以用这张验收单检查任何 Codex 任务：

```text
Agent 说完成后，我看 6 件事：

1. 输出文件在哪里？
2. 它为什么这么做？
3. 它改了哪些地方？
4. 它用什么证据证明有效？
5. 有哪些风险或升级点？
6. 下一步由谁判断？
```

这张单子就是人的位置。

人不负责盯着 Agent 每一步走路。人负责看证据、风险、边界和下一步判断。

## 回锅测试

1. 用一句话回答：为什么 `agent 完成指令` 不能算完成标准？
因为这个问题 Agentic 流程设计得太大了，粒度太粗，没法一次性完成验收。

第一个叫 Agentic 的流程，具体步骤如下：

1. 比如 10.5：用户把答案写下去，Agent 读取该答案，并针对答案写一个“批注回应报告”。
2. 在 10.5“批注回应报告”中包含两个分支，其 If 条件为“是否补救”：
   (a) 如果需要补救：指向 10.6，进行 10.6 的审计，并写入学习记录（Learning Log）。
   (b) 如果不需要补救：直接进入第 11 步。
3. 进入 11（或 11 审计）后，审计学习记录，并同步更新学习记录和 Index。

我觉得这个流程设计得非常完整。
2. 请列出当前 `dbs-learning 下一篇` 任务的 4 类证据包材料。
回锅就是那四类证据包：
1. 回锅测试分数
2. 检测分数
3. 五槽是否完整（用户五槽是否完整）
4. 四槽是否完整

这个“五槽”和“四槽”，我看完之后才算有了非常清晰的认知：

• 五槽（触发状态、工具动作、反馈信号、停止条件、谁说）
• 四槽（谁、在什么时候、做什么、怎么样算完成）
3. 把“连续 2 次学不会”改写成一个可观察的停止条件。

两次学不会改成一个可观测信号，就是两次无槽的。

第一个可能反馈的信号，就是回国分数、测试分数都低于60 分
然后五槽和四槽都缺了很多，缺了两项及以上。
## 本篇检验题

### 题目口径补充

本页第一节里的“当前任务”指 Codex agent 的结算任务。Human agent 的学习执行任务也可以写成一条独立 Loop。两条 Loop 可以并列，但一份答案先标明主体，避免把两个人的状态和停止条件混在一起。

1. 任选 Codex agent 或 Human agent，把任务写成五槽：触发 / 状态 / 工具动作 / 反馈信号 / 停止条件。第一行标明主体。
2. 对同一个主体，把任务写成四槽：谁 / 什么时候 / 做什么 / 怎样算完成。
3. 写出 2 个需要人判断的升级点，必须具体到当前课程，不要写泛泛的“让人判断”。

### 用户复答（2026-07-10，聊天记录）

主体：Human agent。

1. 五槽尝试：我先精读 Codex agent 的回应，检查五个点有没有多或少；用 Mac 触控板点击；打开 `10.6.md`，在 VS Code 中用 Typeless 做口头费曼；全部内容费曼完后停止。
2. 四槽尝试：我看到 Codex 要我检查信息数量的消息后，点进学习位置，用 Typeless 完成费曼；所有内容都回答完后结束。
3. 升级点尝试：简单任务可以交给低模型迭代或代工。困难的就比如，我以后可能要开发交叉的地方。

然后  Codex 和 human Agent 拿不准（比如我把两个放在一起去学，Agent 拿不准），然后就去交给我作为一个 Human Agent 去判断，要去用最贵的模型还是便宜的模型。

## 小结

- Agent 声称完成，只是一个信号；证据包齐全，才接近可验收。
- 五槽让任务能运行，四槽让行动能落地，证据包让人能判断。
- 当前课程的证据包包括批注回应报告、learner-log、路径裁决、新篇或补救篇、审计文件、计划和索引。
- 最大尝试次数要写成可观察条件，例如连续 2 次缺关键槽位。
- 人工升级点要具体到当前任务，先写材料不足、答案身份不明、连续补救不过，再写是否升级成 skill。
