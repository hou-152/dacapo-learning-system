## 核心观点

这是一场针对 AI 实战营第一期的开营宣讲。营长用 21 天时间，定下一个明确目标：把"能跑的 [[demo-to-product|Demo]]"推到"能交付的产品"。

交付的裁判是用户——他们愿不愿意用、能不能用、能不能复用。营长见过太多黑客松里"能跑但没法交付"的 Demo，所以把"能交付"作为北极星。

最终目标不是"会部署小龙虾的人"，而是单拎出来就能独立交付、独立商业化的 [[opc|OPC（一人公司）]]。

## 实现路径：周循环 + 黑客松 + 作品集

营长设计了三重机制：

1. **[[21-day-cycle|21 天周循环]]**：每周一定方向，周二到周六打磨，周六录演示，周日 [[code-review|Code Review]]。机制的本质是"每周必须拿出一个可被他人查看的产物"。

2. **[[hackathon|黑客松]]**：21 天内必须参加 1-2 场黑客松。作用是倒逼优化、链接资源、演练交付，还是获客场景（游园会放二维码拉内测群）。

3. **[[portfolio|作品集]]**：三个可见的作品才是能力的证据。营长的逻辑是"能力大于学历"——商汤、SK 海力士都只看能力不看学历，而能力的凭据就是拿得出手的作品。

## 核心交付物：工程化 Agent 项目

第一期承诺的交付物是一个 [[engineered-agent|工程化 Agent 项目]]。载体不限（小龙虾、自建网站、自搭工作流），但必须达到工程化标准：可落地、可复用、能交付。

关键修饰是"工程化"，而不是一次性跑通的 demo。

## 价值主张：FDE

营长借 [[fde|FDE（前沿部署工程师）]] 这个词来指"AI 时代很基础的交付能力"——帮企业把 AI 落地、按需定制、非标定价。

他给这套主张配了三条论据：
- 大厂（AWS、OpenAI 等）已设岗
- 薪资是"非标"状态可以前期积累资金
- 整个行业还处在"摸着石头过河"的前期风口

在营长的体系里 FDE 只是台阶而非终点：越过它，目标是"超越 FDE 的能力"（FFDE）。

## 注意力与词效比

营长强调两个约束：

1. **[[attention-focus|注意力聚焦]]**：21 天只做一个事情，选定一个点打穿。想法多时要先集中调研、再确认先做哪个。

2. **[[token-efficiency|词效比]]**：人效比的 AI 版本——用 token 消耗来衡量 agent/skill 的性价比。同样的结果、更低的 token 成本，就是商业化时对企业的卖点。

## 养 Agent 的两条路线

营长介绍了养 agent 的两条路线，判据是目的：

1. **自进化型**：不设 [[three-config-files|SOUL/USER/AGENTS]] 文档、不设方向，靠长出来的机制去探索

2. **商业化定制型**：设定文档，把场景焊死——"销冠只能干销冠"，不能跑去搞金融

两条路线的区别体现在是否设定 [[three-config-files|三件套（SOUL.md / USER.md / AGENTS.md）]]。

## 防平庸与自进化

营长设计了四重防线防止生成式 AI"趋势概率分布"走向平庸：

1. **[[professional-sources|专业信息源]]**：喂给小龙虾的知识必须是各行业最顶尖的专业来源（论文、专业刊物），而不是网上随便的文章

2. **[[summary-reflection|总结与反思]]**：每日总结 + 每周总结 + 思考下周做什么。没有定期复盘，agent 只会重复昨天

3. **[[attention-protocol|注意力协议]]**：让小龙虾把自己的思考路径固化成一份协议，每次思考都走协议，中断时反思协议有没有走完

4. **[[judgment|判断力]]**：前期每个小龙虾连续聊一周，反复"我是这么看的，你怎么看"，大量交互之后它才会慢慢形成自己的判断

## 安全防御：Skill 审计

营长强调 [[skill-security|Skill 安全审计]]的必要性：

- 未审核的 skill 可能带毒、被注入
- 本地部署时服务器可能被当肉机
- 装前必须过安全审计，共享小龙虾时必须做 session 之间的隔离

## 元习惯：AI native

营长定义的行为标准：遇事第一反应是找 AI——有想法让它判断可不可行，没想法让它去调研平台热点给方向，想法太多就语音一股脑倒给它。

配套的趋势判断是"一句话完成一个任务"，所以接口越自然越好（用嘴讲 API，而不是自己钻代码库）。

这是整个营的"[[ai-native|元习惯]]"，也是成为 [[opc|OPC]] 的行为前提。
